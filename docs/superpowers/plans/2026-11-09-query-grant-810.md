# Query grant 구현 계획 (#810)

기준 브랜치는 #808의 `e0ba49cd`이며 DB migration V056을 사용한다. #809 progress 구현과 파일 경계를 분리한다.

## 계약

Spring이 256-bit opaque grant를 발급하고 SHA-256 hash만 저장한다. 저장되는 메타데이터는 runId, 승인 planHash, filterHash를 포함한 확정 filters, canonical fields, versions, maxPlaces, expiry이며 원문 질문과 semantic query는 보존하지 않는다. 만료는 현재 시각+30초와 실행 deadline 중 빠른 시각이다. Run 하나당 grant 하나를 발급한다.

Lookup은 AI adapter의 현행 `Authorization: Bearer <internal-ai.service-token>` 계약을 사용한다. SecretBundle의 current/previous constant-time 검증 후에만 grant 저장소에 접근한다. Grant 소비는 PostgreSQL row lock 하에서 active run, deadline, grant expiry, consumed 상태와 요청 scope를 검증하고 한 번만 완료한다. 같은 grant 재사용은 409이며 실패한 요청을 자동 retry하지 않는다.

오류는 401(service 인증/알 수 없는 grant), 403(filter/limit 범위 초과), 409(소비됨/inactive run), 410(expired grant)로 구분한다. 내부 SQL/secret/grant를 error body와 log에 기록하지 않는다. 응답은 `catalogVersion: journey.query.tools.v1`과 승인된 projection만 포함한다. PlaceQueryPort 결과에 placeIds/excludedIds를 추가 적용하고 canonical field allowlist에 따라 address/region/category/publicStatus를 제한한다.
