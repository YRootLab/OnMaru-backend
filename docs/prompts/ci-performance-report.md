# CI 성과 보고서 작성 프롬프트

CI·테스트·CD 실행 데이터를 비개발자, 개발자, 채용 담당자가 같은 문서에서 이해할 수 있도록 정리할 때 사용한다. 이 프롬프트는 관측값을 홍보 문구로 바꾸는 도구가 아니라, 무엇을 확인했고 무엇이 아직 미확정인지 분명히 하는 편집 계약이다.

## 사용 방법

아래 `입력 데이터`를 채운 뒤, `요청 프롬프트` 전체를 AI에게 제공한다. 수치가 없거나 비교 조건이 맞지 않으면 빈칸을 추측으로 채우지 말고 `측정 중` 또는 `비교 불가`로 남긴다.

### 입력 데이터

```text
대상 저장소 / 기간:
독자: 비개발자, 제품·운영 담당자, 개발자, 포트폴리오 독자
관측 실행 링크와 결과:
- CI:
- 테스트:
- CD:
직렬 기준선: 실행 횟수, 동일 SHA 여부, 중앙값, p95, 실패율
병렬 후보: 실행 횟수, 동일 조건 여부, 중앙값, p95, 실패율
가장 긴 단계와 시간:
실패·취소·환경 차이:
이번 변경:
아직 확인할 항목:
원시 데이터/아티팩트 링크:
```

## 요청 프롬프트

```text
당신은 소프트웨어 전달 속도를 사실에 근거해 설명하는 기술 작가이자 CI 관측성 엔지니어다.
아래 입력 데이터를 바탕으로 한국어 Markdown 보고서를 작성하라.

독자는 CI, CD, runner, critical path라는 용어를 모를 수 있다. 첫 문단에서는 이를 각각
"코드를 합치기 전 자동으로 확인하는 절차", "확인된 코드를 배포하는 절차",
"작업을 수행하는 임시 컴퓨터", "전체 완료를 가장 오래 붙잡는 단계"처럼 자연어로 풀어라.

반드시 다음 순서를 지켜라.

1. 제목: "[프로젝트] CI 성과: [무엇을 측정했고 무엇을 알았는가]" 형식의 구체적인 제목을 쓴다.
2. 5줄 이내의 "먼저 읽을 결론"에서 현재 대기 시간, 가장 큰 병목, 확정된 사실,
   아직 주장하면 안 되는 사실을 설명한다.
3. "개발자가 체감하는 흐름"에서 왜 이 시간이 중요한지 한두 문단으로 설명한다.
4. "숫자로 본 현재 상태"에서 CI, 테스트, CD를 표로 구분한다. 성공 실행이 없는 CD는
   배포 시간이 아니라 "성공 표본 없음"으로 표시한다.
5. "시간을 가장 많이 쓰는 곳"에서 상위 3개 단계와 전체 비중을 표로 설명하고,
   각 단계가 사용자 관점에서 무엇을 기다리게 하는지 풀어 쓴다.
6. Mermaid는 최대 하나만 사용한다. 노드는 7개 이하로 제한하고, 세부 테스트 이름을
   나열하지 않는다. 예: 변경 → 자동 확인 → 느린 핵심 검사 → 결과 → 배포/측정.
7. "병렬화는 어디까지 확인됐나"에서 성공한 사실과 실패한 후보를 분리한다.
   실패, 취소, 환경 불일치, 동일 SHA 반복 미달의 결과는 절대로 개선율로 표현하지 않는다.
8. "다음 측정에서 확정할 것"에서는 동일 조건 3회 이상, 중앙값, p95, 실패율 같은
   측정 계획을 비개발자도 이해할 수 있는 말로 쓴다.
9. "포트폴리오에 남길 수 있는 한 문장"은 검증된 사실만 사용해 2~3문장으로 제시한다.
10. 마지막에 실행 링크와 데이터 한계를 남긴다.

사실성 규칙:
- 서로 다른 commit SHA, runner 이미지, 캐시 상태, 명령, 도구 버전의 실행은 직접 비교하지 않는다.
- failed, cancelled, timeout, artifact 누락 실행은 improvement/regression 판정에서 제외한다.
- 중앙값이 없으면 "관측값"이라고 쓰고, 평균·개선율·절감 시간을 추정하지 않는다.
- CD 성공 표본이 없으면 실패까지 걸린 시간을 배포 성능으로 부르지 않는다.
- 숫자마다 단위(초, 분, %, 실행 횟수)를 붙이고 실행 링크를 가깝게 배치한다.

문체와 시각화 규칙:
- 전문 용어는 처음에 쉬운 말로 풀고, 이후에는 같은 표현을 일관되게 사용한다.
- 문단 중심으로 쓴다. 표는 비교를 돕는 곳에서만 사용한다.
- 과장된 "개선", "최적화 완료", "성공" 대신 증거 강도에 맞춰 "관측", "후보", "측정 중"을 쓴다.
- Mermaid 노드와 간선 라벨은 짧게 쓴다. 단계별 로그를 다이어그램으로 옮기지 않는다.

입력 데이터:
{{INPUT_DATA}}
```

## 출력 전 확인표

- [ ] 독자가 CI/CD를 몰라도 첫 두 문단을 이해할 수 있는가?
- [ ] 성공한 비교 표본과 실패·미확정 표본이 분리됐는가?
- [ ] 모든 시간과 비율에 근거 링크 또는 계산 근거가 있는가?
- [ ] Mermaid가 7개 이하 노드로 핵심 의사결정만 보여 주는가?
- [ ] 포트폴리오 문장이 미확정 개선율을 주장하지 않는가?
