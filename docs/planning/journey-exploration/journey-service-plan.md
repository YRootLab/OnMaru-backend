# 웹과 앱에서 이어가는 여정 탐색과 회원 경험

> **2026-09-11 개선 설계:** [감사 후속 계약](../revision-2026-09-11/README.md)이 최신 검토 기준이다. 모듈/DB·소유권·run 복구·방문 후기·검색·자원 정책은 해당 묶음을 우선한다. 구조 ADR은 초안 승인 대기이며 구현 완료를 뜻하지 않는다. 아래 장기 SSE/RAG 및 1.0 예시는 최신 MVP 계약과 구분한다.


작성일: 2026-09-10. 상태: 사용자 요청 반영 / 상세 정책 검토안.

2026-09-10 제출 범위 결정: 사용자는 약7일의 구현 기간을 고려해 오디보다 여정 탐색을 먼저 상세 구현하고, 카카오 로그인만 우선 적용하기로 했다. [7일 MVP FE 전달서](seven-day-mvp-fe-handoff.md)가 이번 제출 범위에서 이 장기안보다 우선한다. 오디 AI·공유·네이티브 앱·GPS·multi-agent 등은 제출 P0에서 제외한다.

사용자가 웹·앱에 친화적인 연속 탐색 방향에 동의하고 로그인·회원 기능의 기획 반영을 요청했다. 또한 여정 탐색을 오디에 한정하지 않고 OnMaru의 여러 데이터를 친화적으로 발견하고 이해하는 경험으로 구체화해 달라고 요청했다. 이 요구를 반영하되 아래 화면 구성, 비회원 범위, 공유 방식, 수치와 출시 순서는 제안이다. 인증 공급자·앱 기술·정식 ADR·구현 착수는 확정하지 않는다.

## 1. 제품 정의와 화면의 역할

**여정 탐색은 사용자의 관심과 질문을 장소·이야기·지역 정보에 연결하고, 이해하고 싶은 것과 가보고 싶은 곳을 선택해 웹과 앱에서 이어가는 탐색 공간이다.**

사용자가 얻는 결과는 관련 자료의 나열이 아니라 '왜 나에게 관련 있는지 이해한 후보', '현재 선택한 장소와 관심', '현장에서 살펴볼 것'이다. 자동 완성 일정은 기본 결과물이 아니다. 방문 없이 이야기를 이해하고 저장하는 것도 정상적인 사용이다.

페이지명은 사용자가 부른 `여정 탐색`, 기존 경로 `/discover`를 작업 기준으로 둔다. `이야기길`은 경험 이름 후보로 남기며 별도 중복 페이지를 만들지 않는 안을 제안한다.

| 화면 | 중심 과업 | 다른 화면과의 연결 |
|---|---|---|
| 여정 탐색 | 여러 원천에서 발견, 비교, 고정, 교체, 저장 | 모든 콘텐츠에서 공통 탐색으로 진입 |
| 오디 | 이야기 발견·재생, 대본 보기, 해당 이야기 질문 | 관련 후보 미리보기와 여정에 담기 |
| 한옥·장소 상세 | 해당 장소와 특징 이해 | 이 장소에서 탐색 시작 또는 기존 여정에 추가 |
| 지도 | 지리적 위치·주변 장소 확인 | 선택한 여정의 장소를 같은 식별자로 표시 |
| 내 여정 | 저장 목록, 다시 열기, 이름 변경·삭제·공유 관리 | 여정 탐색의 개인 저장 목록이며 별도 편집 엔진이 아님 |

오디에 전체 여정 편집기·지도·관계 그래프를 중복 배치하지 않는다. 이야기 중심으로 머무는 사람은 오디 안에서 충분히 듣고 질문할 수 있어야 한다. 장소 비교나 선택 변경이 필요할 때 공통 여정 탐색으로 이동한다.

오디의 제안 동작은 '이 이야기로 탐색'과 '내 여정에 담기'다. 진행 중인 여정이 있으면 이어 담을지 새로 시작할지 선택하며 기존 선택을 덮어쓰지 않는다. 전달 맥락은 선택 이야기, 명시적 관심·관련 질문, 대상 여정으로 제한한다. 전체 대화를 자동 복제하지 않는다. 동일 앱 셸 안에서는 플레이어와 재생 위치를 유지하고, 기기 이동은 자동 재생 대신 이어 듣기 선택을 제공한다.

## 2. 첫 화면부터 현장까지의 구체적 흐름

### 발견: 질문을 잘 쓰지 못해도 시작한다

첫 화면은 실제 자료로 만든 관심 주제와 장소·이야기를 바로 탐색할 수 있는 화면이다. '한옥에서 살던 방식', '건축의 차이' 등은 해당 지역에 검수된 자료가 있을 때만 제공한다. 자연어 입력과 지역 선택을 함께 제공한다. 미로그인 첫 방문에도 결과를 볼 수 있다.

기본 진입은 세 가지다: 관심 주제 선택, 자유 질문 입력, 오디·한옥·게시물에서 선택한 자원으로 시작. 회원은 저장한 여정을 다시 여는 경로도 가진다. 이동 후보를 구하려는데 지역이 없으면 지역을 묻고, 개념·이야기 질문에는 지역 선택을 강요하지 않는다.

### 이해: 작은 탐색 결과를 만든다

예시 요청: '서울에서 한옥에 살던 사람들의 생활을 알고 싶어. 나중에 직접 가보고 싶어.' 실제 장소 추천 결과를 검증한 예시는 아니다.

초기 보드는 장소 후보 최대 5개를 제안한다. 각 후보에 짧은 연결 이유와 자료가 있는 관련 이야기·관찰 포인트를 붙인다. 지역 자료는 장소 사실처럼 섞지 않고 별도 맥락으로 표시한다. 자료가 부족하면 후보 수를 줄인다.

위 후보 보드는 방문 후보 탐색의 결과다. '대청마루는 무엇인가' 같은 이해 질문은 근거 있는 답변만 반환할 수 있으며 지역·장소 카드·지도 생성을 강제하지 않는다. 결과를 답변, 후보 변경 제안, 추가 질문, 자료 부족으로 구분한다. 답변만 받은 상태에서도 명시적으로 관심이나 공개 이야기를 저장할 수 있어야 한다.

카드에서 즉시 판단할 정보는 다음과 같다.

- 어떤 장소·이야기인가: 실제 이미지 또는 명시적 미디어 없음 상태, 이름, 종류, 지역.
- 왜 내 관심과 연결되는가: 근거를 갖춘 짧은 이유.
- 무엇을 더 이해하거나 볼 수 있는가: 질문, 비교 대상 또는 검수된 관찰 포인트.
- 판단에 필요한 제한은 무엇인가: 좌표·운영 정보 부족, 자료 기준일 등 해당 정보에 맞는 표시.

선택한 자원의 상세에는 질문, 관련 이야기 재생, 근거 확인, 여정에 담기를 제공한다. 모든 문장에 긴 출처를 반복하기보다 주장별 근거에 접근할 수 있게 하고, 중요한 미확인 상태는 접힌 서랍 안에 숨기지 않는다.

### 연결: 선택한 주변만 펼친다

지도는 '어디에 있는가', 관계 보기는 '왜 연결되는가', 기록은 '내가 어떻게 선택했는가'에 답한다. 세 의미를 한 선으로 표현하지 않는다.

관계 보기에서는 선택한 자원 주변의 기본 1-hop 관계부터 펼친다. 초기 최대 노드 12개·연결 16개는 기존 제안값을 유지하며 사용성 확인 후 조정한다. 최초 화면에서 전체 그래프를 펼치지 않지만 사용자가 연결 관계를 직접 탐색할 수 있는 기능은 MVP에 포함하는 안이다.

관계에는 '이야기의 배경', '같은 주제', '주변 장소', '편집자가 함께 고른 자료'처럼 이해 가능한 이름을 붙인다. 의미 유사성만으로 역사적 사실 관계를 만들지 않는다. 관계를 선택하면 연결 근거와 대상을 보여주고, 같은 연결을 목록으로도 탐색할 수 있게 한다. 그래프 좌표를 지도 좌표로 사용하지 않는다.

첫 계약에서 주제는 검수된 태그·관계 라벨로 표현한다. 현재 ResourceRef에 없는 TOPIC이나 후기 노드를 임의로 추가하지 않는다. 선택 가능한 독립 주제 노드가 필요해지면 식별자·근거·상세 조회 계약을 먼저 확장한다. 공공 지역 관측은 REGION 맥락, 공개 후기는 장소 상세의 구분된 정보로 시작한다.

### 선택: 바꿔도 내가 고른 것은 남는다

장소 고정, 제외, 추가, 대안 요청, 변경안 적용·취소, 되돌리기를 제공한다. AI가 만든 제안만으로 현재 보드가 바뀌지 않는다. '이곳은 유지하고 다른 생활 이야기를 찾아줘'는 고정 장소를 유지하며 후보 교체를 제안한다.

내 여정에는 선택 장소뿐 아니라 선택한 관심과 이어 볼 이야기를 저장한다. 기본적으로 방문 순서·이동 시간·완주를 보장하지 않는다. 경로 공급자로 검증되지 않은 연결선을 도보 경로라고 표시하지 않는다.

'적용'은 현재 탐색 보드의 선택을 확정하고, '내 여정에 저장'은 그 탐색을 회원의 장기 저장 대상으로 만드는 동작이다. 비회원도 임시 보드에 적용할 수 있다. 회원이 한 번 저장한 여정에서는 이후 명시적으로 적용한 변경을 자동 저장하고 저장 중·완료·실패를 표시한다. 미적용 AI 제안, hover, 열린 패널은 확정 선택으로 저장하지 않는다. 서버 저장 실패를 성공으로 표시하지 않으며 읽기 전용 공유본은 자동 갱신하지 않는다.

### 이어가기: 현장에서는 현재 장소에 집중한다

모바일 웹과 앱에서 같은 여정을 열고 장소를 직접 선택한다. '도착했어요'는 사용자 자기 기록이며 검증된 방문 인증이 아니다. 이전 관심과 질문을 이어 관찰 포인트, 오디오, 추가 질문을 제공한다. 질문에 답을 얻고 종료하는 것도 성공이며 매번 다음 장소로 이동시킬 필요는 없다.

## 3. 여러 데이터의 역할과 AI의 경계

| 원천 | 여정 탐색에서 쓰는 용도 | 보장하지 않는 것 |
|---|---|---|
| 한옥·관광 장소 | 방문 후보, 위치, 장소 특징·방문 정보 | 확인하지 않은 운영시간·접근성 |
| 오디 대본·음원 | 근거 있는 설명, 듣기, 주제 연결 | 대본 속 극화 대사가 실제 역사 기록이라는 주장 |
| 검수 게시물·큐레이션 | 지역을 보는 관점, 편집된 연결과 관찰 포인트 | 편집 추천을 사용자 인기 순위로 표시 |
| 공개 온기 후기 | 여행자가 남긴 경험과 작성 시점 | 개별 후기를 객관적 역사·실시간 상태로 확정 |
| 공공 지역 방문 집계 | 기간과 지역 단위의 방문 흐름 | 현재 특정 장소의 혼잡도 |

여러 데이터를 활용한다는 것은 모든 응답에 모든 원천을 넣는다는 뜻이 아니다. 질문에 필요한 자료만 검색하고, 해당 자료가 무엇을 설명할 수 있는지 구분한다. 후기 노출은 공개·검수 상태를 따르며 후기 원문 AI 색인은 자동으로 범위에 포함하지 않는다.

AI는 현재 관심을 구조화하고, 공개 자료를 검색하고, 근거에 맞춘 설명·비교·다음 탐색을 제안한다. 단순 필터와 이미 검수된 연결은 LLM 없이도 처리할 수 있다. 저장·고정·적용·권한 판단은 서버의 명시적 동작이다. 사용자가 요청하지 않은 이동·게시·예약을 수행하지 않는다.

FE는 정해진 장소·이야기·지역 정보·근거·질문 블록을 렌더링한다. AI는 임의 HTML이나 화면 코드를 만들지 않는다. 진행 상태를 보여주되 모델 내부 추론을 탐색 기록으로 노출하지 않는다.

## 4. 웹·앱에 친화적인 표현

| 환경 | 제안 구성 |
|---|---|
| 데스크톱 웹 | 후보 목록과 선택 상세를 함께 비교, 지도·관계 보기 전환, 저장 여정 접근 |
| 모바일 웹 | 동일 기능을 한 번에 한 중심 뷰로 제공, 목록·지도·관계 전환, 상세 시트, 공유 링크 직접 진입 |
| 앱 | 모바일 핵심 경험과 같은 데이터·선택 상태, 현장 듣기·이어보기 중심 |

기기 폭에 따라 핵심 기능을 없애지 않는다. 동일 브라우저 재접속 복구와 로그인 후 기기 간 동기화는 별도 동작이다. 앱 설치 없이 공개 콘텐츠와 공유 여정을 모바일 웹에서 열 수 있어야 한다. 네이티브 앱 여부, PWA 채택, 오프라인 패키지는 기술·운영 검토 후 결정한다.

감성적인 인상은 실제 장소 사진, 짧은 이야기, 명확한 편집 관점, 선택 대상이 이어지는 움직임으로 만든다. 사진·음원은 사용 권한과 대상 일치를 확인한다. 글자 가독성, 키보드 조작, 터치 선택, 모션 감소를 함께 지원한다. 그래프를 움직이느라 질문과 결과가 가려지거나 탐색 위치가 매번 초기화되지 않게 한다.

## 5. 로그인과 회원 기능

회원 기능은 사용자가 이번에 요청한 범위다. 아래 구체 정책은 검토안이며 기존 인증 공급자 미정 상태는 유지한다.

| 구분 | MVP 제안 |
|---|---|
| 비회원 | 공개 콘텐츠·공유본 열람, 제한된 AI 질문과 임시 탐색; 임시 보존·사용량 안내 |
| 로그인 유도 시점 | 장기 저장·기기 간 이어보기·개인 여정 공유 시점; 탐색 첫 화면 진입은 허용 |
| 가입·로그인 | 이번 MVP는 카카오 로그인1종; 첫 인증 후 필요한 약관 확인과 최소 프로필 생성 |
| 프로필 | 닉네임 조회·수정; 관심 주제는 선택 사항이며 자동 장기 취향 추론은 제외 |
| 내 여정 | 저장·목록·다시 열기·이름 변경·삭제, 장소·이야기 북마크 |
| 이어보기 | 선택·고정·명시적 관심·이어 들을 위치 동기화; 재생은 사용자가 시작 |
| 계정 관리 | 로그아웃, 전체 세션 로그아웃, 계정 탈퇴와 연관 데이터 삭제 진행 상태 |
| 공유 관리 | 회원 소유 여정의 읽기 전용 공유본 생성·철회 |

로그인 취소·실패로 임시 보드가 사라지지 않아야 한다. 비회원 보드를 계정에 저장할 때는 사용자의 저장 동작에 따라 서버가 검증한 익명 세션을 이관하고 중복 요청을 처리한다. 클라이언트가 보낸 소유자 ID나 임의 세션 ID를 소유권 증명으로 삼지 않는다. 기존 회원 여정을 자동으로 덮어쓰지 않는다.

MVP 이관안은 active run이 끝나거나 취소된 뒤 현재 committed board와 사용자가 선택한 관심·공개 자원만 새 회원 여정으로 복사하는 것이다. 기존 회원 여정 병합, pending proposal, 이벤트 replay, checkpoint 이관은 제외한다. 중복 저장은 같은 결과를 반환하고, 복사가 성공한 뒤 익명 원본의 접근·실행을 폐기한다. 다른 탭이 접근 중이어도 이전 익명 권한으로 회원 여정을 읽을 수 없어야 한다. 만료된 익명 원본은 복구 성공으로 위장하지 않는다.

웹과 앱에서 동일 인증 주체가 같은 내부 회원으로 연결되어야 한다. 다른 공급자 계정을 이메일 문자열만으로 자동 병합하지 않는다. 다중 공급자 연결, 비밀번호 자체 관리, 소셜 팔로우·공동 편집은 초기 범위에서 제외하는 안이다. 공급자 선정·복구 경로와 웹·앱 인증 계약은 구현 전 확정한다.

공유는 원본 편집 권한을 주는 링크가 아니다. 공개 자원과 사용자가 공유 대상으로 확인한 제목·선택만 담는 읽기 전용 스냅샷을 제안한다. 비공개 질문·대화·개인 위치·탐색 기록은 기본 제외한다. 공유본에서도 삭제·비공개 전환된 원천은 다시 검증해 숨긴다. 링크 철회와 계정 탈퇴 후 기존 링크 접근도 차단한다. 공개 검색엔진 노출은 기본 비활성으로 두는 안이다.

2026-09-10 구현 순서는 카카오 로그인 기반 `내 여정 저장·다시 열기`를 P0로 확정하고, 시간이 남으면 로그인 없는 PDF 인쇄·파일 저장, 그 다음 로그인 회원의 읽기 전용 공유 링크 순으로 진행한다. PDF는 브라우저 인쇄 layout을 우선하고 공유 링크는 별도 snapshot과 철회를 제공한다. PDF와 공유가 카카오 저장의 완료를 늦추면 제출 이후로 넘긴다.

다중 기기에서 오래된 버전을 저장하면 조용히 덮어쓰지 않고 최신 상태와 충돌을 안내한다. 로그아웃 시 기기의 개인 캐시와 접근을 정리한다. 탈퇴 시 접근·세션·공유 링크를 차단하고 여정·북마크·AI 연관 자료의 삭제를 추적한다. 후기·감사 메타데이터 등 별도 보존 대상과 보존 기간은 공개 전 정책으로 확정한다.

로그아웃은 해당 인증 세션과 그 연결의 접근을 끊되 다른 기기의 회원 여정을 삭제하지 않는다. 전체 로그아웃은 모든 인증 세션을 해제한다. 탈퇴는 실행 중 AI 작업 취소와 늦게 도착한 결과의 재저장 방지도 포함한다. 보드·프로필·북마크·오디오 재생 위치는 각 상태의 버전으로 충돌을 처리하여 재생 위치 갱신 때문에 장소 변경이 실패하지 않게 한다. 재생 위치를 가장 큰 초 값으로 병합하지 않는다. 다시 듣기로 되감은 위치도 유효한 사용자 선택이다.

## 6. 트래킹의 의미를 구분한다

사용자가 언급한 '트래킹'의 범위는 아직 불명확하다. 아래 첫 번째를 MVP 제안으로 해석하며 실제 이동 기록까지 승인된 것으로 보지 않는다.

| 종류 | 범위와 상태 |
|---|---|
| 탐색·선택 기록 | 명시적으로 선택한 관심, 저장·고정·제외·적용한 변화와 이유를 이어보기 위해 보존하는 MVP 제안 |
| 방문·감상 기록 | 사용자가 직접 남기는 봤음·들었음 기록의 최소 형태를 검토; 실제 방문 인증 아님 |
| GPS 이동 궤적 | 경로 수집·백그라운드 위치·거리 측정은 별도 요구 확인 전 제외 |
| 제품 분석 이벤트 | 노출·선택·저장 등의 효과 측정; 개인 탐색 기록 및 위치 추적과 별도 정책 |

질문 전체나 모든 클릭을 무기한 축적하지 않는다. 서버 저장 범위·보존 기간·지우기 동작은 회원 계약에서 명시해야 한다. 사용자 기록은 모델의 숨겨진 추론이나 관광 사실 관계 그래프와 섞지 않는다.

## 7. MVP 요구와 확인할 결과

아래 `JE` 항목은 이번 추가 기획의 로컬 요구 식별자이며 GitHub Issue가 아니다. 기존 JX 요구를 대체하지 않고 확장한다.

| ID | 요구 | 기존 연결 | 확인할 완료 조건 |
|---|---|---|---|
| JE-01 | 관심·질문·선택 자원에서 여정 시작 | JX-04,05 | 오디 재생 없이도 시작 가능, 필요한 경우만 지역 질문, 관련 없는 원천을 채워 넣지 않음 |
| JE-02 | 오디와 공통 여정 연결 | BE-REQ-008,009 / JX-06,07 | 선택 이야기·명시적 맥락 전달, 기존 고정 선택 보존, 같은 셸 재생 위치 유지 |
| JE-03 | 작은 관계 보기와 동등한 목록 | JX-05,06,11 | 모든 사실 연결에 근거, 선택 동기화, 키보드·모바일에서도 관계 탐색 가능 |
| JE-04 | 회원과 내 여정 | JX-07,08 확장 | 로그인 성공·취소·실패, 익명 저장 재시도, 다른 계정 접근 차단, 탈퇴 후 접근 차단 확인 |
| JE-05 | 기기 간 이어보기 | JX-07,08 확장 | 같은 회원의 최신 선택 복구, 오래된 변경 충돌 안내, 로그아웃 후 개인 상태 미노출 |
| JE-06 | 읽기 전용 공유 | 신규 | 비공개 맥락 제외, 비회원 모바일 열람, 원본 수정 불가, 철회·원천 비공개·탈퇴 반영 |
| JE-07 | 현장 관찰과 탐색 기록 | JX-05,11 확장 | 위치 권한 없이 수동 장소 선택, 관심에 맞는 검수 관찰 포인트, 자기 기록과 실제 방문 구분 |

첫 검증은 한 지역의 검수 가능한 장소·오디·편집 자료를 연결해 실시한다. 제공 범위가 확인된 후기와 공공 지역 자료만 추가한다. 모든 원천의 존재를 첫 시연의 필수 조건으로 만들지 않는다.

비교 기준은 같은 자료의 정적 안내다. 웹에서는 이해에 기반한 후보 선택과 저장, 모바일에서는 저장 맥락 복구와 관찰 대상 찾기·설명 가능 여부를 본다. 관계 보기 사용 여부와 이해 개선을 따로 관찰한다. 효과가 없으면 관계 보기의 기본 노출을 줄이거나 목록 중심으로 조정한다. 합격선·표본·비용 예산은 평가 착수 전에 합의한다.

## 8. 구현 기획에 반영해야 할 변경

기존 FE 추적표의 `ODII-F001~004`, `HANOK-F001~004`, `MAP-F001~004`와 연결하며 FE 원본 파일은 이 문서에서 수정하지 않는다. `/discover` 프로토타입은 [기존 FE 감사](fe-data-audit.md)의 코드 근거를 사용하고, 새 JE 요구는 계약 확정 시 FE/BE 추적표에 반영해야 한다.

기존 `fe-api-handoff.md`는 회원·공유·익명 이관을 완전히 명세하지 않았다. 인증 상태, 회원 저장 수명, 공유 권한, 기기 충돌, 탈퇴 삭제 범위를 OpenAPI·SSE 계약과 fixture에 추가해야 한다. 익명 세션의 기존 24시간 보존 초안을 회원 여정에 그대로 적용하지 않는다.

기존 W0 인증·계약 작업과 W5 작성 주체, X0 fixture, X2 세션, X5 통합, X6 FE, X8 평가에 영향을 준다. 특히 회원 기반 탐색은 온기 작성 작업 하나에 숨기지 않고 독립 인수 조건을 가져야 한다. W/X/JE 중복을 통합한 뒤 GitHub Issues로 관리한다. 이 문서는 테이블이나 DDL을 확정하지 않으며 후속 영속 모델 변경 시 `docs/database/schema.md`를 함께 갱신한다.

남은 결정은 파일럿 지역·대표 과업, 인증 공급자와 회원 복구, AI 사용량·예산, 기록·공유 보존 기간, 앱 구현 방식, 트래킹의 실제 요구다. 우선 화면 책임과 한 가지 연결 흐름을 검토한 뒤 계약·데이터·이슈를 구체화한다.

## 9. 2026-09-10 정합성 검토와 검증 시나리오

기존 PRD·FE 계약·이슈 영향 문서를 대조한 문서 검토다. 아래는 보완한 제안이며 런타임 검증 결과가 아니다.

| 발견한 빈틈 | 보완 방향 | 구현 전 fixture |
|---|---|---|
| 설명 질문에도 지역·후보가 강제될 수 있음 | ANSWER 결과와 보드 변경 제안 분리 | 지역 없이 개념 질문 → 답변·근거, 보드 버전 유지 |
| 적용과 장기 저장이 혼동됨 | 임시 보드 확정과 회원 저장 분리 | 비회원 적용 → 로그인 취소 → 임시 선택 유지 |
| 익명에서 회원으로 바뀔 때 실행·소유권 경합 | 실행 종료 후 확정 선택 복사, 이전 접근 폐기 | 중복 저장·다른 탭 변경·만료·늦은 AI 결과 |
| 주제·후기 노드가 기존 자원 계약에 없음 | 태그·관계 라벨·장소 상세로 시작 | 미지원 type 거절, 목록과 그래프의 참조 일치 |
| 기존 내 여정에 담기의 명령이 없음 | 기존 여정 대상에는 명시적 추가 명령 | 중복 추가·고정 보존·오래된 버전·active run 충돌 |
| 공유본과 원본 수정의 관계가 불명확 | 읽기 전용 고정판, 재공유는 새 판 | 원본 편집 후 공유본 유지, 비공개 전환은 즉시 제외 |
| 재생 위치 갱신이 여정 편집과 충돌할 수 있음 | 재생 상태 버전 분리 | 두 기기 재생·되감기·여정 편집 동시 수행 |

첫 프로토타입의 대표 과업은 다음 세 가지로 제안한다.

1. 웹에서 관심 주제로 시작해 두 후보의 차이를 이해하고 하나를 저장한다.
2. 오디에서 질문한 뒤 기존 여정에 이야기를 추가한다. 고정 장소와 재생 위치는 유지한다.
3. 모바일에서 같은 계정으로 저장 여정을 열고 관찰 포인트를 확인한다. 공유받은 비회원은 개인 질문 없이 공개 선택만 본다.

우선 확인할 사용자 결정은 파일럿 지역·관심 주제와 트래킹의 의미다. 인증 공급자·앱 기술은 비교할 요구가 정리된 뒤 선택하며, 이 단계에서 임의 제품명을 확정하지 않는다. AI 한도·보존 기간은 계약 공개 전에 수치로 결정해야 한다.
