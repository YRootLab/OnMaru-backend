# 이야기길 PRD: 듣던 이야기에서 다음 장소로

문서 상태: 검토용. 기존 [백엔드 PRD](../backend-prd.md)에 대한 확장이다. 기존 온기·장소·오디 API 이관을 대체하지 않는다.

## 1. 제품 결정

**이야기길은 자연어와 오디 이야기로 방문 후보를 발견하고, 지도·카드·근거를 함께 보면서 선택한 장소를 보존해 여정을 좁혀 가는 탐색 화면이다.** 자동으로 완성된 여행을 강요하거나 끝없이 채팅하는 화면이 아니다.

첫 고객 가설은 “국내 문화·한옥 여행에 관심이 있고, 한 지역에서 짧은 자유시간 동안 어디부터 가야 할지 고민하는 여행자”다. 외국어 확장·전국 장거리 일정·예약은 후속이다. 이 가설은 실제 고객 조사 결과가 아니다.

새 이름은 **이야기길**, 보조 문구는 **듣던 이야기, 가보고 싶은 길로.** 기존 `여정 탐색`은 기능을 설명하는 대안 이름으로 남긴다. 상표 확인이나 선호도 검증은 하지 않았다.

## 2. 해결할 문제와 성공 가설

| 가설 | 기능이 검증하는 것 | 관찰할 지표 | 반증/축소 조건 |
|---|---|---|---|
| H1 이야기 맥락이 방문 후보 발견을 돕는다 | 오디→근거 있는 장소 연결 | 동일 자료의 검색 대비 관련 후보 선택 성공률, 선택 이유 설명 가능 여부 | 카드 장식만 늘고 과업 성공률이 개선되지 않음 |
| H2 이전 선택 보존이 재탐색 부담을 줄인다 | 고정/부분 교체/되돌리기 | 수정 과업 시간, 잃어버린 선택 수, 수동 복구 횟수 | 선택 보존 불변식 실패 또는 UI 이해가 더 어려움 |
| H3 출처가 판단을 돕는다 | 연결 근거·관측일·미확인 표시 | 사실/추정 구분 정답률, 근거 패널 활용, 신뢰 인터뷰 | 출처를 읽어도 실시간·공식 점수로 오인 |
| H4 주간 편집판은 AI 없이도 재방문 이유가 된다 | 주간 다섯 장과 저장 | 노출 대비 유효 선택, 판별 재방문, 편집 소요 시간 | 매주 유지 비용에 비해 이용 근거 없음 |

첫 5명은 문제를 찾는 형성 평가용이지 시장성 입증 표본이 아니다. 이후 검색/일반 채팅/이야기길의 동일 과업을 순서 균형화해 비교한다. 효과 크기와 변동을 본 뒤 추가 표본 수를 정한다. 개인정보 동의와 측정 목적을 알리고 실제 방문 추적은 별도 동의 없이는 하지 않는다.

## 3. 핵심 사용자 흐름

### A. 자연어에서 선택 보드로

1. `/discover`에서 “이 지역에서 한옥 이야기를 들으며 한 시간 정도 걷고 싶어”를 입력한다. 지역이 없으면 먼저 지역을 질문한다. 위치 권한 거부 시 수동 지역 선택을 제공한다.
2. 서버는 지역·시간·관심 주제·기준 장소를 구조화한다. 실시간 한산함·실내·무장애 등 확인하지 못한 속성은 추정 충족으로 표시하지 않는다.
3. FE는 “자료 찾는 중”, “연결 확인 중” 같은 진행 상태를 보여준다. 모델 내부 추론은 표시하지 않는다.
4. 검증된 후보 최대5개를 가로 레일과 지도에 동시에 올린다. 첫 응답에 그래프 전체를 펼치지 않는다.
5. 카드 선택 시 해당 카드 아래 또는 모바일 상세 시트에 방문 정보·관련 오디·연결 이유를 연다. 지도는 해당 후보를 강조한다.
6. 사용자가 장소를 고정하고 “시장 대신 다른 이야기를 듣고 싶어”를 입력한다. 기존 보드를 유지하면서 변경 제안을 옆에 보여준다.
7. “적용”하면 새 버전이 되고 “취소”하면 원래 상태 그대로다. 길찾기는 검증된 지도 연결로 전달한다. 경로 공급자가 없으면 소요 시간 대신 후보 위치만 보여준다.

### B. 오디에서 출발하기

1. 오디의 ‘지도로 듣는 이야기’에서 지역·이야기를 선택한다.
2. 새 버튼 **이 이야기에서 이어 걷기**가 story canonical ID와 선택 지역을 이야기길 세션 생성에 전달한다. 재생은 기존 플레이어에서 유지한다.
3. 대본의 검증된 주제·대상과 연결된 장소만 후보에 넣는다. 관련 지역만 확인되면 “이야기와 관련된 지역”으로 표시하고 실제 이야기의 배경 장소처럼 단정하지 않는다.
4. “이야기의 배경”, “같은 건축 주제”, “주변 후보”를 서로 다른 관계로 보여준다. LLM 의미 유사성만으로 ‘이곳에서 있었던 일’을 만들지 않는다.

### C. 주간 다섯 장에서 출발하기

1. 이번 주 편집판의 한옥·오디·게시물 카드를 연다.
2. “왜 골랐나요”에서 선정 이유·대상 기간·공급자 근거를 확인한다.
3. “여기서 이어 찾기”로 해당 장소/이야기를 고정한 보드를 만든다.
4. 자체 행동 데이터가 충분해지면 별도 탭에 주간 인기 TOP5를 공개한다. 편집판을 인기 순위로 조용히 바꾸지 않는다.

## 4. 기능 요구와 인수 기준

| ID | 우선순위 | 요구사항 | 검증 가능한 완료 조건 |
|---|---|---|---|
| JX-01 | P0 | 공공/UGC/데모 원천 분리 | 모든 온기·인기 응답에 origin/status/asOf가 있고 결측을 숫자0이나 오늘 값으로 위장하지 않음 |
| JX-02 | P0 | 추천 한옥·추천 오디 서버 제공 | placement 별 명시적 방식과 canonical refs, 비공개/삭제 리소스 미노출 |
| JX-03 | P0 | 주간 편집판·게시형 콘텐츠 | 검수된 revision만 게시, 정확히 연결된 자원만 노출, 후보5개 미만이면 부족 상태를 정직하게 표시 |
| JX-04 | P1 | 자연어 조건 검색 | 지역 누락·자료 부족·미확인 조건이 명시적 상태로 반환되고 hard constraint 위반 후보는 제외 |
| JX-05 | P1 | 이야기-장소 관계 탐색 | 모든 사실 관계에 유효 evidence ref, 좌표 없는 자료는 지도 핀 생성 금지 |
| JX-06 | P1 | 가로 대안·세로 상세 | 지도/카드/관계 선택이 동일 canonical ref를 가리키고 플레이어가 불필요하게 초기화되지 않음 |
| JX-07 | P1 | 고정·부분 교체·적용·되돌리기 | 고정된 ref 보존, 오래된 proposal 적용409, 취소한 preview가 committed state를 변경하지 않음 |
| JX-08 | P1 | SSE·재접속·취소 | 중복/역전/누락/만료 cursor/오래된 run 테스트에서 snapshot과 일치, terminal 상태가 충돌하지 않음 |
| JX-09 | P1 | AI 실패 시 유용한 대안 | 기존 선택 유지, 필터 검색·편집판 제공, 실패를 생성 성공으로 위장하지 않음 |
| JX-10 | P2 | 실제 주간 인기 TOP5 | KST 집계 기간·qualified event·중복 방지·표본 기준·rankingVersion이 고정된 판으로 재현됨 |
| JX-11 | P1 | 근거·접근성·안전 | 출처 추적 가능, 키보드로 모든 선택/해제 가능, 감소된 모션, 프롬프트 인젝션으로 도구·권한 확대 불가 |
| JX-12 | P2 | 두 시대의 한 장 | 검수된 과거 서술과 현재 운영 정보를 분리, 실제 개선 확인 후 제한 출시 |

P0/P1은 제품 우선순위이지 반드시 병렬 실행하라는 뜻이 아니다. 공모전 최소 시연 범위는 P0 데이터 정직성 + 한 지역 P1 흐름1개다. 자체 주간 인기 집계가 준비되지 않으면 편집판으로 시연하고 그 사실을 설명한다.

## 5. UI 원칙

- **선택이 대화보다 앞선다.** 질문 기록은 보조 패널이고 장소·이야기·현재 고정 조건이 화면 중심이다.
- **가로는 대안, 세로는 깊이.** 같은 목적의 대안을 좌우로 비교하고 하나의 상세만 펼친다. 드래그만이 유일한 조작 방식이 되지 않게 한다.
- **지도는 위치, 관계 뷰는 이유.** 관계선이 도보 경로처럼 보이지 않게 선 형태·범례·모드를 구분한다.
- **재탐색은 덮어쓰기가 아니라 제안이다.** 추가/제거/유지와 이유를 표시한 뒤 적용한다.
- **알 수 없음은 정상 상태다.** 운영시간·혼잡·접근성·오디오 없는 후보를 억지로 채우지 않는다.
- **AI는 UI 코드를 생성하지 않는다.** 허용된 컴포넌트 종류와 검증된 데이터 참조만 선택한다.

## 6. MVP와 제외 범위

KEEP: 관계 근거, canonical refs, 서버 발행 편집판, 선택 상태 버전, 장애 fallback, 재현 가능한 평가.

SIMPLIFY: 지식 그래프는 기본1-hop, 상세에서만 확장. LangGraph는 고정 단계와 제한된 repair. 추천은 SQL 기준선부터 시작.

DEFER: Neo4j, 전국 자동 역사 그래프, 협업 여정, 개인 행동 장기 프로필, 학습 기반 추천, 예약·결제, 음성 대화, 자동 날씨별 우회, 장거리 최적 경로.

REMOVE: LLM 임의 React/HTML, 관광 집계로 장소 실시간 혼잡 추정, 실측 없는 주간 인기 라벨, 후보 수를 맞추는 허구 자료.

## 7. 출시·철회 게이트

데이터 게이트: 파일럿 지역에 실제 장소·오디·근거·좌표 연결이 있는지 전수 점검한다. 검증 부족이면 지역을 바꾸거나 장소 연결 대신 지역 수준 안내로 축소한다. 전국 서비스의 일부만 시연한다고 지역특화 가산점을 가정하지 않는다.

품질 게이트: 초기 평가 세트 100문항 제안(일반30, 조건20, 관계15, 부족10, 인젝션10, 원본 변경10, 다국어5). 위험 질문은 별도 통과 기준을 둔다. 작은 평가 세트에서 사실 오류0이 관찰되어도 운영 무오류를 보장하지 않는다.

UX 게이트: 고정 선택 손실0, 미확인 정보의 사실 오인0을 목표로 형성 평가한다. 비교 과업에서 이점이 없으면 그래프를 기본 화면에서 제거하고 카드/근거 중심으로 유지한다.

성능 게이트 초안: cached 검색 첫 유효 카드 p95 2초, AI 첫 검증 후보 p95 8초, run 절대 제한30초. 대상 장비·모델·부하를 함께 기록하며 미달 시 모델 축소 또는 비동기 진행 안내를 조정한다. 측정 전 홍보 수치로 쓰지 않는다.

운영 게이트: 동일 데이터·모델·prompt·contract revision으로 평가 재실행 가능, 원본 삭제 반영·비용 상한·장애 fallback·세션 삭제 흐름이 확인되어야 공개한다.
