# 이야기길과 오디 AI 도슨트의 핵심 경험 검토

작성일: 2026-09-09. 상태: 논의 기록 / 미확정 제품 가설.

사용자가 공유한 Cline의 제안과 이에 대한 비판적 검토를 보존한다. 이 문서의 저장은 제품 방향 확정이나 구현 승인을 의미하지 않는다. 기존 [이야기길 PRD](product-prd.md)와 [추천·AI 설계](architecture-and-recommendation.md)를 대체하지 않는다.

후속 논의: 사용자는 웹에서 고른 관심을 현장 웹·앱에서 이어가는 방향에 동의하고 로그인·회원 기능 추가를 요청했다. [웹·앱 여정 탐색과 회원 경험 상세안](journey-service-plan.md)에 오디와 여정 탐색의 역할, 여러 원천 활용, 관계 보기, 회원·공유·이어보기, MVP 조건을 정리했다. 아래 현장 우선안은 최초 검토 기록이며 후속안은 방문 전과 현장을 함께 다룬다. 상세 정책은 아직 제안이다.

## 출발점: 이야기에서 다음 장소로 이어 걷기

Cline이 제안한 중심 경험은 오디 이야기를 듣다가 '이어 걷기'를 누르면 근거 있는 장소 후보가 나타나고, 마음에 든 장소를 고정한 채 나머지만 교체하는 흐름이다.

이야기에서 장소로 연결하는 경험과 선택 보존은 유지할 가치가 있는 후보다. 다만 이를 경쟁사가 복제하지 못하는 차별화로 보거나, 출처 표시만으로 사실 오류가 사라진다고 주장할 근거는 부족하다. 기술 이름보다 사용자 경험을 중심에 놓는 방향은 유효하지만, AI 도슨트가 제공할 추가 가치를 더 구체화해야 한다.

## 기존 제안에서 재검토할 주장

### 이야기와 장소를 연결하는 것만으로 독점적 차별화가 되지는 않는다

Mindtrip은 여행 콘텐츠를 개인화된 목록·일정으로 연결한다고 소개한다. VoiceMap은 장소에서 이야기를 듣는 도보 경험을 제공하며, 오디 자체에도 도보·코스여행이 있다. 따라서 비교 대상은 일반 AI 여행 채팅뿐 아니라 기존 오디오 가이드와 정적 큐레이션까지 포함해야 한다.

공식 소개 확인 자료(2026-09-09 확인, 실제 제품 비교 실험은 아님):

- [Mindtrip](https://mindtrip.ai/)
- [VoiceMap](https://voicemap.me/about)
- [오디 공식 앱 소개](https://play.google.com/store/apps/details?hl=ko&id=kto.smarttour)

이 자료만으로 경쟁사가 아래 제안과 동일한 기능을 제공하는지, 제공하지 않는지까지 단정하지 않는다.

### 코퍼스와 데이터 규율은 곧바로 모트가 아니다

오디 콘텐츠의 독점 이용권은 확인되지 않았다. 외부 콘텐츠, 출처 표시, 장소 고정 기능 자체를 복제 불가능한 자산으로 볼 수 없다. 직접 검수한 연결과 운영 경험이 축적되면 경쟁우위가 될 가능성은 있지만 현재는 검증해야 할 가설이다.

### 무할루시네이션을 약속하지 않는다

검색 범위를 제한해도 출처를 잘못 해석할 수 있다. 인용 ID의 존재와 해당 출처가 실제 주장을 뒷받침하는지는 별도로 검사해야 한다. '그 길은 거짓말하지 않는다'는 문구와 '무할루시네이션'이라는 보장은 채택하지 않는 방향을 제안한다.

### 이야기를 들은 사람이 항상 다음 장소를 원하는 것은 아니다

사용자는 현재 장소를 더 이해하고 싶을 수 있다. 질문에 대한 답변만으로 목적을 달성했다면 이동을 요구하지 않아야 한다. 모든 질문을 방문지 추천으로 연결하는 정책은 피한다.

### 의도 추출만으로는 AI의 추가 가치가 약하다

검수된 이야기와 장소를 연결하는 버튼은 AI 없이도 만들 수 있다. AI가 질문에 맞춘 설명, 비교, 맥락 이어가기에서 정적 콘텐츠보다 어떤 이점을 주는지 별도로 검증해야 한다.

## 대안 비교와 우선 검증 방향

| 접근 | 사용자가 얻는 것 | 주요 약점 |
|---|---|---|
| 이야기 → 주변 장소 | 다음에 갈 곳을 쉽게 찾음 | 관련 장소 목록과 차이가 작을 수 있음 |
| 질문 → 현장 관찰 → 다음 탐색 | 궁금했던 내용을 눈앞에서 이해함 | 관찰 대상과 설명을 현장까지 검수해야 함 |
| 두 시대 비교 | 같은 장소를 새롭게 바라봄 | 과거 자료와 현재 대응 지점 확보가 필요함 |

우선 검증 제안은 **내가 궁금해한 것을 실제 장소에서 발견하게 해주는 도슨트**다. 질문과 관찰을 중심에 놓고, 이어 걷기를 이동 기능으로 연결한다. 이는 현재 검증되지 않은 제품 가설이며 두 시대 비교는 후속 실험 후보로 남긴다.

기억에 남겨야 할 순간은 '추천이 나왔다'보다 **'아까 물어본 게 여기서 보이네'**에 가깝다.

## 가상 사용자 흐름

남산골 한옥마을을 활용한 설명용 시나리오다. 저장된 [오디 API 샘플](../../api/tour/tour_audio_guide_api.md)에는 창살·난간·환기구 등을 설명하는 대목이 있다. 아래 경험을 실제 제공하려면 현재 관람 가능 여부, 위치, 설명과 관찰 대상의 일치 여부를 추가 검수해야 한다. 현재 운영 정보나 실제 사용자 반응을 확인한 사례가 아니다.

1. 사용자가 오디를 듣다가 '한옥은 다 비슷해 보이는데, 뭘 보면 차이를 알 수 있어?'라고 묻는다.
2. 도슨트가 근거에 맞춰 짧게 설명하고 현재 장소에서 살펴볼 특징 하나를 제시한다. 질문이 해결되면 이동을 요구하지 않는다.
3. 사용자가 '다른 집과 비교해 보고 싶어'를 선택하면 이야기길이 비교할 후보를 보여준다. 카드의 중심 정보는 '여기서 무엇을 비교할 수 있는가'다.
4. 다음 장소에서 '도착했어요'를 누르면 직전 질문을 이어 관찰 포인트와 비교 설명을 보여준다. 같은 장소 소개를 처음부터 반복하지 않는다. 이 버튼은 자동 위치 검증이나 방문 사실 인증을 의미하지 않는다.
5. 사용자가 '장식보다 사람들이 살던 방식이 궁금해졌어'라고 하면 고정한 장소는 보존하면서 탐색 주제를 바꾼다.

## 도슨트와 이야기길의 역할

| 기능 | 책임 |
|---|---|
| 오디 AI 도슨트 | 지금 듣거나 보고 있는 것에 대한 질문을 이해하고 근거에 맞게 설명 |
| 이야기길 | 질문을 더 탐색할 장소·이야기·관찰 대상을 연결하고 선택 관리 |
| 공유 맥락 | 현재 이야기, 사용자가 명시한 관심, 이미 설명한 내용, 선택·제외한 장소 |

AI는 같은 검수 자료라도 질문에 맞춰 설명의 깊이를 바꾸고, 두 장소를 비교하고, 이미 설명한 내용을 이어갈 수 있다. 사실과 관계는 검수된 자료에 묶되 설명을 고정 문구로만 제한할 필요는 없다. 생성한 설명의 근거 적합성은 평가해야 한다.

오디 대본의 극화된 인물 대사를 실제 역사 기록처럼 인용하지 않는 구분도 필요하다. 근거가 부족한 경우에는 부족함을 알리고, 검증되지 않은 비교나 관찰 대상을 채워 넣지 않는다.

## 축적할 자산의 가설

단순한 이야기와 장소의 연결보다 **어떤 질문에, 어디의 무엇을 보여주면 이해가 생기는가**에 대한 검수 콘텐츠와 현장 검증 결과가 경쟁우위 후보가 된다.

아직 보유한 자산이나 입증된 방어력은 아니다. 콘텐츠 제작·검수·현장 확인·갱신 비용과 다른 지역으로 확장할 때의 비용도 함께 확인해야 한다.

## 가장 작은 검증

같은 자료로 만든 정적 해설·관련 장소 목록과 질문 기반 관찰 흐름을 비교한다. 초기에는 수동으로 진행할 수 있으며 SSE, LangGraph, 자동 위치 감지를 먼저 구현할 필요는 없다.

관찰할 행동은 다음과 같다.

- 사용자가 안내된 실제 관찰 대상을 찾는가.
- 보고 난 차이를 자기 말로 설명할 수 있는가.
- 다음 탐색을 자발적으로 선택하는가. 현재 질문이 해결돼 종료하는 경우도 구분해 기록한다.
- 잘못된 이해, 불필요한 이동, 조작 부담이 생기는가.

'신기한가'라는 반응만으로 성공을 판단하지 않는다. 비교 과업, 진행 순서, 참가자 조건과 과업별 성공·실패 기록을 남겨야 한다. 표본 수와 정량 합격선은 아직 합의하지 않았다.

수동 진행에서도 정적 안내 대비 이점이 보이지 않으면 질문·관찰 연결의 효용부터 재검토한다. 데이터 연결 실패와 사용자 가치 실패를 구분하고, 하나의 실패만으로 그래프나 UI 형태를 원인이라고 단정하지 않는다.

## 다음 논의에서 결정할 것

1. 첫 사용 순간: 여행 전에 갈 곳을 찾는 사람인가, 이미 관광지에 와서 무엇을 볼지 고민하는 사람인가.
2. 파일럿 지역에서 근거와 현장 관찰 대상이 연결되는 콘텐츠를 확보할 수 있는가.
3. 정적 안내와 비교할 대표 질문·과업 및 성공 기준은 무엇인가.

최초 추천은 **관광지 현장 사용자를 대상으로 먼저 검증**하는 것이었다. 후속 논의에서는 웹·앱 연속 사용을 반영해 방문 전 발견·저장과 현장 이해를 함께 다루기로 방향을 확장했다. 첫 평가 과업과 지역은 아직 확정되지 않았으며 [후속 상세안](journey-service-plan.md)에 남은 결정을 기록한다.
