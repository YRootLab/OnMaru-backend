# 행정안전부 한옥체험업 API 리뷰 및 도입 검토

본 문서는 온마루(On-Maru) 프로젝트의 기획(**Feature 2: 온마루 온기 맵 & 발자취**)에서 검토된 **'행정안전부_문화_한옥체험업 조회서비스'** 공공데이터의 특성을 분석하고, 우리 서비스의 하이엔드 UX 지향점과 부합하는지 장단점을 비교한 문서입니다.

---

## 1. API 개요 및 데이터 제공 형식

이 데이터는 각 지자체에서 영업 허가를 받은 **모든 한옥체험업소의 행정/인허가 정보**를 일괄 취합하여 제공합니다. 관광 목적이 아닌 '행정 관리' 목적의 데이터입니다.

### 📌 데이터 구조 (JSON 예시)
API 호출 시 아래와 같이 사진이나 설명 없이 텍스트 기반의 행정 데이터만 반환됩니다.

```json
{
  "body": {
    "items": [
      {
        "bplcNm": "락고재",              // 사업장명 (업소 이름)
        "dtlStateNm": "영업",            // [필수 필터링] 영업상태명 ('영업' 상태만 추출)
        "rdnwhlAddr": "서울특별시 종로구 계동길 49-23", // 도로명주소
        "sitewhlAddr": "서울특별시 종로구 계동 98번지", // 지번주소
        "siteTel": "02-123-4567",        // 전화번호
        "x": "199401.3214",              // X좌표 (Bessel 중부원점TM - 변환 필수)
        "y": "453412.1123",              // Y좌표 (Bessel 중부원점TM - 변환 필수)
        "apvPermYmd": "20100416",        // 인허가일자
        "totEpNum": "4",                 // [활용 추천] 객실수
        "totFlrNum": "1"                 // [활용 추천] 총층수 (주로 1층)
      }
    ]
  }
}
```

## 2. UI/UX 표출 시나리오 (사용자 화면 예상)

만약 이 데이터만 단독으로 사용하여 지도에 마커를 찍고 상세 페이지를 구성한다면, 사용자에게 다음과 같은 화면이 노출됩니다.

*   **지도 화면**: 마커는 정상적으로 표시됨 (단, 좌표계 변환 작업이 사전에 진행되어야 함).
*   **바텀 시트 (Bottom Sheet) 요약**:
    *   **이미지 영역**: `고급스러운 한옥 일러스트 기본 제공` (사진 부재 보완)
    *   **텍스트 영역**: "락고재 (영업중)", "종로구 계동길 49-23"
    *   **행정 데이터 가공**: "단층 한옥 • 객실 4개" (총층수 및 객실수 활용)
*   **상세 페이지 (Detail Page)**:
    *   숙소의 외부/내부 사진 ❌
    *   어떤 매력이 있는 한옥인지 설명(소개글) ❌
    *   주차/와이파이 등 편의시설 정보 ❌
    *   **노출되는 긍정적 정보**: 이름, 주소, 전화번호, **AI 생성 감성 문구**, 객실 규모(방 개수) 등.

## 3. 장점과 단점 (Pros & Cons)

### 👍 장점 (Pros)
1.  **압도적인 데이터 수량 및 포괄성**: 한국관광공사(TourAPI)에는 등록되지 않은 동네의 작은 한옥 민박집까지, 영업 허가를 받은 대한민국의 '모든' 한옥 숙소 리스트를 빠짐없이 얻을 수 있습니다.
2.  **정확한 영업 상태**: 폐업, 휴업 등의 상태가 관공서 데이터베이스와 연동되므로 최신 행정 상태가 반영됩니다. 백엔드에서 `dtlStateNm`이 **"영업"**인 데이터만 필터링하면 '현재 합법적으로 운영 중인 전국의 모든 한옥 숙소 리스트'를 정확히 뽑아낼 수 있습니다.

### 👎 단점 (Cons)
1.  **시각적 매력 부재 (하이엔드 UX 저해)**: 이미지(사진)와 상세 소개글이 전혀 없습니다. "가장 한국적인 공간에서 느끼는 프리미엄 경험"이라는 온마루의 기획 의도와 달리, 사용자에게 건조하고 텅 빈 상세 페이지를 제공하게 되어 앱의 퀄리티(톤앤매너)를 크게 떨어뜨릴 위험이 있습니다.
2.  **비표준 좌표계 사용**: 카카오맵 등 일반적인 지도에서 사용하는 위경도(WGS84)가 아닌 중부원점TM 좌표계를 사용하므로, 백엔드에서 위경도로 일일이 변환하는 데이터 가공 비용이 발생합니다.
3.  **관광 데이터로서의 한계**: 사용자는 "이 한옥이 얼마나 예쁜지, 어떤 체험을 할 수 있는지"가 궁금하지만, 해당 API는 '언제 영업 허가를 받았는지' 같은 불필요한 행정 정보만 제공합니다.

## 4. 결론 및 제안 (Conclusion)

온마루(On-Maru)는 단순한 '숙소 검색기'가 아니라, **이야기(도슨트)와 감성(온기 맵)이 결합된 프리미엄 서비스**를 지향합니다.

온마루의 목표는 유명 관광지뿐만 아니라, 지역 구석구석에 숨겨진 로컬 한옥까지 사용자에게 빠짐없이 안내하여 폭넓은 선택지와 풍부한 정보를 제공하는 것입니다. 따라서 TourAPI와 더불어 **행정안전부 데이터를 함께 연동하여 대한민국의 모든 한옥체험업소 정보를 사용자에게 포괄적으로 제공하는 것이 필수적**입니다.

*   **최종 권장**: PRD(기획서) 상의 **Feature 2(온마루 온기 맵)** 마커 표시에 '행정안전부 한옥체험업 API'를 보조 데이터로 연동하여 채택합니다. 단, 데이터의 시각적 매력 부재(사진/설명 없음)는 아래 **[5. AI 보완 방안]**을 통해 해결하는 하이브리드 전략을 사용합니다.

---

## 5. AI를 활용한 데이터 공백 보완 방안 (Hybrid Strategy)

행정안전부 데이터를 통해 사용자에게 더 많고 다채로운 로컬 한옥 정보를 제공하되, **설명과 사진이 없는 공백을 AI로 채우는 하이브리드 전략**입니다.

### 🤖 안전한 AI 활용 시나리오 (프롬프트 제어)
*   **텍스트(설명) 생성**: 백엔드에서 데이터를 수집할 때, 숙소 이름과 주소 데이터를 LLM(GenAI)에 넣어 짧고 따뜻한 소개글을 자동 생성합니다.
*   **환각(Hallucination) 방지 프롬프트**: AI가 실제 숙소에 없는 시설(마당, 방 개수 등)을 지어내지 않도록 팩트 기반 묘사를 금지하고, **오직 감성적인 환영 인사말만 2줄로 작성**하도록 통제합니다.
    *   *생성 결과 예시*: "종로구 계동의 조용한 골목에 자리한 **락고재**입니다. 가장 한국적인 공간에서 따뜻한 하룻밤의 온기를 남겨보세요."
*   **이미지 공백 대체**: 실제 사진이 없으므로, 온마루의 브랜딩 톤앤매너에 맞는 **고급스러운 3D/일러스트 한옥 렌더링 이미지**를 기본(Default) 썸네일로 제공합니다.

### 💡 결론 (투트랙 하이브리드)
1.  **프리미엄 숙소 (TourAPI 데이터)**: 돋보이는 핀으로 표시하고, 실제 사진과 상세 정보를 제공. (메인 콘텐츠)
2.  **로컬 동네 한옥 (행정안전부 데이터)**: 작고 은은한 '동네 한옥' 마커로 표시하고, 예쁜 일러스트와 AI가 생성한 '따뜻한 환대 메시지'를 제공하여 지도를 꽉 채우는 용도로 활용.
