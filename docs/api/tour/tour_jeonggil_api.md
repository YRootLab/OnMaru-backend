# Feature 4: 온마루 정-길 (Jeong-gil) API 도입 검토 및 활용 명세서

본 문서는 온마루 산책로 '정-길' 주변의 로컬 상권(전통시장, 공방, 찻집 등)을 맵에 구현하기 위해 검토 중인 공공 API 2종의 **실제 데이터 구조, 한계점, 그리고 이를 극복하기 위한 활용 방안과 기대 효과**를 팀원들과 논의하기 위해 작성되었습니다.

---

## 1. 공공 API 수신 데이터 현황 및 치명적 한계점

### [A] 국토교통부 전통시장현황 API (거시적 공간 정보)
시장의 위치, 편의시설, 규모 등 굵직한 행정 데이터를 제공합니다.

* **수신 가능 데이터 (주요 필드)**
  * `name`: 시장 명칭 (예: 광장시장)
  * `category`: 시장 형태 (상설장, 5일장 등)
  * `items`: 취급 품목 카테고리 (예: 농산물+의류+음식점)
  * `park` / `toilet`: 주차장, 공중화장실 보유 여부 (Y/N)
  * `market`: 점포 수 (규모 파악용)
  * `opn_per`: 장이 서는 주기 (예: 2일+7일장)
  * `ag_geom`: 시장 좌표 (Point)

* 🚨 **데이터 한계점 (반드시 인지해야 할 사항)**
  1. **사진(이미지) 존재 여부**: ❌ 단 1장도 없음.
  2. **상세 설명 텍스트 존재 여부**: ❌ 전혀 없음 (마케팅 문구 없음).
  3. **특정 먹거리/상품명 존재 여부**: ❌ "빈대떡, 마약김밥" 등 세부 메뉴명이 아니라 "가공식품+음식점" 형태로 뭉뚱그려져서 제공됨.
  4. **시장 내 개별 상점 리스트 여부**: ❌ 시장 구역에 대한 정보만 있을 뿐, 시장 안에 어떤 가게가 있는지 리스트업 해주지 않음.

### [B] 소상공인 상가(상권)정보 API (미시적 개별 점포 정보)
시장 내부나 산책로 길가에 있는 개별 상점의 디테일한 정보를 제공합니다.

* **수신 가능 데이터 (주요 필드)**
  * `bizesNm`: 개별 상호명 (예: 순희네 빈대떡, 아름다원)
  * `indsSclsNm`: 소분류 업종 (예: 전통찻집, 공방, 한식)
  * `lon`, `lat`: 개별 점포의 정확한 위경도 좌표

* 🚨 **데이터 한계점**
  * 이 API 역시 행정 데이터이므로 **가게 사진이나 상세 소개글, 메뉴 정보는 포함되어 있지 않습니다.**

## 2. API 활용 전략 (한계 극복 및 UI/UX 적용 방안)

위의 한계점(사진 부재, 상세 설명 부재)을 극복하고 온마루의 하이엔드 UI를 구현하기 위해 다음과 같은 **'공공데이터 + 민간API 매시업(Mash-up)'** 전략을 제안합니다.

1. **뭉뚱그려진 텍스트 ➡️ 감성 해시태그 파싱**
   * 전통시장 API에서 넘어오는 "가공식품+의류및신발" 문자열을 프론트엔드에서 쪼개어 `#가공식품` `#의류구경` 같은 칩(Chip) 형태의 큐레이션 UI로 매핑합니다.
2. **이미지 부재 ➡️ 외부 API 실시간 연동 (Fallback 처리)**
   * 유저가 지도 위의 마커를 클릭해 바텀 시트 팝업을 열 때, 상호명(`name`, `bizesNm`)을 바탕으로 **카카오 로컬 API나 네이버 이미지 검색 API**를 백엔드에서 1회 찔러 썸네일과 별점을 가져옵니다.
   * 외부 API 조회 실패 시 온마루가 자체 제작한 고화질 일러스트(예: 찻집 일러스트, 시장 일러스트)를 기본으로 노출합니다.
3. **편의 정보의 직관적 시각화**
   * `park` 필드가 Y면 **[🅿️ 주차가능]**, 5일장(`opn_per`) 날짜가 오늘과 일치하면 **[✨ 오늘 장날]** 뱃지를 달아 유저의 방문을 강력하게 유도합니다.

## 3. 도입 시 기대 효과 (왜 이 방식으로 가야 하는가?)

단순히 카카오/네이버 지도 API에만 의존하지 않고, 이 공공데이터를 우리 DB에 구축했을 때 얻는 효과입니다.

1. **데이터 소유 및 오프라인 공간 쿼리 가능**
   * 카카오 API는 상점 리스트를 우리 DB에 대량 저장하는 것을 금지합니다.
   * 공공데이터로 뼈대(좌표, 상호명)를 구축해 두면, "특정 산책로 좌표 반경 1km 이내의 전통찻집"을 우리 서버 단독으로 과금 없이 매우 빠르게 필터링(Spatial Query) 할 수 있습니다.
2. **맞춤형 로컬 큐레이션 가능**
   * 카카오에는 명확한 필터로 존재하지 않는 "온누리상품권 가능 매장", "주차 가능한 전통시장" 등의 로컬 맞춤형 필터링을 온마루 앱 내에서 자체적으로 구현할 수 있습니다.
3. **비용 절감 및 속도 최적화**
   * 지도에 수십 개의 마커를 뿌릴 때는 우리 DB의 가벼운 공공데이터를 쓰고, 유저가 특정 상점을 클릭했을 때만 카카오/네이버 API를 호출하므로 외부 API 호출 비용을 획기적으로 줄일 수 있습니다.
