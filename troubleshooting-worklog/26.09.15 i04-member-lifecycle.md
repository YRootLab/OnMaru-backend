# 26.09.15 I04 Member lifecycle

## 문제

#93은 회원 세션 조회, logout, 탈퇴 요청을 같은 session boundary에서 처리해야 했다. logout 직후 같은 cookie가 더 이상 인증되지 않아야 하고, 탈퇴 요청은 member를 `DELETING`으로 바꿔 late run/save 같은 후속 쓰기가 재생성되지 않게 막아야 했다.

## 진행

- `modules:identity`에 `lifecycle` package를 추가해 member 조회, session revoke, deletion request 정책을 분리했다.
- 기존 `InMemoryIdentityStore`를 OAuth session 저장소이자 lifecycle 저장소로 확장해 Kakao login으로 발급한 opaque session과 member API가 같은 store를 보게 했다.
- `MemberLifecycleService`가 session token 원문을 `TokenHasher`로 hash한 뒤 active session/member만 반환하도록 했다.
- `POST /api/v1/auth/logout`, `GET /api/v1/members/me`, `DELETE /api/v1/members/me` web boundary를 추가했다.
- logout/delete 응답은 session cookie를 즉시 만료시키고 `Cache-Control: no-store`를 유지한다.
- 삭제 요청은 member 상태를 `DELETING`으로 바꾸고 deletion ledger를 남기는 store contract로 표현했다.

## 왜 이 기술을 사용했나

- Store port + service: session cookie 처리와 member lifecycle 정책을 controller에서 분리해 후속 JDBC persistence로 교체하기 쉽게 했다.
- `TokenHasher`: session 원문을 조회 key로 직접 저장·비교하지 않고 hash로만 다루기 위해 기존 OAuth 보안 경계를 재사용했다.
- `__Host-onmaru-session` 만료 cookie: 브라우저가 즉시 기존 opaque session을 버리게 하면서 서버 revoke도 함께 수행하기 위해 사용했다.
- MockMvc boundary test: 계약 fixture의 status/header/body/cookie 동작을 Spring filter와 함께 검증하기 위해 사용했다.

## 해결 결과

- session cookie가 없거나 revoke/deletion된 사용자는 `/api/v1/members/me`에서 `AUTH_REQUIRED`를 받는다.
- logout 직후 같은 session token은 더 이상 current member로 조회되지 않는다.
- 탈퇴 요청은 `DELETING`을 반환하고 session을 폐기한다.
- `DELETING` member는 `allowsLateWrite=false`가 되어 late run/save 재생성 방지 조건을 만족한다.
