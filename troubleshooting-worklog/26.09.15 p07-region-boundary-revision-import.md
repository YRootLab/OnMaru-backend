# P07 행정구역 경계 revision import 작업 로그

날짜: 2026-09-15

## 문제 상황

#137은 좌표 resolve와 관광 관측 연결의 선행 조건인 행정구역 경계 데이터를 안전하게 활성화하는 작업이었다. 경계 데이터는 잘못 공개되면 후기 지역 집계와 방문자 관측 API가 틀린 지역을 반환하므로, 실제 DB import 전에 source qualification, revision evidence, geometry 검증, quarantine 흐름이 먼저 필요했다.

## 오류명 또는 실패 증상

TDD 첫 실행은 `RegionBoundaryImportService`, `RegionBoundaryGeometry`, `RegionBoundarySourceManifest` 등 타입이 없어 compile RED가 났다. 이후 첫 GREEN 직전에는 테스트 fixture에서 “구 없는 시군”인 `광주시`를 시도 부모 없이 넣어 `PARENT_REGION_NOT_FOUND`가 발생했다. 이는 fixture가 행정계층을 잘못 표현한 것이어서 `경기도(41)` 부모를 추가해 수정했다.

## 기존 구조나 방식의 한계

`catalog` 모듈에는 source qualification, sync checkpoint, dataset publication 조각은 있었지만 행정경계 전용 도메인 경계가 없었다. 그래서 #102의 `/regions/resolve`나 #90의 관측 adapter가 바로 raw boundary file이나 DB 테이블에 의존하면, 출처·권리·revision hash가 없는 데이터를 실수로 활성화하거나 부모 없는 지역 코드와 invalid geometry가 공개 read model로 섞일 수 있었다.

## 관련 코드 맥락

- `modules/catalog/src/main/java/com/yrootlab/onmaru/catalog/application/regionboundary/RegionBoundaryImportService.java`
  - `RegionBoundaryImportCommand`를 받아 source manifest를 먼저 검증한다.
  - `datasetUrl`, `license`, `attribution`, `observedAt`, 64자 SHA-256 `revisionHash`가 없으면 `SOURCE_NOT_QUALIFIED`로 거절한다.
  - 후보별로 필수 필드, geometry, SIDO/SIGUNGU 부모 관계를 검사하고 rejected row는 `RegionBoundaryQuarantine`으로 분리한다.
  - 유효 row가 하나 이상이면 `RegionBoundaryRevision`을 active revision으로 게시한다.

- `modules/catalog/src/main/java/com/yrootlab/onmaru/catalog/application/regionboundary/RegionBoundaryGeometry.java`
  - WGS84 좌표 ring이 닫혀 있는지, 대한민국 좌표 범위 안인지, 면적이 0이 아닌지 확인한다.
  - point-in-polygon 계산에서 경계선 위 좌표를 포함으로 처리한다. #102의 좌표 resolve에서 경계점 fixture를 0건으로 오판하지 않기 위함이다.

- `modules/catalog/src/main/java/com/yrootlab/onmaru/catalog/application/regionboundary/InMemoryRegionBoundaryStore.java`
  - 현재는 DB 대신 active revision을 메모리에 보관하고, 좌표가 포함되는 SIDO/SIGUNGU projection을 반환한다.
  - 이후 PostGIS repository가 들어와도 `RegionBoundaryStore` 포트만 교체하면 import service의 검증 규칙은 유지된다.

- `docs/reference-snapshots/region-boundaries/manifest.json`
  - 행정안전부 경계 데이터의 source URL, license, attribution, observedAt, revision hash, fixture coverage를 기록했다.

## 검토한 선택지

1. PostGIS import까지 한 번에 구현한다.
2. 문서 manifest만 추가하고 코드 구현을 미룬다.
3. 순수 Java 도메인 import/validation 포트를 먼저 만들고, DB import는 후속 이슈에서 연결한다.
4. invalid row가 하나라도 있으면 전체 revision을 실패시킨다.

## 판단 기준

- #137의 AC인 source evidence, 동명 구, 구 없는 시군, 경계점, invalid geometry quarantine을 지금 검증할 수 있어야 한다.
- #102와 #90이 재사용할 수 있는 명확한 도메인 포트가 있어야 한다.
- 현재 저장소의 documentation-first/runtime scaffold 상태에서 외부 대용량 GIS fixture를 무리하게 넣지 않아야 한다.

## 최종 결정

순수 Java `regionboundary` 도메인 import/resolve 포트를 먼저 구현하고, source manifest 문서와 테스트 fixture로 검증 가능한 안전장치를 세웠다.

## 해결 방식

- `RegionBoundarySourceManifest`로 source URL, license, attribution, observedAt, revision hash를 필수화했다.
- `RegionBoundaryGeometry`로 닫힌 ring, 한국 좌표 범위, 경계점 포함 판정을 구현했다.
- `RegionBoundaryImportService`에서 부모 없는 SIGUNGU, invalid geometry, 누락 필드를 quarantine하도록 했다.
- `RegionBoundaryImportServiceTests`에 서울/부산 `중구` 동명 구, 경기도 `광주시` 같은 구 없는 시군, 경계점 포함, invalid geometry quarantine fixture를 추가했다.
- `docs/reference-snapshots/region-boundaries`에 qualification manifest를 추가해 데이터 source와 권리 근거를 남겼다.
