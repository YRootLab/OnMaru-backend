# Gemini provider adapter 구현

## 문제

FastAPI에는 intake와 deterministic baseline만 있고 외부 model adapter가 없었다. Gemini 실패가 예외 문자열로 새거나 무제한 대기하면 Spring의 baseline fallback 계약을 안정적으로 실행할 수 없고, prompt·evidence·key를 telemetry에 남기면 보안 경계를 위반한다.

## 진행

1. provider package 부재로 실패하는 테스트를 먼저 만들었다.
2. REST transport와 provider-neutral request/response type을 분리했다.
3. policy, versioned few-shot, untrusted data block을 분리하고 JSON structured output, temperature 0, output token 상한을 요청에 고정했다.
4. 429, timeout, service failure, malformed response와 caller cancellation을 typed code로 변환했다.
5. key·prompt·evidence 없이 model/version/revision과 usage/cost만 telemetry에 기록하도록 검증했다. 독립 review에서 invalid JSON 응답의 usage 누락을 발견해 parse 전에 usage를 보존하도록 보강했다.
6. authorization key가 있을 때만 실행되는 5초·64 output token live smoke를 추가했다.
7. 상위 task cancellation을 provider 오류로 바꾸지 않고 transport cleanup 뒤 `CancelledError`를 재전파하도록 독립 review finding을 반영했다.

## 결과

- focused fake-provider test 9개 통과
- 전체 pytest, Ruff, mypy와 repository verification은 PR 직전 실행한다.
- live smoke는 실제 key를 repository나 기본 CI에 제공하지 않으므로 기본 suite에서 skip한다.
