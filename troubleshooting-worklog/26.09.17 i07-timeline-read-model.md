# [I07] 내 월간 활동 타임라인 read model 구현

## 1. 개요
- **Issue**: [#126 [I07] 내 월간 활동 타임라인 read model 구현](https://github.com/YRootLab/OnMaruBE/issues/126)
- **작업 브랜치**: `feature/126-timeline-read-model`
- **목적**: 월별 찜(장소), 담아두기(오디 이야기), 여정 저장, 방문 후기 작성 4종 활동을 KST 월 단위로 프로젝션하고 날짜별(`groups`)로 정렬·합성한 `GET /api/v1/me/timeline` Read Model 엔드포인트를 제공한다.

## 2. 주요 설계 및 구현 내용
1. **도메인 프로젝션 (`modules/journey/timeline`)**:
   - `TimelineItemType`: `SAVED_PLACE`, `SAVED_ODII_STORY`, `SAVED_JOURNEY`, `WROTE_VISIT_REVIEW` 4종 이벤트 지원.
   - `TimelineTarget`: Sealed interface 기반 다형성 타깃(`PLACE`, `ODII_STORY`, `SAVED_JOURNEY`, `VISIT_REVIEW`).
   - `MemberTimelineService`:
     - KST(`Asia/Seoul`) 월 경계 계산 (`[month.start, month.end)`).
     - 원천 저장소로부터 4종 이벤트를 시간 역순 정렬(`occurredAt DESC, id DESC`).
     - 비공개/삭제 리소스는 카드 노출 대신 `unavailableCount`만 증가시켜 stale 데이터 유출 방지.
     - `asOf` 시점 일관성 및 `TimelineCursor` 기반 서명 페이지네이션(`hasMore`, `nextCursor`).
     - KST `YYYY-MM-DD` 기준 일자별 그룹화(`groups`).

2. **스프링 웹 어댑터 및 보안 경계 (`apps/spring-api/web/me/timeline`)**:
   - `MemberTimelineController`:
     - `GET /api/v1/me/timeline` 엔드포인트.
     - 세션 쿠키(`__Host-onmaru-session`) 기반 인증 필수(미인증 시 `401 AUTH_REQUIRED`).
     - `Cache-Control: no-store` 헤더 적용으로 개인 응답 브라우저/프록시 캐싱 방지.
     - `month`(`YYYY-MM`), `limit`(1..50) 파라미터 유효성 검사(`400 VALIDATION_ERROR`).
     - 서명 커서 코덱(`MemberTimelineCursorCodec`): 10분 TTL 만료 검증(`410 CURSOR_EXPIRED`), 타 회원 커서 격리(`404 NOT_FOUND`), 위변조 방지(`400 CURSOR_INVALID`).
   - 관측성(Observability): SLF4J Key-Value 구조화 로깅(`member.id`, `month`, `timeline.group_count`, `timeline.unavailable_count`, `timeline.has_more`).
