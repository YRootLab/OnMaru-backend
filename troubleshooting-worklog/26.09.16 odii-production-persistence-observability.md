# Odii production revision 저장과 운영 관측성 보강

날짜: 2026-09-16

## 문제 상황

Issue #197은 #96/#103/#104에서 만든 Odii 수집·공개 API·장소 연결 계약을 production runtime으로 연결하는 follow-up이다. 기존 runtime은 `InMemoryAudioRevisionStore` 중심이라 Spring 재시작 후 active revision을 복원할 수 없고, production 다중 writer에서 장소 연결 승인 불변식을 DB가 보장하지 못했다.

## 실패 증상과 리스크

- production profile에서 in-memory store가 선택되면 provider fixture를 publish해도 재시작 후 active revision이 사라진다.
- 마지막 page 실패나 stale writer가 LKG를 덮으면 공개 API가 검증되지 않은 partial revision을 노출할 수 있다.
- `audio_place_odii_links` 승인 전환이 여러 save 조합이면 동시 승인 또는 부분 저장이 남을 수 있다.
- 운영 관측성이 없으면 `SOURCE_FAILED`, `ACTIVE_REVISION_CHANGED`, 승인 conflict, active revision unavailable을 장애/정상 방어 신호로 구분하기 어렵다.

## 관련 코드 맥락

- `apps/spring-api/src/main/java/com/yrootlab/onmaru/tourism/audio/JdbcAudioRevisionStore.java`
  - `AudioRevisionStore`의 PostgreSQL adapter다. stage open 시 `catalog_dataset_revisions`와 `audio_revision_stages`를 만들고, base revision이 있으면 spot/story/subtitle version을 복사한 뒤 새 provider rows를 observed로 upsert한다. publish는 lease, active revision, stage ready, active pointer, watermark 갱신을 한 transaction에서 처리한다.
- `apps/spring-api/src/main/resources/db/migration/baseline/V010__a02_odii_production_persistence.sql`
  - `audio_revision_stages`, version row의 `source_modified_at/observed/missing_observations`, `transcript_provenance`, place-link `review_status`, spot별 approved partial unique index를 추가한다.
- `apps/spring-api/src/main/java/com/yrootlab/onmaru/persistence/audio/JdbcAudioPlaceLinkStore.java`
  - `approveExclusive`가 같은 spot 후보를 `FOR UPDATE`로 잠그고, 다른 후보를 reject한 뒤 대상 후보만 approve한다. 실패 시 rollback되어 기존 approved 상태가 유지된다.
- `modules/audio/src/main/java/com/yrootlab/onmaru/audio/sync/OdiiRevisionSyncService.java`
  - `OdiiSyncObserver`를 통해 sync started/failed/completed lifecycle을 기록한다.
- `apps/spring-api/src/main/java/com/yrootlab/onmaru/web/audio/TelemetryOdiiStoryQueryStore.java`
- `modules/audio/src/main/java/com/yrootlab/onmaru/audio/query/ObservedOdiiStoryQueryStore.java`
  - active revision snapshot 조회 성공/실패를 `OdiiStoryQueryObserver` port로 알린다.
- `apps/spring-api/src/main/java/com/yrootlab/onmaru/observability/TelemetryOdiiStoryQueryObserver.java`
  - query observer port를 기존 `TelemetrySink` 이벤트로 변환한다. web slice가 observability에 직접 의존하지 않도록 분리했다.

## 검토한 선택지

1. 기존 in-memory store 유지 후 startup seed만 추가: 재시작 복원과 동시 writer 문제가 해결되지 않아 제외했다.
2. JPA entity 도입: 현재 저장소는 domain port와 SQL migration 중심이라 변경 범위가 커져 제외했다.
3. JDBC adapter + existing port 유지: domain 계약을 보존하면서 production persistence만 교체할 수 있어 선택했다.
4. 관측성을 controller에만 추가: sync/publish/place-link transaction 결과를 놓치므로 부족했다.

## 최종 결정

PostgreSQL JDBC adapter와 migration을 추가하고, production profile에서 JDBC store를 선택하게 했다. 관측성은 domain에는 `OdiiSyncObserver` port로, Spring runtime에는 기존 `TelemetrySink` adapter로 연결했다.

## 해결 방식

- `JdbcAudioRevisionStore`가 stage, publish, active snapshot load, tombstone 누적, watermark 갱신을 DB transaction으로 처리한다.
- `OdiiStoryVersion`에 `AudioSubtitleLine`을 추가하고, active projection은 subtitle line을 R2 transcript로 매핑한다.
- `OdiiProjectionMetadataResolver`와 `CatalogRegionOdiiProjectionMetadataResolver`로 category/region hydrate와 대한민국 fallback을 분리했다.
- production profile에서 `AudioRevisionStore`/`AudioPlaceLinkStore`는 JDBC adapter를 사용하고, non-production fallback만 in-memory를 허용한다.
- `JdbcAudioPlaceLinkStore`와 DB partial unique index가 spot별 approved link를 최대 1개로 제한한다.
- telemetry 이벤트를 추가했다.
  - `odii.sync.started`
  - `odii.sync.failed`
  - `odii.sync.completed`
  - `odii.place_link.approval.completed`
  - `odii.place_link.approval.failed`
  - `odii.active_revision.snapshot`
  - `odii.active_revision.unavailable`
