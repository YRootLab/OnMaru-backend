# M02 VisitReview 목록 조회와 cursor 구현

날짜: 2026-09-15

## 문제 상황

Issue #110은 공개 방문 후기 목록을 `ALL`, `REGION`, place 범위로 안정적으로 조회하고, `limit + 1` cursor paging을 제공하는 작업이었다. 계약 문서에서는 `createdAt DESC, id DESC` 순서, `mine`, `likedByMe`, `likeCount`, `queryKey`, `coverage` 응답을 요구했다.

## 오류명 또는 실패 증상

- 신규 community 모듈이 없어 `modules/community` 경로 자체가 없었다.
- 첫 cursor 테스트에서 `VisitReviewCursorExpiredException`이 발생했다. cursor 만료를 review `createdAt` 기준으로 계산했기 때문에, 과거 후기를 페이지 기준점으로 쓰면 새로 발급한 cursor도 즉시 만료되는 문제가 있었다.

## 기존 구조나 방식의 한계

VisitReview schema와 DB migration은 있었지만 read model 코드와 web boundary는 없었다. 후기 작성, 좋아요, 신고 이슈가 뒤따르기 때문에 목록 조회를 catalog나 journey에 섞지 않고 `modules/community`의 query package로 분리해야 했다.

## 관련 코드 맥락

- `modules/community/.../query/VisitReviewQueryService`
  - `VisitReviewQuery`를 입력받아 `PUBLISHED` 후기만 필터링한다.
  - `ALL`, `REGION`, `PLACE` 범위에 맞춰 필터링하고 `createdAt DESC, id DESC`로 정렬한다.
  - cursor는 `queryKey`, `limit`, 마지막 반환 item의 `createdAt/id`, `issuedAt`을 Base64 URL-safe payload로 담는다.
  - decode 시 queryKey와 limit이 현재 요청과 다르면 `VisitReviewCursorInvalidException`을 던진다.
- `apps/spring-api/.../web/review/query/VisitReviewQueryController`
  - `/api/v1/visit-reviews`와 `/api/v1/places/{placeId}/visit-reviews`를 노출한다.
  - session cookie가 있으면 현재 회원을 조회해 `mine`과 `likedByMe` 계산에 전달한다.
- `.github/workflows/ci.yml`
  - 새 `modules:community:test` 단계를 추가해 PR마다 read model 테스트가 빠지지 않게 했다.

## 검토한 선택지

1. Spring API 내부 패키지에만 구현: 빠르지만 이후 작성/좋아요/신고 로직과 도메인 경계가 흐려진다.
2. DB repository까지 바로 구현: 현재 로컬 API scaffold 흐름보다 범위가 커지고, paging 규칙 검증이 느려진다.
3. community 모듈의 in-memory read projection으로 계약을 먼저 고정: 기존 catalog/journey 패턴과 맞고 후속 DB adapter 교체가 쉽다.

## 판단 기준

- cursor 무누락 규칙과 scope binding이 가장 중요하다.
- 후속 #118/#122/#123이 같은 community 경계를 재사용할 수 있어야 한다.
- CI에서 새 모듈 테스트가 자동으로 실행되어야 한다.

## 최종 결정

`modules:community`를 추가하고 VisitReview query/read model을 독립 모듈로 구현했다. 실제 DB adapter는 후속 persistence 연결 시 교체하고, 현재는 in-memory projection으로 public API 계약을 고정한다.

## 해결 방식

- TDD로 `VisitReviewQueryServiceTests`를 먼저 작성해 정렬, cursor, scope/limit binding, region/place filter, unsupported scope 400 전파 조건을 고정했다.
- cursor 만료 기준을 review 작성시각이 아니라 cursor 발급시각 `issuedAt`으로 수정했다.
- `VisitReviewQueryWebBoundaryTests`로 목록 endpoint, place endpoint, session 기반 `mine/likedByMe`, cursor error envelope를 검증했다.
- Spring API가 `modules:community`를 의존하도록 Gradle 설정을 갱신하고 CI에 community 테스트 단계를 추가했다.

## 결과

- community 모듈 테스트와 Spring web boundary 테스트가 통과했다.
- #118 작성/삭제, #122 좋아요, #123 신고·moderation 작업이 재사용할 수 있는 기본 read boundary가 생겼다.
