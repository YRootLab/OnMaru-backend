# C04 monthly hanok editorial 구현

날짜: 2026-09-15

## 문제 상황

Issue #84는 사람이 게시한 월별 한옥 editorial edition을 재현 가능하게 제공해야 했다. AI 추천이나 실시간 인기 순위가 아니라, publish된 placement 순서와 이유를 그대로 API에서 반환해야 한다.

## 오류명 또는 실패 증상

- RED 테스트 실패: `MonthlyHanokEditionService`, `MonthlyHanokEditionDraft`, `MonthlyHanokSlot`, `InMemoryMonthlyHanokEditionStore` 등이 없어 catalog 도메인 테스트가 컴파일 실패했다.
- 웹 RED 테스트 실패: monthly store bean과 `/api/v1/hanoks/monthly` controller가 없어 Spring context 테스트가 실패했다.

## 기존 구조나 방식의 한계

#98에서 한옥 목록 card projection은 생겼지만, 월별 editorial은 별도의 publish 단위와 placement 순서를 가진다. list query만으로는 사람이 정한 slot, reason, month별 revision을 표현하거나 비공개 place 참조를 publish 시점에 막을 수 없었다.

## 관련 코드 맥락

- `modules/catalog/editorial/MonthlyHanokEditionService`
  - `publish(draft)`: draft의 placement placeId가 현재 public hanok snapshot에 있는지 검증한 뒤 저장한다.
  - `find(month, memberId)`: published draft를 읽어 placement 순서대로 `HanokCard`를 구성하고 saved state를 반영한다.
- `InMemoryMonthlyHanokEditionStore`
  - 월별 draft를 저장하는 현재 scaffold용 store다.
  - `markUnavailable()`로 read failure 503 경계를 테스트한다.
- `apps/spring-api/web/editorial/MonthlyHanokEditionController`
  - `GET /api/v1/hanoks/monthly?month=YYYY-MM` 요청을 YearMonth로 해석한다.
  - store outage는 R1 공통 `SERVICE_UNAVAILABLE` envelope으로 반환한다.

## 검토한 선택지

1. `/hanoks/monthly`에서 한옥 목록 상위 N개를 자동 조합한다.
2. fixture JSON을 controller에서 직접 반환한다.
3. editorial draft/store/service를 catalog module에 두고, web layer는 query만 호출한다.

## 판단 기준

- C04의 핵심은 “사람이 게시한 순서와 이야기”를 재현하는 것이다.
- publish validation은 web controller보다 catalog editorial domain에 있어야 한다.
- placement의 place card는 #98의 list card projection과 같은 모양이어야 한다.

## 최종 결정

3번을 선택했다. catalog editorial service가 publish validation과 query projection 조합을 담당하고, Spring API는 R1 endpoint와 error envelope만 맡는다.

## 해결 방식

- `MonthlyHanokEditionServiceTests`로 public place만 publish 가능, placement 순서 유지, saved state 반영, 월 없음 empty placements를 먼저 고정했다.
- `MonthlyHanokEditionWebBoundaryTests`로 2026-09 fixture 응답, 2026-10 empty placements, store outage 503을 검증했다.
- Spring configuration에서 2026-09 editorial fixture를 seed했다.

## 결과

- `/api/v1/hanoks/monthly`가 published editorial edition을 반환한다.
- 비공개/없는 place 참조는 publish 시점에 거부된다.
- 월 없음은 empty placements로 안정적으로 응답한다.
