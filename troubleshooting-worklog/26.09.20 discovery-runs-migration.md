# `onmaru.discovery_runs` relation 누락 troubleshooting

## 증상

PostgreSQL 요청에서 다음 오류가 발생한다.

```text
ERROR: relation "onmaru.discovery_runs" does not exist
```

이 오류는 Bean wiring 오류가 아니라, Journey JDBC adapter가 `onmaru.discovery_runs`를 조회하거나 저장하는 시점의 운영 DB 스키마 불일치다.

## 코드와 migration 확인 결과

- JDBC 구현은 `onmaru.discovery_runs`를 직접 사용한다.
  - `adapters/persistence-jdbc/.../JdbcJourneyRunStore.java`
  - `adapters/persistence-jdbc/.../JdbcJourneyResultStore.java`
- 해당 테이블 생성 SQL은 이미 저장소에 있다.
  - `apps/spring-api/src/main/resources/db/migration/baseline/V006__d04_journey_discovery_schema.sql`
- `V006`은 `onmaru.discovery_explorations`, `onmaru.discovery_runs`, proposals, turns 및 active-run unique index를 함께 생성한다.
- Spring은 `classpath:db/migration/baseline`을 Flyway location으로 사용한다.
  - `apps/spring-api/src/main/resources/application.yaml`

따라서 현재 증상만으로는 코드에 `CREATE TABLE`이 빠진 상태가 아니라, production DB에 migration이 적용되지 않았거나 Flyway history와 실제 schema가 drift된 상태가 가장 유력하다. `public.discovery_runs`에만 테이블이 있다면 schema mismatch다.

## Neon에서 실행할 read-only 확인 SQL

```sql
SELECT current_database(), current_schema(), current_user;

SELECT schema_name
FROM information_schema.schemata
WHERE schema_name IN ('onmaru', 'public');

SELECT table_schema, table_name
FROM information_schema.tables
WHERE table_name IN (
  'discovery_explorations',
  'discovery_runs',
  'discovery_proposals',
  'discovery_turns'
)
ORDER BY table_schema, table_name;

SELECT installed_rank, version, description, success
FROM flyway_schema_history
WHERE version IN ('001', '006', '009', '014', '015')
ORDER BY installed_rank;
```

## 판정과 조치

| 결과 | 판정 | 조치 |
| --- | --- | --- |
| `onmaru.discovery_runs` 없음, Flyway `006` 없음 | migration 미적용 | 운영 migration credential로 정상 배포/기동하여 Flyway를 실행 |
| `onmaru.discovery_runs` 없음, Flyway `006` 성공 | DB drift 또는 수동 복구 누락 | 수동 `CREATE TABLE` 금지. DB 백업 후 reconciliation migration을 새 버전으로 검토 |
| `public.discovery_runs`만 존재 | schema mismatch | 애플리케이션 SQL을 바꾸지 말고 `onmaru` schema migration 및 데이터 이관 계획을 검토 |
| `onmaru.discovery_runs` 존재 | 다른 DB/branch 접속 또는 권한 문제 가능 | Render `ONMARU_DB_URL` 대상과 Neon branch/database를 대조하고 runtime role 권한을 확인 |

운영 DB에서 직접 `CREATE TABLE`을 실행하지 않는다. Flyway history와 실제 객체를 먼저 대조하고, drift가 확인될 때만 별도 reviewed migration으로 복구한다.
