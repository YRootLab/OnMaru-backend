# AI06 offline 평가 harness 구축

- 날짜: 2026-09-16
- 관련 Issue: #111

## 문제 상황

baseline과 모델 proposal의 품질·안전·비용·지연을 같은 fixture로 재실행하고 비교할 실행 계약이
없었다. model·prompt·ranking·dataset 버전도 하나의 결과에 고정되지 않아 수치 변화의 원인을
분리하기 어려웠다.

## 실패 증상

첫 RED 테스트는 `ModuleNotFoundError: onmaru_ai.evals`로 실패했다. 구현 후 경계 테스트에서는
검색 결과가 비어도 nDCG가 `1.0`이 되는 오류와 `--compare` report가 closed schema에서 거절되는
문제가 드러났다.
독립 리뷰에서는 빈 `PROPOSE_BOARD`, actual까지 포함한 비교 hash, 중복 retrieval로 부풀릴 수 있는
nDCG, evidence ID 일치율을 semantic faithfulness로 부른 문제를 재현했다.
재리뷰에서는 공백·URL·Markdown summary가 통과하는 문제, dataset 표시명까지 gold hash에 포함한
문제, report의 gate 집합과 `overallPassed` 불변식이 열려 있던 문제, snake_case wire key 우회를
추가 RED 테스트로 재현했다.

## 관련 코드 맥락

- `ai/src/onmaru_ai/evals/models.py`: fixture, version pin, threshold, report의 closed Pydantic 계약
- `ai/src/onmaru_ai/evals/runner.py`: recall@5, nDCG@3, claim support, evidence ID precision, safety, p95, cost와 gate 계산
- `ai/src/onmaru_ai/evals/cli.py`: JSON 입출력, 이전 report 비교, gate 기반 종료 코드
- `scripts/run-ai-evals`: 저장소 루트에서 실행하는 offline 진입점

runner는 외부 모델을 호출하지 않는다. 실제 실행에서 수집한 결과를 고정 입력 계약으로 정규화한
뒤 순수 계산만 수행하며, canonical input hash로 같은 fixture인지 식별한다.

## 검토한 선택지

1. 평가마다 live provider를 호출: 실제성은 높지만 비용·변동성과 secret 의존 때문에 PR gate에 부적합
2. 점수만 문서에 수기 기록: 재실행과 threshold 실패 종료 코드를 보장하지 못함
3. 고정 gold/actual fixture를 offline 채점: 결정적 CI와 버전 비교에 적합
4. RAG까지 함께 활성화: Issue #119 범위이며 baseline gate와 결합하면 책임이 흐려짐

## 최종 결정

고정 fixture를 strict schema로 검증하고 report schema와 종료 코드를 제공하는 offline harness를
선택했다. RAG activation과 live model 실행은 제외했다.

## 해결 방식과 결과

- 중복 case ID와 잘못된 gold ref를 입력 단계에서 fail-closed 처리했다.
- 빈 retrieval의 nDCG ideal ranking을 실제 결과 길이가 아니라 top 3 gold 기준으로 계산했다.
- allowlist·pin·exclude·outcome·reason/evidence 위반을 case safety violation으로 집계했다.
- 실행 시각을 제외하고 정렬된 JSON과 canonical SHA-256으로 report 재현성을 확보했다.
- 이전 report delta를 동일한 closed report schema 안에 포함했다.
- CI에서 offline gates와 생성 schema drift를 함께 검증한다.
- report `1.1`은 전체 input hash와 actual/model을 제외한 gold hash를 분리해 같은 gold의 challenger만
  compatible하게 비교한다.
- `PROPOSE_BOARD`의 1~3 ref/reason exact shape와 unique retrieval을 입력에서 거절하고, nDCG도
  중복 ref를 한 번만 계산한다. 잘못된 입력은 traceback 대신 종료 코드 2로 끝난다.
- 생성 summary 전체의 frozen human support label을 별도 `claimSupport`로 계산하고, ID 일치는
  `evidenceIdPrecision`으로 이름을 바로잡았다.
- production proposal validator와 eval이 공용 plain-text safety helper를 사용해 summary의 공백,
  모든 scheme URL, protocol-relative/IP/IDN URL, Markdown(Setext 포함)을 같은 정책으로 거절한다.
- `goldSha256`은 case ID와 immutable gold만 포함한다. dataset 표시명만 바꾼 report는 호환되고
  relevance 같은 gold 내용을 바꾸면 호환되지 않는다.
- report는 `quality`, `safety`, `latency`, `cost`, `determinism` 다섯 gate를 정확히 한 번 요구하고
  `overallPassed`와 gate 논리곱의 일치를 model validation에서 강제한다. JSON Schema도 개수·고유성을
  선언하며 wire 입력은 camelCase alias만 허용한다.

## 병합 후 final audit 보강

- Python 정규식의 Unicode `\b`가 한글 접두어와 ASCII scheme 사이를 경계로 보지 않아
  `안내tel:`과 `이동javascript:`를 놓치는 반례를 production proposal과 eval 양쪽에서 재현했다.
  ASCII scheme character negative lookbehind를 사용해 이 입력을 거절한다. colon 다음이 whitespace인
  `Reason: reviewed evidence only.`는 자연어 label로 허용한다.
- hostname heuristic은 dot label마다 alphabetic 문자를 요구한다. 따라서 실제 bare domain과 IDN은
  계속 거절하면서 `Version 1.2`, `평점은 4.5`, `약 1.5km` 같은 관광 문장의 숫자 token은 허용한다.
- offline launcher가 Python 3.11 이하만 우회하고 3.13 이상은 그대로 실행하던 조건을 프로젝트의
  `>=3.12,<3.13` 지원 범위와 일치시켰다. shell regression test는 3.11과 3.13을 각각 모사해
  `uv run --project ai python` re-exec 인자 보존과 traceback 부재를 확인한다.

현재 synthetic 4건은 harness 동작 증거일 뿐 운영 품질 승인 자료가 아니다. 60건 사람 검수 gold
set과 RAG 비교 평가는 후속 범위로 남긴다.
