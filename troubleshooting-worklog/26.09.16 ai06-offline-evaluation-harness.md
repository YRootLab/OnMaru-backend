# AI06 offline 평가 harness 구축

- 날짜: 2026-09-16
- 관련 Issue: #111

## 문제 상황

baseline과 모델 proposal의 품질·안전·비용·지연을 같은 fixture로 재실행하고 비교할 실행 계약이
없었다. model·prompt·ranking·dataset 버전도 하나의 결과에 고정되지 않아 수치 변화의 원인을
분리하기 어려웠다.

## 실패 증상

첫 RED 테스트는 `ModuleNotFoundError: onmaru_ai.evals`로 실패했다. 구현 후 경계 테스트에서는
검색 결과가 비어도 nDCG가 `1.0`이 되는 오류와 `--compare` report가 closed schema에서 거절되는
문제가 드러났다.

## 관련 코드 맥락

- `ai/src/onmaru_ai/evals/models.py`: fixture, version pin, threshold, report의 closed Pydantic 계약
- `ai/src/onmaru_ai/evals/runner.py`: recall@5, nDCG@3, evidence support, safety, p95, cost와 gate 계산
- `ai/src/onmaru_ai/evals/cli.py`: JSON 입출력, 이전 report 비교, gate 기반 종료 코드
- `scripts/run-ai-evals`: 저장소 루트에서 실행하는 offline 진입점

runner는 외부 모델을 호출하지 않는다. 실제 실행에서 수집한 결과를 고정 입력 계약으로 정규화한
뒤 순수 계산만 수행하며, canonical input hash로 같은 fixture인지 식별한다.

## 검토한 선택지

1. 평가마다 live provider를 호출: 실제성은 높지만 비용·변동성과 secret 의존 때문에 PR gate에 부적합
2. 점수만 문서에 수기 기록: 재실행과 threshold 실패 종료 코드를 보장하지 못함
3. 고정 gold/actual fixture를 offline 채점: 결정적 CI와 버전 비교에 적합
4. RAG까지 함께 활성화: Issue #119 범위이며 baseline gate와 결합하면 책임이 흐려짐

## 최종 결정

고정 fixture를 strict schema로 검증하고 report schema와 종료 코드를 제공하는 offline harness를
선택했다. RAG activation과 live model 실행은 제외했다.

## 해결 방식과 결과

- 중복 case ID와 잘못된 gold ref를 입력 단계에서 fail-closed 처리했다.
- 빈 retrieval의 nDCG ideal ranking을 실제 결과 길이가 아니라 top 3 gold 기준으로 계산했다.
- allowlist·pin·exclude·outcome·reason/evidence 위반을 case safety violation으로 집계했다.
- 실행 시각을 제외하고 정렬된 JSON과 canonical SHA-256으로 report 재현성을 확보했다.
- 이전 report delta를 동일한 closed report schema 안에 포함했다.
- CI에서 offline gates와 생성 schema drift를 함께 검증한다.

현재 synthetic 4건은 harness 동작 증거일 뿐 운영 품질 승인 자료가 아니다. 60건 사람 검수 gold
set과 RAG 비교 평가는 후속 범위로 남긴다.
