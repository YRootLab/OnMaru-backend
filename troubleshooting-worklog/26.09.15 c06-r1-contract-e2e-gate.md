# C06 R1 contract E2E gate 추가

날짜: 2026-09-15

## 문제 상황

Issue #107은 R1 한옥 API가 FE에 전달 가능한 실행 계약인지 endpoint별로 증명하는 작업이었다. #98 목록, #99 상세, #84 월별 editorial, #108 장소 찜 구현이 각각 끝났지만, 한 Spring context에서 saved state가 list/detail/monthly/save/delete로 이어지는지 막아주는 통합 게이트가 없었다.

## 오류명 또는 실패 증상

- 첫 targeted run 실패: `runtimeResponsesCarryR1FixtureShape`에서 `nextCursor`가 `null`이었다.
- 원인: 통합 테스트 seed가 2개 item만 넣어 `limit=2`에서 fixture처럼 `hasMore=true`가 될 수 없었다.

## 기존 구조나 방식의 한계

개별 endpoint 테스트는 각 기능의 경계를 검증했지만, R1 전체 계약의 drift를 막기에는 부족했다. 예를 들어 saved place PUT 이후 list/detail/monthly가 같은 `savedByMe`를 보는지, 반복 DELETE 후 detail projection이 false로 돌아오는지는 단일 흐름에서 검증되어야 했다.

## 관련 코드 맥락

- `apps/spring-api/src/test/java/com/yrootlab/onmaru/r1/R1HanokContractE2ETests`
  - `savedPlaceStateFlowsAcrossListDetailMonthlyAndDeleteIsIdempotent`
    - anonymous list에서 `savedByMe=false`를 확인한다.
    - member가 PUT을 반복해도 saved state가 true로 유지되는지 확인한다.
    - list/detail/monthly가 같은 saved store를 읽는지 확인한다.
    - DELETE 반복 후 detail `savedByMe=false`를 확인한다.
  - `r1ReadFailuresKeepStablePublicEnvelope`
    - list/detail/monthly read failure가 모두 `SERVICE_UNAVAILABLE` envelope으로 응답하는지 확인한다.
  - `runtimeResponsesCarryR1FixtureShape`
    - R1 fixture의 `schemaVersion`, nullable thumbnail, stable cursor, empty monthly placement 모양을 확인한다.

## 검토한 선택지

1. 기존 endpoint별 테스트만 신뢰한다.
2. OpenAPI YAML 문자열만 검사한다.
3. R1 주요 endpoint를 한 Spring context에서 실제 HTTP 흐름으로 검증한다.

## 판단 기준

- #107의 목적은 문서와 runtime drift를 endpoint별 contract test로 막는 것이다.
- saved state는 여러 endpoint가 같은 저장소를 바라봐야 하므로 E2E 흐름 검증이 필요하다.
- Swagger/OpenAPI 문서 검증은 이미 `verify-contracts` CI가 담당하므로 runtime side를 보강하는 편이 효과적이다.

## 최종 결정

3번을 선택했다. R1 주요 runtime response shape와 savedByMe 흐름을 MockMvc E2E test로 고정했다.

## 해결 방식

- R1 fixture와 같은 list/detail/monthly seed를 테스트 setup에 구성했다.
- 첫 실패에서 `nextCursor=null` 원인을 확인하고 세 번째 list item을 seed해 `limit=2` cursor fixture를 재현했다.
- 기존 `verify-contracts`와 함께 실행되도록 Spring API test suite에 포함했다.

## 결과

- 익명/회원 saved state와 반복 PUT/DELETE fixture 흐름이 통합 테스트로 고정됐다.
- list/detail/monthly source outage envelope이 한 테스트에서 검증된다.
- R1 runtime response shape가 OpenAPI/fixture와 어긋나면 Spring API 테스트에서 실패한다.
