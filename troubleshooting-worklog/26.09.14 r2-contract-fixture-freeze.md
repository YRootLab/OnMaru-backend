# R2 지도·Odii·관광 관측 계약 동결 작업 기록

## 날짜

2026-09-14

## 문제 상황

Issue #133은 R2 public query와 연결 resource DTO를 runtime 구현 전에 기계 판독 가능한 OpenAPI와 fixture로 고정하는 작업이었다. 기존에는 VisitReview OpenAPI와 R1 계약은 있었지만, 지도 장소, 행정구역 resolve/count, Odii story, 관광 관측/heatmap 계약이 prose와 개별 문서에 흩어져 있었다.

## 오류명 또는 실패 증상

- RED 실패: `AssertionError: missing OpenAPI contract: .../docs/contracts/openapi/r2-map-audio-insights.openapi.yaml`
- 환경 경고: Python 3.9 로컬 실행에서 `urllib3 v2 only supports OpenSSL 1.1.1+` 경고가 R1/R2 validator 출력 앞에 나타났다.
- PR 생성 후 발견한 표시 문제: 최초 PR body 일부 테스트 목록에 literal `\n`이 섞여 가독성이 떨어졌다.

## 기존 구조나 방식의 한계

- `scripts/test/validate-r1-contract.py`는 R1 전용 OpenAPI와 `docs/contracts/fixtures/r1`만 검증했다.
- CI는 `scripts/verify-contracts`를 실행했지만, 그 안에서는 R2 계약 검증이 없었다.
- CI dependency 파일명이 `requirements-r1-contract.txt`라 R2 validator가 같은 의존성을 공유하게 된 뒤에는 이름이 실제 역할과 맞지 않았다.
- `docs/contracts/README.md`에도 R2 OpenAPI와 fixture bundle의 위치가 안내되어 있지 않았다.

## 관련 코드 맥락

- `scripts/test/validate-r2-contract.py`
  - 담당 로직: R2 OpenAPI 문서와 fixture JSON을 읽어 OpenAPI 3.1 표준 검증, required path/schema 존재 확인, fixture 응답 schema 매칭, JSON Schema body 검증, provider-only key 누출 방지를 수행한다.
  - 입력: `docs/contracts/openapi/r2-map-audio-insights.openapi.yaml`, `docs/contracts/fixtures/r2/*.json`
  - 출력: 검증 성공 메시지 또는 `AssertionError`
  - 핵심 분기: fixture request path를 `/api/v1` prefix 제거 후 OpenAPI path template과 비교하고, response status/schema가 operation response와 일치하지 않으면 실패시킨다.

- `docs/contracts/openapi/r2-map-audio-insights.openapi.yaml`
  - 담당 계약: `/map/places`, `/regions/resolve`, `/visit-review-regions`, `/odii/stories`, `/odii/stories/{storyId}`, `/insights/observations`, `/insights/heatmap`의 public read schema를 고정한다.
  - 중요한 결정: `coverageStatus`를 map/Odii/insights 응답에 포함하고, Odii 응답에는 `language`, `languageStatus`를 포함해 결측·fallback 상태를 숨기지 않는다.

- `docs/contracts/fixtures/r2/*.json`
  - 담당 fixture: 정상, 결측, 언어 fallback, 404, 400, 503 시나리오 13개를 OpenAPI 응답 schema에 맞춰 예시화한다.
  - 문제와의 연결: Issue #133 acceptance의 “지도·Odii·관측 정상/결측/error fixture 검증”을 실제 validator가 읽는 파일로 고정한다.

- `scripts/verify-contracts`
  - 담당 로직: R1/R2 계약 검증 후 DBML/Azimutt/Postgres generated artifact drift를 확인한다.
  - 변경 이유: CI가 이미 이 스크립트를 호출하므로, R2 validator를 여기에 연결하면 별도 workflow 확장 없이 CI coverage에 들어간다.

- `.github/workflows/ci.yml`
  - 담당 로직: PR/push에서 repository hygiene, Spring test, Node test, planning/Odii fixture 검증, contract/generated artifact 검증, FastAPI test를 실행한다.
  - 변경 이유: R1 전용 dependency path와 step 이름을 `requirements-contract.txt`, R1/R2 contract validation으로 정리해 CI가 실제 검증 범위를 드러내게 했다.

## 검토한 선택지

1. 기존 `visit-reviews.openapi.json`에 R2 map/Odii/insights path를 추가한다.
2. R1처럼 R2 전용 OpenAPI bundle과 fixture 디렉터리를 만든다.
3. prose 문서만 보강하고 validator는 나중에 추가한다.
4. CI workflow에 R2 validator 직접 step을 추가한다.
5. 기존 `scripts/verify-contracts`에 R2 validator를 연결한다.

## 판단 기준

- Issue #133의 expected touch point가 `docs/contracts/openapi/r2-map-audio-insights.openapi.yaml`, `docs/contracts/fixtures/r2`로 명시되어 있는가
- runtime endpoint 구현 없이 계약만 고정하는가
- R1/VisitReview와 충돌하지 않고 R2 전용 bundle로 병렬 작업이 가능한가
- CI가 OpenAPI lint와 fixture schema test를 자동으로 실행하는가
- provider 원본 ID나 service key가 public DTO/fixture에 노출되지 않는가

## 최종 결정

R2 전용 OpenAPI와 fixture bundle을 만들고, 새 R2 validator를 `scripts/verify-contracts`에 연결하는 방향을 선택했다.

## 해결 방식

- TDD 흐름으로 먼저 `scripts/test/validate-r2-contract.py`를 추가했다.
  - 첫 실행은 R2 OpenAPI 파일이 없어 `missing OpenAPI contract`로 실패했다.
  - 이 실패가 Issue #133의 실제 빈 계약 상태를 정확히 가리켜 RED로 인정했다.
- `docs/contracts/openapi/r2-map-audio-insights.openapi.yaml`을 추가했다.
  - R2 public read path 7개와 `MapPlacePage`, `RegionResolution`, `RegionCountPage`, `OdiiStoryPage`, `OdiiStoryDetail`, `ObservationPage`, `HeatmapResponse`, `Error` schema를 정의했다.
  - `coverageStatus`, `language`, `languageStatus` 누락을 validator가 실패시키도록 했다.
- `docs/contracts/fixtures/r2`에 13개 fixture를 추가했다.
  - 정상: map places, region resolve/count, Odii list/detail, observations, heatmap
  - 결측: map empty, insights missing coverage, Odii language fallback
  - error: invalid request, Odii not found, service unavailable
- `scripts/verify-contracts`에 R2 validator 실행을 추가했다.
  - CI는 이미 이 스크립트를 호출하므로 R2 계약 검증이 CI에 자연스럽게 포함된다.
- `requirements-r1-contract.txt`를 `requirements-contract.txt`로 rename하고 CI cache/install path와 step 이름을 R1/R2 기준으로 바꿨다.
- Python SSL 환경 경고는 validator import 전에 warning filter를 적용해 로컬 출력이 계약 검증 결과에 집중되도록 했다.
- PR 생성 후 body에 섞인 literal `\n`은 `gh pr edit --body-file -`로 다시 저장해 정리했다.
