# M09 R2 통합 계약 E2E 게이트

## 문제

R2의 지도, 지역, 방문 후기, Odii, 관광 인사이트, 저장 리소스는 각 기능 테스트와 OpenAPI fixture 검증은 있었지만 사용자 흐름을 한 번에 통과시키는 출시 gate가 없었다. 특히 moderation으로 숨긴 후기 본문과 집계가 다시 공개되거나, 세 OpenAPI 문서 사이의 인증·cursor·오류 envelope가 runtime serializer와 달라져도 하나의 실패 신호로 잡히지 않았다.

## 진행

`testing/e2e/r2/contract-gate.json`에 R2 map/audio/insights, visit-review, identity-saved 계약과 fixture group, 필수 runtime scenario를 선언했다. `scripts/test/validate-r2-e2e-gate.py`를 `scripts/verify-contracts`에 연결해 계약·fixture·runtime suite·release evidence 중 하나가 빠지면 CI에서 실패하게 했다.

Spring `R2ContractE2ETests`는 고정 provider projection으로 region/map/insights guest 흐름, 후기 작성·좋아요·신고와 Odii/place 저장, signed cursor, moderation 숨김, source outage를 실제 controller에 연쇄 요청한다. R2 fixture body와 runtime body를 재귀적으로 key/type 비교하고 provider 전용 key를 전 응답 트리에서 거절한다. 관측 결측은 빈 배열과 `MISSING`으로 유지하고 오래된 관측일과 현재 `generatedAt`을 모두 노출해 0 합성이나 freshness 은폐를 막는다.

추가 보강으로 `insights-observations-stale` fixture와 runtime assertion을 추가했다. `InsightsQueryService`는 집계 우선순위를 `MISSING > STALE > PARTIAL > COMPLETE`로 두어 오래된 관측이 `COMPLETE`로 마스킹되지 않게 했다. PostgreSQL-backed E2E 확장은 이번 이슈의 통합 gate 범위와 기존 R1/R2 controller-fixture 패턴을 고려해 새로 키우지 않고, provider fixture 기반 Spring runtime gate에 집중했다.

## 해결

초기 RED에서 REGION query에 문맥 없는 cursor를 넣으면 query validation이 먼저 실행돼 `VALIDATION_ERROR`가 반환됨을 확인했다. Canonical malformed cursor 계약을 검증하도록 `scope=ALL`로 분리했고, fixture의 nullable `parentRegionCode`처럼 같은 schema 안에서 허용되는 null은 serializer key 존재를 유지한 채 type 비교에서 허용했다.

최종 gate는 정상·비회원·비공개·source outage·관측 결측/오래됨, auth/CSRF, signed cursor, 공통 error envelope, hidden text/count 비재노출을 함께 검증한다. 재현 명령과 scenario별 판정 근거는 `docs/operations/release-evidence/r2/README.md`에 기록했다.
