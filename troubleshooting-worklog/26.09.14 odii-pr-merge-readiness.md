# Odii PR 머지 전 충돌 해결과 검증 보강 기록

## 날짜

2026-09-14

## 문제 상황

PR #145는 Issue #61 Odii qualification 작업 자체는 끝났지만, 머지 직전 확인에서 GitHub가 `CONFLICTING / DIRTY` 상태를 보고했다. CI는 통과했지만 `develop`에 PR #142가 먼저 merge되면서 CI workflow, changelog, handoff가 충돌했다.

## 오류명 또는 실패 증상

- GitHub PR 상태: `mergeable=CONFLICTING`, `mergeStateStatus=DIRTY`
- 로컬 병합 실패:
  - `.github/workflows/ci.yml`
  - `CHANGELOG.md`
  - `handoff.md`
- 추가 테스트 보강 중 실패:
  - `rejects manifests missing required scenarios` 테스트가 의도한 missing scenario 오류가 아니라 `fixture hash mismatch for other.json`를 먼저 만났다.

## 기존 구조나 방식의 한계

기존 PR #145는 Odii fixture 검증을 추가했지만, 같은 시점에 #142가 planning input snapshot 검증을 CI에 추가했다. 두 PR 모두 `.github/workflows/ci.yml`의 같은 영역을 수정했기 때문에 단순 한쪽 선택으로 해결하면 한쪽 검증이 사라질 수 있었다.

또한 Odii validator는 실제로 hash mismatch와 required scenario 누락을 처리하고 있었지만, unit test는 secret redaction 중심이었다. CI에서 `node --test scripts/test/*.test.mjs`를 돌리게 된 만큼 validator의 핵심 실패 분기를 더 직접적으로 고정하는 편이 안전했다.

## 관련 코드 맥락

- `.github/workflows/ci.yml`
  - 담당 로직: PR과 `develop/main` push에서 repository hygiene과 Node 기반 검증을 실행한다.
  - 충돌 원인: #142는 `node --test scripts/test/*.test.mjs`와 `node scripts/verify-planning-inputs.mjs`를 repository hygiene step 안에 넣었고, #145는 Node test와 Odii manifest validation을 별도 step으로 추가했다.
  - 해결: Node test를 공통 step으로 유지하고, `Planning input snapshot validation`, `Odii fixture manifest validation`을 각각 별도 step으로 분리했다. 이렇게 해야 #131 snapshot 검증과 #61 Odii fixture 검증이 둘 다 CI에서 살아남는다.

- `scripts/test/odii-fixture-validation.test.mjs`
  - 담당 로직: `validateOdiiFixtureSet()`이 secret leakage, URL redaction, fixture hash, required scenario를 제대로 실패시키는지 검증한다.
  - 입력: 테스트마다 임시 디렉터리에 manifest와 fixture JSON을 만든다.
  - 출력: Node TAP test 결과.
  - 추가한 테스트:
    - `rejects fixture hash mismatches`: fixture 파일 내용과 manifest의 SHA-256이 다르면 `fixture hash mismatch`로 실패해야 한다.
    - `rejects manifests missing required scenarios`: manifest의 `requiredScenarios`에 있는 scenario가 `captures`에 없으면 `missing required Odii scenarios`로 실패해야 한다.
  - 실패 원인: 처음에 `other.json` 내용을 `"{}\n"`으로 저장했지만 hash는 `"{}"`의 SHA-256을 넣었다. 그래서 required scenario 검사까지 도달하지 못하고 hash mismatch가 먼저 발생했다.
  - 해결: `"{}\n"`의 실제 SHA-256인 `ca3d163...`으로 고쳐 intended branch까지 도달하게 했다.

- `scripts/lib/odii-fixture-validation.mjs`
  - 담당 로직: manifest JSON을 읽고 required scenario, capture 필드, fixture hash, secret-like 문자열을 검사한다.
  - 이번에는 production code를 바꾸지 않았다. 이미 있는 분기를 regression test로 고정했다.

## 검토한 선택지

1. PR #145를 바로 merge한다.
2. GitHub UI에서 conflict를 수동 해결한다.
3. 로컬에서 `origin/develop`을 merge하고, 양쪽 CI 검증을 모두 보존한다.
4. validator 테스트는 현 상태로 두고 CI 통과만 확인한다.

## 판단 기준

- 공유 저장소 정책상 conflict 상태 PR은 merge하면 안 된다.
- #142와 #145의 검증은 서로 대체 관계가 아니라 둘 다 필요한 gate다.
- #61 완료 증거는 `redacted capture manifest validation`이므로 Odii 검증은 CI에 남아야 한다.
- 테스트 보강은 production code 변경 없이 안전장치의 의도를 더 명확히 해야 한다.

## 최종 결정

`origin/develop`을 PR 브랜치에 merge하고, CI workflow는 planning input 검증과 Odii fixture 검증을 모두 별도 step으로 보존했다. 이후 Odii validator의 hash mismatch와 required scenario 누락 테스트를 추가했다.

## 해결 방식

- `git merge origin/develop`으로 충돌을 재현했다.
- `.github/workflows/ci.yml`은 다음 순서로 정리했다.
  - Repository hygiene
  - Node script tests
  - Planning input snapshot validation
  - Odii fixture manifest validation
- `CHANGELOG.md`는 #61 Odii fixture 항목과 #131 planning snapshot 항목을 둘 다 유지했다.
- `handoff.md`는 #61 현재 작업 기록을 위에 두고, #131은 “직전 develop merge 포함 작업”으로 보존했다.
- Odii validator unit test를 3개에서 5개로 늘렸다.
- 테스트 작성 중 hash literal 오류를 발견했고, fixture 파일 내용의 newline까지 포함한 SHA-256으로 바로잡았다.

## 결과

- PR #145 conflict는 해소되어 `mergeable=MERGEABLE` 상태가 되었다.
- 새 로컬 검증:
  - `node --test scripts/test/*.test.mjs`: 16개 테스트 통과
  - `node scripts/verify-planning-inputs.mjs`
  - `node scripts/validate-odii-fixtures.mjs`
  - `git diff --check`
- 추가로 필요한 CI:
  - 이번 PR 범위에서는 더 없다. Node test, planning input snapshot validation, Odii fixture manifest validation이 CI에 들어가 있다.
  - Gradle/Python lint/typecheck/test를 CI에 본격 편입하는 작업은 별도 Issue #69의 범위로 남긴다.
- 남은 merge 조건:
  - GitHub Actions `verify` 재통과 확인
  - 공유 저장소 정책상 review approval 1개 확보
  - merge 후 #61 자동 close가 안 되면 수동 close 확인
