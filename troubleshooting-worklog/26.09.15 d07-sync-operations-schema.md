# D07 sync operations schema worklog

## 날짜

2026-09-15

## 문제 상황

수집 scheduler와 worker가 실패 복구, lease fencing, checkpoint 재개, quarantine, outbox 재시도를 수행하려면 실행 상태를 프로세스 메모리가 아니라 PostgreSQL에 남겨야 했다. Issue #80은 이 저장소의 operations schema를 Flyway baseline migration으로 추가하는 작업이다.

## 오류명 또는 실패 증상

TDD 첫 실행에서 `OperationsMigrationTests`가 실패했다.

- `operations_sync_*` 테이블이 없어 run/checkpoint insert가 `PSQLException`으로 실패했다.
- `operations_outbox_events_undelivered_idx`가 없어 outbox 재시도 인덱스 검증이 실패했다.
- 최초 GREEN 전환 뒤에는 PostgreSQL `pg_indexes.indexdef` 포맷 차이로 partial index 문자열 검증이 0건을 반환했다.

## 기존 구조나 방식의 한계

문서에는 `docs/database/modules/operations.dbml`, `docs/spring/catalog-ingestion.md`, `docs/operations/runtime-and-reliability.md`에 schedules, runs, leases, checkpoints, watermarks, quarantine 규칙이 있었지만 실행 가능한 DDL은 없었다. scheduler 구현 전에 DB가 `(dataset, scheduled_for, attempt)` 중복과 revision FK, lease generation predicate를 받아줄 수 있는지 먼저 증명해야 했다.

## 관련 코드 맥락

- `apps/spring-api/src/main/resources/db/migration/baseline/V004__d07_sync_operations_schema.sql`
  - `operations_sync_run_status` enum과 sync schedules/runs/checkpoints/leases/watermarks/quarantine/outbox 테이블을 만든다.
  - `operations_sync_runs_dataset_scheduled_for_attempt_uq`로 같은 dataset 일정의 같은 attempt 중복 생성을 막는다.
  - `operations_sync_watermarks.revision_id`는 `catalog_dataset_revisions.id` FK를 사용해 성공 publish 이후 watermark가 실제 revision을 가리키게 한다.
  - `operations_outbox_events_undelivered_idx`는 `delivered_at IS NULL` partial index로 아직 전달되지 않은 이벤트 재시도 조회를 빠르게 한다.
- `apps/spring-api/src/test/java/com/yrootlab/onmaru/testing/postgres/OperationsMigrationTests.java`
  - Testcontainers PostgreSQL/PostGIS에 Flyway 전체 migration을 적용한다.
  - run attempt uniqueness, watermark revision FK, stale lease owner의 fenced write 0건, checkpoint와 staged revision의 commit/rollback atomicity를 SQL 레벨로 검증한다.
- `db/migration/registry/migrations.json`
  - V004 checksum과 sha256을 등록해 병합된 migration drift를 CI에서 탐지한다.

## 검토한 선택지

1. application service 구현 시점에 테이블을 함께 추가한다.
2. DBML만 업데이트하고 executable DDL은 뒤로 미룬다.
3. #80에서 Flyway DDL과 DB contract test만 먼저 추가한다.
4. lease 차단을 trigger/function으로 강제한다.

## 판단 기준

- #88 scheduler, #89 quarantine, #95 publish가 같은 operations 저장소에 의존한다.
- 지금 저장소의 migration 정책은 DBML 의도보다 Flyway SQL을 실행 가능한 source로 삼는다.
- lease 만료 여부는 DB clock과 `owner_token/generation/lease_until` predicate로 worker transaction에서 검증해야 하므로, schema 단계에서는 predicate가 안전하게 동작하는 최소 구조와 테스트를 먼저 고정하는 편이 맞다.

## 최종 결정

V004 Flyway migration으로 operations 저장소를 먼저 만들고, Testcontainers 기반 DB contract test로 sync run/lease/checkpoint/outbox 불변식을 고정했다.

## 해결 방식

1. RED: `OperationsMigrationTests`를 추가해 아직 없는 operations schema 때문에 실패하는 상태를 확인했다.
2. GREEN: `V004__d07_sync_operations_schema.sql`을 추가해 schedules, runs, checkpoints, leases, watermarks, quarantine, outbox 테이블과 핵심 제약을 만들었다.
3. registry: `migrations.json`에 V004 stable checksum과 SHA-256을 등록했다.
4. docs: `docs/database/migration-and-concurrency.md`에 D07 migration 소유권을 추가했다.
5. 테스트 보정: partial index 검증은 `pg_indexes.indexdef` 문자열 대신 `pg_index.indpred`를 `pg_get_expr`로 읽도록 바꿔 PostgreSQL 포맷 차이에 덜 민감하게 했다.

## 결과

- `./gradlew :apps:spring-api:test --tests '*OperationsMigrationTests' --no-daemon` 통과.
- `node --test scripts/test/migration-policy.test.mjs` 통과.
- 남은 과제는 #88 scheduler 구현에서 실제 worker transaction이 lease row를 잠그고 같은 predicate로 checkpoint/stage write를 수행하도록 application code를 연결하는 것이다.
