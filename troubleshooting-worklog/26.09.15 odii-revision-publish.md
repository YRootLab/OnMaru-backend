# Odii revision 수집과 원자 게시 구현

## 작업 배경

- GitHub Issue: #96 `[A02] Odii 수집·revision·tombstone publish 구현`
- 선행 Issue #61, #79, #80, #88, #95가 모두 Closed이고 중복 열린 PR이 없는 상태에서 시작했다.
- 목표는 검증된 Odii 응답을 언어별 identity로 보존하고, spot/story partial publish 없이 새 revision을 게시하며, 실패 시 이전 LKG와 watermark를 유지하는 것이다.
- 공개 story API와 canonical place 검수 연결은 각각 후속 Issue #103, #104 범위다.

## 구현 경계

`adapters:tourism-api`에는 Odii provider envelope parser, bounded HTTP client, URI builder, provider item 변환만 둔다. HTTP client는 attempt timeout과 page budget을 분리하고 429/5xx/transport 오류만 제한적으로 재시도한다. `Retry-After`가 page budget을 넘으면 즉시 실패하며 service key가 포함된 URI는 redaction할 수 있다.

신규 `modules:audio`에는 `provider + tid + tlid + langCode`, `provider + stid + stlid + langCode` identity, 공식 대본 provenance, source validation, revision stage와 publication orchestration을 둔다. 빈 provider script는 `MISSING`으로 기록하며 estimated transcript를 만들지 않는다.

`InMemoryAudioRevisionStore`는 현재 repository의 reference adapter 패턴을 따른다. stage는 active snapshot 복사본에서만 변경하고, 공통 `DatasetPublicationService`가 lease와 expected base revision을 확인한 뒤 active revision, watermark, 누락 관측 카운터를 한 publication 경계에서 교체한다. 누락 identity는 성공 게시 기준 두 번 연속 관측되지 않았을 때만 `DELETED` tombstone이 된다.

## TDD 기록

1. `OdiiEnvelopeParserTests`를 먼저 추가했다. 초기 RED는 `OdiiEnvelopeParser`, `OdiiPage`, `OdiiParseException` 부재로 컴파일 실패했다. fixture가 빈 결과에서 `numOfRows=0`을 반환하는 실제 계약을 발견해, `totalCount=0`과 빈 item일 때만 0을 허용했다.
2. `OdiiSourceMapperTests`를 먼저 추가했다. 초기 RED는 신규 audio module과 mapper/domain type 부재로 실패했다. GREEN에서 ko/en language identity 분리, 빈 script/audio, duration/coordinate/timestamp, SHA-256 content hash를 검증했다.
3. `OdiiHttpClientTests`를 먼저 추가했다. 초기 RED는 HTTP client/config/URI type 부재로 실패했다. 503 retry, provider auth non-retry, URI encoding과 secret redaction을 구현했다.
4. `OdiiRevisionSyncServiceTests`를 먼저 추가했다. 초기 RED는 revision orchestration/store type 부재로 실패했다. 다국어 전체 게시, 마지막 페이지 실패 LKG, 두 번 연속 누락 tombstone, stale lease/base 거부를 구현했다.
5. 자체 리뷰에서 rejected publication도 누락 카운터를 올리는 결함을 발견했다. `rejectedPublicationDoesNotAdvanceMissingObservationCounters`가 실제 tombstone 조기 생성으로 RED가 되는 것을 확인한 뒤, 누락 카운터를 stage-local로 계산하고 publish 성공 시에만 commit하도록 수정했다.
6. `Retry-After`가 page budget보다 긴 429 응답을 즉시 반복 호출하는 결함도 회귀 테스트로 재현했다. budget 안에서 대기할 수 있을 때만 retry하도록 수정했다.
7. `OdiiClientConfigurationTests`는 Spring bean 부재로 RED를 확인한 후 `onmaru.odii.client.*` 기본값과 override binding을 구현했다.
8. review에서 provider 200 error envelope의 rate-limit 분류, percent-encoded service key 이중 인코딩, `OdiiPageSource` 실행 adapter 누락을 발견했다. 각각 failing test를 추가해 retryability 보존, raw/encoded key 호환, 실제 HTTP-to-audio source 연결을 보강했다.
9. `AudioMigrationTests.publishesSpotStoryPointerAndWatermarkInOneDatabaseTransaction`를 추가해 PostgreSQL rollback에서는 이전 active revision/watermark가 유지되고 commit에서는 staged spot/story revision, active pointer, watermark가 함께 전환되는지 검증했다.

## 검증

구현 전 기준선에서 다음 명령이 모두 통과했다.

```bash
./gradlew test --no-daemon
cd ai && uv run ruff check . && uv run mypy && uv run pytest
node --test scripts/test/*.test.mjs
bash scripts/verify-contracts
git diff --check
```

구현 과정의 focused GREEN은 다음 명령으로 확인했다.

```bash
./gradlew :adapters:tourism-api:test --tests '*Odii*Tests' :modules:audio:test --no-daemon
./gradlew :apps:spring-api:test --tests '*OdiiClientConfigurationTests' --no-daemon
```

최종 전체 검증도 다음 명령으로 통과했다.

```bash
./gradlew test --no-daemon
cd ai && uv run ruff check . && uv run mypy && uv run pytest
node --test scripts/test/*.test.mjs
node scripts/verify-planning-inputs.mjs
node scripts/validate-odii-fixtures.mjs
bash scripts/verify-contracts
git diff --check
```

Gradle은 41 tasks를 성공했고, FastAPI는 21 tests, Node는 35 tests가 통과했다. Odii fixture 8개와 R1/R2/identity 계약 및 generated Azimutt/Postgres artifact도 검증됐다. macOS system Python의 LibreSSL warning은 있었지만 contract validation은 exit code 0이었다.

## 남은 경계

- 실제 전국 Odii 수집 partition/query 조합은 qualification snapshot에 완전 열거 endpoint가 고정되지 않아 임의 keyword로 구현하지 않았다. `OdiiPageSource` port가 검증된 partition 전략을 주입받도록 유지한다.
- PostgreSQL migration의 audio identity/version/tombstone FK와 제약, transaction rollback/commit publication 계약은 `AudioMigrationTests`가 검증한다. production JDBC adapter는 persistence wiring이 구체화되는 후속 단계에서 `AudioRevisionStore` port 구현으로 추가할 수 있다.
- 공개 story 조회, URL proxy 정책, canonical place 승인 projection은 #103/#104에서 구현한다.
