# Git Flow 운영 문서와 브랜치 이슈 파서 작업 로그

날짜: 2026-09-15

## 문제 상황

사용자가 Git Flow release automation, Git Flow strategy, project initial harness 관점으로 `AGENTS.md`와 운영 흐름을 개선하고 브랜치 파서를 커밋·푸시·머지하길 요청했다. 기존 저장소는 `develop`과 `main` Git Flow 정책, Release Please, post-merge Issue reconcile을 이미 갖고 있었지만, 작업 브랜치 이름에서 관련 Issue 번호를 기계적으로 검증하는 장치가 없었다.

## 오류명 또는 실패 증상

TDD RED로 `scripts/test/branch-issue-parser.test.mjs`를 먼저 추가했을 때 `ERR_MODULE_NOT_FOUND`가 발생했다. `scripts/lib/branch-issue-parser.mjs`가 없어서 `feature/192-*` 같은 브랜치명에서 Issue 번호를 읽는 계약이 구현되지 않았다는 신호였다.

## 기존 구조나 방식의 한계

PR 본문과 issue reconcile은 closing keyword를 잘 처리했지만, PR을 만들기 전에 branch와 Issue 연결이 맞는지 확인하는 규칙은 문서와 사람의 주의에 의존했다. 이 때문에 `feature/foo`처럼 번호 없는 브랜치도 CI에 올라갈 수 있었다.

## 관련 코드 맥락

- `scripts/lib/branch-issue-parser.mjs`: `feature/<number>-...`, `fix/<number>-...`, `docs/<number>-...`, `hotfix/<number>-...` 패턴에서 Issue 번호를 추출한다. 장기 브랜치인 `develop`, `main`, `release/*`는 Issue 번호를 요구하지 않는다.
- `scripts/print-branch-issue.mjs`: 현재 branch 또는 인자로 받은 branch를 파싱해 Issue 번호를 출력한다. 번호가 필요한 work branch에 번호가 없으면 오류로 실패한다.
- `scripts/test/branch-issue-parser.test.mjs`: 정상 work branch, 장기 branch, malformed branch, 오류 메시지 계약을 검증한다.
- `.github/workflows/ci.yml`: pull_request에서 `github.head_ref`를 파서에 넘겨 브랜치명 규칙을 CI gate로 만든다.
- `AGENTS.md`: Git Flow, Release Please, local capture, PR 전/merge 전 cleanup, branch parser 사용 규칙을 한 문서에 모았다.

## 검토한 선택지

1. 문서만 보강하고 파서는 만들지 않는다.
2. PR 제목이나 본문에서만 Issue 번호를 검사한다.
3. branch parser를 repository-local Node script로 만들고 CI pull_request에서 실행한다.
4. GitHub branch protection만으로 처리한다.

## 판단 기준

현재 저장소의 Node script tests가 이미 CI에 포함되어 있고, private repository의 branch protection은 API로 확인되지 않는다고 AGENTS에 기록되어 있다. 따라서 문서 규칙만 두는 것보다 repository-local parser와 CI gate를 함께 두는 편이 재현 가능하고, workflow 권한도 `contents: read`로 유지할 수 있다.

## 최종 결정

브랜치명에서 Issue 번호를 파싱하는 작은 Node library와 CLI를 추가하고, AGENTS에 이 규칙을 공식 운영 흐름으로 기록한다.

## 해결 방식

- `scripts/test/branch-issue-parser.test.mjs`로 RED를 먼저 확인했다.
- `scripts/lib/branch-issue-parser.mjs`에 `parseIssueNumberFromBranch`, `shouldRequireIssueBranch`, `requireIssueNumberFromBranch`를 구현했다.
- `scripts/print-branch-issue.mjs`를 추가해 agent와 CI가 같은 parser를 사용하게 했다.
- `.github/workflows/ci.yml` pull_request에 branch parser step을 추가했다.
- `AGENTS.md`에 Issue-first, branch naming, Release Please release flow, project harness lifecycle을 보강했다.
- `handoff.md`와 `CHANGELOG.md`에 #192 작업 맥락과 변경 요약을 기록했다.

## 결과

- `node scripts/print-branch-issue.mjs`: 현재 branch에서 `192` 출력.
- `node --test scripts/test/*.test.mjs`: 35개 테스트 통과.
- `bash scripts/verify-contracts`: 통과. 로컬 Python LibreSSL 기반 `urllib3` 경고는 있었지만 exit code 0이었다.
- GitHub Project 조회 결과: `YRootLab` owner에 project 0개로 확인됐다.
