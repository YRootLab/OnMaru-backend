# R1 계약 검증 강화 작업 로그

## 날짜

2026-09-14

## 문제 상황

Issue #62의 R1 한옥·장소·찜 OpenAPI와 fixture를 동결하면서, 단순 파일 존재 확인이나 수동 리뷰만으로는 계약 drift를 막기 어렵다는 문제가 있었다. 특히 FastAPI 테스트는 AI 서비스 디렉터리에서 실행되어야 하고, R1 fixture는 OpenAPI 표준 구조와 실제 response schema에 맞는지 자동 검증되어야 했다.

## 오류명 또는 실패 증상

- `ModuleNotFoundError: No module named 'yaml'` 가능성: CI가 PyYAML을 명시 설치하지 않으면 clean runner에서 contract validator가 실패할 수 있었다.
- `TypeError: zip() takes no keyword arguments`: 로컬 `python3`가 3.9라 `zip(strict=True)`를 지원하지 않았다.
- `response ... has no JSON schema ref`: fixture endpoint/status schema cross-check 중 `#/components/responses/Error` 간접 참조를 처음에는 따라가지 못했다.
- 로컬 `python3` 실행 시 `NotOpenSSLWarning`: macOS 기본 Python 3.9 LibreSSL 조합에서 urllib3 경고가 발생했다. CI는 Python 3.12로 고정했다.

## 기존 구조나 방식의 한계

초기 validator는 필수 path/schema, fixture 이름, provider key 비노출, 공유 `placeId` 정도를 직접 검사했다. 이 방식은 빠르지만 OpenAPI 문서 자체가 표준을 만족하는지, fixture body가 OpenAPI component schema 전체를 만족하는지, fixture의 `request.method/path/status`가 실제 operation response schema와 연결되는지까지 보장하지 못했다.

## 관련 코드 맥락

- `scripts/test/validate-r1-contract.py`
  - 담당 로직: `docs/contracts/openapi/r1.openapi.yaml`와 `docs/contracts/fixtures/r1/*.json`을 읽어 R1 계약 동결 조건을 검증한다.
  - 입력: OpenAPI YAML, R1 fixture JSON 13개.
  - 출력: 검증 성공 메시지 또는 `AssertionError`.
  - 핵심 분기:
    - `validate_openapi_standard()`는 `openapi-spec-validator`로 OpenAPI 3.1 구조를 검증한다.
    - `validate_fixture_body_json_schema()`는 OpenAPI component schema의 `$ref`를 JSON Schema `$defs`로 변환한 뒤 `Draft202012Validator`로 fixture `response.body`를 검증한다.
    - `operation_response_schema_name()`은 fixture의 `/api/v1/...` path를 OpenAPI path로 매칭하고, method/status의 response schema가 fixture의 `response.schema`와 같은지 확인한다.
    - `assert_no_forbidden_public_keys()`는 fixture 전체와 OpenAPI 문서에서 `contentId`, `pageNo`, `key`, `serviceKey` 노출을 막는다.
- `.github/workflows/ci.yml`
  - 담당 로직: PR/push CI에서 repository hygiene, Spring test, contract/generated artifact validation, FastAPI service tests를 실행한다.
  - 변경 이유: Java는 JDK 21/Gradle cache로 `./gradlew test --no-daemon`을 돌리고, contract validation 의존성은 `scripts/test/requirements-r1-contract.txt`로 설치한다. FastAPI 테스트는 `working-directory: ai`에서 `uv run pytest`로 실행해 Spring 테스트와 섞지 않는다.
- `scripts/verify-contracts`
  - 담당 로직: R1 OpenAPI/fixture 검증, DBML compile, Azimutt/Postgres 생성물 stale 여부를 한 번에 확인한다.
  - 동작 방식: `validate-r1-contract.py`를 실행한 뒤 `npx -y -p @dbml/cli dbml2sql`로 DBML이 PostgreSQL SQL로 컴파일되는지 확인한다. 이어 `AZIMUTT_OUTPUT_DIR`로 임시 디렉터리에 생성물을 만들고 현재 `docs/database/azimutt/*.sql`과 `diff`로 비교한다.
- `scripts/azimutt-export.mjs`
  - 담당 로직: `docs/database/schema.dbml`을 PostgreSQL SQL로 변환하고 Azimutt 호환 SQL 2종과 원본 PostgreSQL SQL 생성물을 쓴다.
  - 변경 이유: 기존에는 고정 경로에만 생성해 로컬 검증 중 working tree를 직접 변경했다. `AZIMUTT_OUTPUT_DIR`를 지원해 CI/로컬 검증에서는 임시 디렉터리에 생성하고 stale 여부만 비교할 수 있게 했다.
- `docs/contracts/openapi/r1.openapi.yaml`
  - 담당 로직: endpoint 구현 없이 FE/Spring이 공유할 R1 public REST contract를 정의한다.
  - 주의점: public schema에는 provider 원본 식별자인 `contentId`, `pageNo`, `key`, `serviceKey`를 넣지 않는다.
- `docs/contracts/fixtures/r1/*.json`
  - 담당 로직: 정상, 빈 목록, cursor, auth, 404, unavailable/service unavailable 등 실행 가능한 예제 역할을 한다.
  - 핵심 규칙: 한옥 상세, 지도 카드, Odii 연결 카드가 같은 canonical `placeId`를 사용한다.

## 검토한 선택지

1. 기존 custom validator만 유지한다.
2. OpenAPI 표준 validator만 추가하고 fixture body 검증은 유지하지 않는다.
3. `jsonschema`만 추가하고 OpenAPI 표준 검증은 생략한다.
4. OpenAPI 표준 검증, JSON Schema fixture body 검증, endpoint/status/schema cross-check를 모두 적용한다.
5. DBML compile과 generated artifact diff를 `scripts/verify-contracts`로 묶는다.
6. FastAPI 테스트를 루트 CI에서 임의 경로로 실행하지 않고 `ai` 서비스 컨텍스트로 분리한다.

## 판단 기준

- CI clean runner에서 재현 가능해야 한다.
- #62 범위인 contract/fixture만 검증하고 endpoint 구현은 만들지 않아야 한다.
- fixture가 실제 OpenAPI operation과 어긋나면 실패해야 한다.
- Spring API 테스트와 FastAPI 테스트의 실행 컨텍스트를 분리해야 한다.

## 최종 결정

OpenAPI 표준 검증, JSON Schema fixture body 검증, endpoint/status/schema cross-check, DBML compile, generated artifact diff를 모두 적용한다. Spring 테스트는 JDK 21/Gradle cache로, FastAPI 테스트는 `ai` 디렉터리 기준으로 실행한다.

## 해결 방식

- `scripts/test/requirements-r1-contract.txt`를 추가해 `PyYAML==6.0.2`, `jsonschema==4.25.1`, `openapi-spec-validator==0.7.2`를 고정했다.
- `.github/workflows/ci.yml`에서 `actions/setup-java@v4`로 JDK 21과 Gradle cache를 설정하고 `./gradlew test --no-daemon`을 실행하게 했다.
- `.github/workflows/ci.yml`에서 `actions/setup-python@v5`로 Python 3.12를 설정하고, requirements 파일로 contract validation 의존성을 설치하게 했다.
- `.github/workflows/ci.yml`에서 Node.js 22를 설정한 뒤 `bash scripts/verify-contracts`로 R1 계약과 DBML/generated artifact를 검증하게 했다.
- 같은 CI job에 `astral-sh/setup-uv@v6`, `uv python install 3.12`, `working-directory: ai`, `uv run pytest`를 추가해 FastAPI service tests를 서비스 경계 안에서 실행하게 했다.
- `validate-r1-contract.py`에서 OpenAPI `$ref`를 JSON Schema `$defs`로 변환해 fixture body를 검증하게 했다.
- fixture path `/api/v1/...`를 OpenAPI path template에 매칭하고, method/status response schema가 fixture의 `response.schema`와 일치하는지 확인하게 했다.
- `#/components/responses/Error` 같은 response 간접 참조를 해석하도록 보강했다.
- 로컬 Python 3.9 호환을 위해 `zip(strict=True)`는 사용하지 않았다.
- `scripts/azimutt-export.mjs`에 `AZIMUTT_OUTPUT_DIR`를 추가해 generated artifact stale 검증이 working tree를 직접 오염시키지 않게 했다.

## 결과

- `git diff --check`: 통과.
- `python3 -m pip install -r scripts/test/requirements-r1-contract.txt && python3 scripts/test/validate-r1-contract.py`: 13개 fixture 검증 통과. 로컬 Python 3.9 환경에서 `NotOpenSSLWarning`은 발생하지만 exit code는 0이다.
- `bash scripts/verify-contracts`: R1 계약 검증, DBML compile, generated artifact diff 통과.
- `./gradlew test`: `BUILD SUCCESSFUL`.
- `cd ai && uv run pytest`: 2개 테스트 통과.
- 남은 과제: 원격 GitHub Actions는 PR 생성 후 실제 runner에서 한 번 더 확인해야 한다.
