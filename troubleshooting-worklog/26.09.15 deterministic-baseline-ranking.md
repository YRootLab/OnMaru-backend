# Issue #97 deterministic baseline 검색·ranking 구현

## 문제와 범위

Issue #97 `[AI03] 검증 데이터 deterministic baseline 검색·ranking 구현`을 기준으로 작업했다. 선행 Issue #64, #95, #74는 모두 Closed였고 관련 담당자와 열린 PR이 없어 `Ready`로 판단했다. 미merge PR #194의 Issue #96을 요구하는 A03/A04 대신 파일과 의존성이 분리된 Wave 5 AI03을 선택했다.

구현은 accepted ADR-0007과 `docs/ai/retrieval-and-rag.md`의 baseline 계약을 따른다. HTTP endpoint, LLM, embedding, vector DB, Spring business DB 접근은 추가하지 않았다. `onmaru_ai.retrieval.baseline`은 Spring payload 또는 verified revision export가 공급한 후보를 처리하는 순수 Python 경계다.

## 결정한 계약

- ranking 전에 dataset revision, region, exclude, public 상태, tombstone, evidence provenance를 hard filter한다.
- lexical, topic, evidence, distance feature는 각각 `[0,1]`이고 `0.45L + 0.25T + 0.20E + 0.10D`로 계산한다. 결측 feature를 재가중하지 않는다.
- 검수된 이름이나 alias가 query에 포함되면 numeric score보다 우선한다.
- canonical ref 중복은 exact-name, score, ref, name 순서로 결정적으로 하나만 남긴다.
- 전체 ranked 후보는 30, proposal 후보는 12, baseline board는 3으로 제한한다.
- pin은 hard filter를 우회하지 않으며, exclude 충돌·부재·비공개 pin은 typed constraint error로 중단한다. pin은 최대 3개이며 중복을 허용하지 않는다.
- 비pin 후보는 `score - 0.15 * max(topic Jaccard)`로 greedily 선택한다. 여러 topic 요청에서는 category당 2개 soft cap을 적용하고 후보 부족 때만 이 cap을 완화한다.
- 결과에 dataset revision, ranking version, dictionary version, hard-filter 제외 사유를 남긴다.

## TDD 진행 기록

1. scoring/filter 테스트를 먼저 추가했다. production package가 없어 `ModuleNotFoundError: onmaru_ai.retrieval`로 RED를 확인했다.
2. frozen dataclass와 scoring을 구현한 뒤 동작 테스트 11개는 통과했다. mypy가 `dict[str, object]` 기반 test builder를 구체 field 타입으로 복원하지 못한 원인을 확인해 helper를 typed keyword 인자로 변경했다.
3. ranker 테스트를 먼저 추가했다. `BaselineConstraintError` import가 없어 RED를 확인했다.
4. ranker 최초 GREEN 시도에서 diversity fixture의 MARKET 후보가 HANOK summary를 공유해 기대 순서와 달랐다. 문서 점수식을 손으로 다시 계산해 fixture를 시장 전용 summary로 바로잡았다.
5. mutation review에서 exact-name 우선순위가 ranked 이후 diversity 단계에서 뒤집힐 수 있음을 발견했다. board 회귀 테스트가 실제로 `higher-score, exact`를 반환하며 실패했고, selection key에 exact-name 우선순위를 추가해 수정했다.
6. 중복 pin과 4개 pin이 `DID NOT RAISE`로 실패하는 테스트를 추가한 뒤 request 생성 경계에서 거부하도록 수정했다.
7. fixture loader를 먼저 추가하고 JSON 3종이 없어 `FileNotFoundError`가 발생하는 RED를 확인했다. synthetic fixture를 추가한 뒤 각 fixture의 정방향·역방향 결과가 동일함을 검증했다.
8. PR 전 수동 review에서 음수 `distance_meters`가 distance feature를 1보다 크게 만들 수 있음을 발견했다. `DID NOT RAISE` RED를 확인한 뒤 Candidate 생성 경계에서 음수 거리를 거부했다.
9. 같은 numeric 경계에서 NaN/Infinity가 비교를 우회해 결정 정렬을 오염할 수 있음을 확인했다. distance와 nearby radius의 non-finite RED 4건을 추가하고 `math.isfinite` 생성자 검증으로 차단했다.

## 남은 경계

Issue #97은 deterministic candidate selection만 소유한다. public Journey API, durable run orchestration, provider proposal schema와 Gemini adapter는 각각 후속 Issue #101/#109/#114, #105, #91 범위다. 실제 검색 저장소 연결은 Spring payload 또는 revision export adapter가 생성되는 후속 orchestration에서 이 순수 모듈에 typed candidate를 전달하도록 유지한다.
