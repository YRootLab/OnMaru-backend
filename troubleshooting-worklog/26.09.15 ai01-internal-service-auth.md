# AI01 Spring-FastAPI 내부 인증 계약 작업 기록

## 날짜

2026-09-15

## 문제 상황

Issue #74는 Spring이 FastAPI로 보내는 내부 AI 요청 경계를 외부에 노출되지 않는 typed contract와 service token 인증으로 고정하는 작업이다. FastAPI는 DB나 사용자 세션을 직접 읽지 않고 Spring이 전달한 bounded request만 처리해야 하며, 잘못된 audience/scope/expired token은 본문을 신뢰하기 전에 거부해야 했다.

## 오류명 또는 실패 증상

- Python RED: `ModuleNotFoundError: No module named 'onmaru_ai.security'`
- Java RED: `cannot find symbol InternalAiTokenSigner`
- 구현 중 FastAPI가 `dict[str, str] | JSONResponse` 반환 타입을 response model로 해석해 `FastAPIError: Invalid args for response field`가 발생했다.

## 기존 구조나 방식의 한계

O03에서 Spring/FastAPI 양쪽의 secret loading, rotation overlap, redaction은 준비되어 있었지만 내부 호출 token을 만들고 검증하는 경계는 없었다. O01의 correlation middleware는 requestId/runId/trace를 기록할 수 있었지만, Authorization token의 audience/scope/expiry를 검증하거나 Spring 발신 header를 생성하는 책임은 비어 있었다.

## 관련 코드 맥락

- `ai/src/onmaru_ai/security/internal_auth.py`
  - FastAPI 내부 endpoint `/internal/v1/journey/proposals`를 설치한다.
  - `validate_internal_token()`은 `Authorization: Bearer <jwt>`를 받아 HS256 서명, `iss/sub/aud/scope/exp/jti`를 검증한다.
  - `SecretProvider.get("internal-ai.service-token")`의 current와 previous 값을 모두 확인해 rotation overlap을 허용한다.
  - 오류는 `INTERNAL_AUTH_INVALID_AUDIENCE`, `INTERNAL_AUTH_FORBIDDEN_SCOPE`, `INTERNAL_AUTH_EXPIRED` 같은 내부 전용 code로 반환한다.

- `apps/spring-api/src/main/java/com/yrootlab/onmaru/integration/ai/security/InternalAiTokenSigner.java`
  - Spring이 FastAPI 호출 전 짧은 HS256 JWT를 만든다.
  - claim에는 issuer, subject, audience, scope, jti, iat, exp와 requestId/traceId/runId/deadlineAt을 넣는다.
  - secret은 기존 `SecretProvider`에서 읽으므로 운영 secret source와 테스트 fake source를 재사용한다.

- `apps/spring-api/src/main/java/com/yrootlab/onmaru/integration/ai/security/InternalAiRequestHeadersFactory.java`
  - Authorization token과 `X-Request-Id`, `X-Run-Id`, `traceparent`를 함께 생성한다.
  - correlation header에는 bearer token을 넣지 않아 telemetry redaction 경계와 충돌하지 않는다.

- `docs/contracts/openapi/internal-ai.yaml`
  - private `/internal/v1/journey/proposals` 계약을 OpenAPI 3.1로 고정한다.
  - fixture `docs/contracts/fixtures/internal-ai/*.json`이 accepted, wrong audience, missing scope 응답을 검증한다.

## 검토한 선택지

1. PyJWT/JJWT 같은 JWT 라이브러리를 추가한다.
2. 현재 범위에서는 HS256 JWT encode/verify를 표준 라이브러리 HMAC으로 직접 구현한다.
3. Spring-FastAPI 내부 인증을 API key header 하나로 단순화한다.
4. mTLS/workload identity를 바로 도입한다.

## 판단 기준

- 지금 이슈는 public journey endpoint나 provider 호출 구현이 아니라 내부 경계 동결이다.
- 기존 O03의 current/previous secret rotation 구조를 재사용해야 한다.
- 새 라이브러리는 CI lockfile과 운영 표면을 늘리므로, 최소 구현으로 충분한지 먼저 확인한다.
- body/query/token은 telemetry에 기록하지 않아야 한다.

## 최종 결정

표준 라이브러리 HMAC 기반 HS256 service JWT를 사용하고, 기존 `SecretProvider`의 current/previous secret으로 rotation overlap을 처리한다.

## 해결 방식

- FastAPI 테스트를 먼저 추가해 current token, previous token, wrong audience, wrong scope, expired token의 RED를 만들었다.
- Spring 테스트를 먼저 추가해 token claim, 짧은 TTL, bearer/correlation header 생성의 RED를 만들었다.
- Python `internal_auth.py`와 Java `InternalAiTokenSigner`/`InternalAiRequestHeadersFactory`를 최소 구현했다.
- FastAPI 반환 타입 문제는 internal endpoint에 `response_model=None`을 명시해 해결했다.
- `internal-ai.yaml`과 fixture 3개를 추가해 기존 `scripts/validate_contracts.py` 검증 경로에 포함했다.

## 결과

- 잘못된 audience는 401 `INTERNAL_AUTH_INVALID_AUDIENCE`로 거부된다.
- scope가 다르면 403 `INTERNAL_AUTH_FORBIDDEN_SCOPE`로 거부된다.
- 만료된 token은 401 `INTERNAL_AUTH_EXPIRED`로 거부된다.
- current/previous service secret 모두 rotation overlap 동안 허용된다.
- requestId/runId/traceparent는 응답과 telemetry correlation에 전달되고, bearer token은 correlation header에 섞이지 않는다.
