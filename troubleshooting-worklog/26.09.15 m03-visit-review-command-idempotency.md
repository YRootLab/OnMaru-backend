# M03 VisitReview 작성·삭제·멱등성 구현

날짜: 2026-09-15

## 문제 상황

Issue #118은 회원이 eligible 장소에 짧은 방문 후기를 작성하고 본인 후기만 삭제할 수 있게 하는 작업이었다. 요구사항은 300 code points/5줄 제한, NFC/trim/CRLF 정규화, actor를 request body에서 받지 않는 것, 동일 POST replay가 한 건만 생성되는 것이었다.

## 오류명 또는 실패 증상

- web 테스트 첫 실행에서 `Location` 헤더의 review id가 기대와 달랐다.
- 원인은 Spring test context 안에서 순차 UUID generator가 다른 테스트 메서드에서도 소비될 수 있는데, 테스트가 특정 id를 과하게 고정했기 때문이다.

## 기존 구조나 방식의 한계

#110에서 VisitReview query/read model은 생겼지만, 쓰기 command 경계와 idempotency 조합은 없었다. 또 CSRF/session/idempotency는 이미 shared-web과 security-web에 존재하므로 새로 만들면 안 되고, 기존 컴포넌트를 조합해야 했다.

## 관련 코드 맥락

- `modules/community/.../command/review/VisitReviewCommandService`
  - `CreateVisitReviewCommand`의 text를 CRLF→LF, trim, NFC 순서로 정규화한다.
  - blank, 300 code points 초과, 5줄 초과를 `VisitReviewTextInvalidException`으로 거부한다.
  - `VisitReviewPlaceLookup`으로 eligible place만 조회해 projection을 만들고 기존 `InMemoryVisitReviewStore`에 추가한다.
  - 삭제는 published 상태이면서 author가 현재 member인 review만 `REMOVED`로 교체한다.
- `VisitReviewCommandController`
  - session cookie에서 member를 찾고, request body의 actor 값은 받지 않는다.
  - `Idempotency-Key`와 `IdempotencyService`를 사용해 같은 member/method/path/payload replay를 저장 응답으로 재사용한다.
  - 다른 payload가 같은 key를 쓰면 shared-web의 `IDEMPOTENCY_CONFLICT` envelope가 반환된다.

## 검토한 선택지

1. command controller 안에서 바로 store를 갱신: 빠르지만 text validation과 소유권 삭제 규칙이 web에 묶인다.
2. query store와 별도 command store를 둔다: 실제 DB 전에는 동기화 코드가 불필요하게 늘어난다.
3. command service가 기존 query projection store를 갱신한다: 현재 in-memory scaffold에서 읽기/쓰기 반영을 가장 단순하게 검증할 수 있다.

## 판단 기준

- 보안 경계는 기존 CSRF/session/idempotency 컴포넌트를 재사용해야 한다.
- 후속 좋아요/신고 이슈가 같은 review id와 ownership 규칙을 재사용할 수 있어야 한다.
- 테스트는 생성 id 값 자체보다 replay와 단일 생성 여부를 검증해야 한다.

## 최종 결정

community command package를 추가하고, web boundary에서 session/CSRF/idempotency를 조합했다. in-memory 단계에서는 command service가 query projection store를 직접 갱신하도록 했다.

## 해결 방식

- `VisitReviewCommandServiceTests`로 텍스트 정규화, 길이/줄 수 validation, eligible place, 본인 삭제 규칙을 먼저 고정했다.
- `VisitReviewCommandWebBoundaryTests`로 POST replay, idempotency conflict, auth required, private place 404, 타인 삭제 404를 검증했다.
- 생성 ID는 테스트 응답에서 캡처해 replay/delete에 사용하도록 바꿔 테스트 순서 의존성을 제거했다.

## 결과

- targeted community test와 command web boundary test가 통과했다.
- #122 좋아요와 #123 신고/moderation이 사용할 VisitReview command 기반이 생겼다.
