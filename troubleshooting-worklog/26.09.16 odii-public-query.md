# Issue #103 Odii 공개 조회 API 작업 로그

## 문제

Odii 공개 조회는 active revision의 story만 제공하면서 언어 fallback, 자막 출처 상태,
비공개·삭제 차단, provider secret URL 비노출을 함께 보장해야 한다. 또한 Issue #104의
검수 결과가 병합된 뒤에는 별도 임시 포트가 아니라 승인된 canonical place query를
소비해야 한다.

## 구현

- story 목록·상세 query service와 Spring HTTP boundary를 추가했다.
- 요청 언어 exact 결과가 없으면 `ko-KR`로 fallback하고 상태를 응답에 명시한다.
- transcript를 `OFFICIAL`, `ESTIMATED`, `MISSING`으로 구분하며 missing일 때 stale line을 제거한다.
- story와 spot이 모두 `ACTIVE`이고 allowlist host의 audio URL인 경우만 공개한다.
- revision·filter·limit에 결속된 signed cursor를 사용하고 변조와 revision 교체를 구분한다.
- `ApprovedAudioPlaceLinkQuery`로 검수 승인된 단일 canonical place만 조회해 `linkedPlaceId`에 반영한다.
- production story store 미연결 상태는 빈 목록 대신 503으로 fail-closed한다.

## 결과

Issue #103 공개 projection은 이제 Issue #104의 승인·공개 장소 hydration 정책을 그대로
사용한다. 미승인, 중복 승인, 삭제된 canonical place는 #104 query에서 비어 있으므로
공개 story 응답에 임의의 place ID가 노출되지 않는다.
