# M04 VisitReview 좋아요 desired-state API 구현

날짜: 2026-09-15

## 문제 상황

Issue #122는 방문 후기 좋아요를 toggle race 없이 desired-state 방식으로 갱신하는 작업이었다. 계약은 `PUT /api/v1/visit-reviews/{reviewId}/likes/me`와 `DELETE /api/v1/visit-reviews/{reviewId}/likes/me`가 각각 `{likedByMe, likeCount}`를 반환하도록 정의되어 있다.

## 오류명 또는 실패 증상

- 구현 전 `VisitReviewLikeServiceTests`는 `VisitReviewLikeService`, `LikeState`, 예외 타입이 없어 컴파일 실패했다.
- web boundary 테스트는 컨트롤러가 없어 모든 endpoint가 기대 상태가 아닌 실패로 떨어졌다.

## 기존 구조나 방식의 한계

#110/#118로 VisitReview query와 command는 생겼지만, like state를 원자적으로 갱신하는 경계는 없었다. query DTO의 `likedByMe`와 `likeCount`는 projection의 liked member set을 읽는 구조라, 좋아요 API가 같은 projection을 안전하게 갱신해야 했다.

## 관련 코드 맥락

- `modules/community/.../like/VisitReviewLikeService`
  - `like(memberId, reviewId)`와 `unlike(memberId, reviewId)`가 desired-state 방식으로 동작한다.
  - hidden/removed 또는 없는 review는 `VisitReviewLikeNotFoundException`으로 감춘다.
  - 작성자 본인 좋아요는 `SelfVisitReviewLikeException`으로 분리해 web에서 403으로 매핑한다.
- `InMemoryVisitReviewStore.update`
  - review id 기준으로 synchronized update를 수행한다.
  - 현재 in-memory scaffold에서 review/member lock 순서를 `review lookup -> member set update`로 고정하는 역할을 한다.
- `VisitReviewLikeController`
  - session cookie의 member만 actor로 사용하고 body는 받지 않는다.
  - CSRF는 기존 `CsrfProtectionFilter`가 처리하며, controller는 auth/self-like/not-found envelope를 담당한다.

## 검토한 선택지

1. boolean toggle API로 구현: race 상황에서 최종 상태가 요청 순서에 따라 뒤집힐 수 있어 이슈 요구와 맞지 않는다.
2. 좋아요 전용 별도 store를 만든다: 실제 DB 전에는 query projection과 동기화해야 해서 중복이 늘어난다.
3. 기존 review projection의 liked member set을 synchronized desired-state로 갱신한다: 현재 scaffold에서 count와 likedByMe를 가장 직접적으로 검증할 수 있다.

## 판단 기준

- 동시 PUT에도 한 member의 like는 한 건이어야 한다.
- self-like는 403, hidden/deleted는 404로 구분되어야 한다.
- read model의 `likedByMe`/`likeCount`와 command 결과가 같은 source를 봐야 한다.

## 최종 결정

`modules/community/like`에 desired-state service를 추가하고, Spring web boundary에서 PUT/DELETE를 no-store 응답으로 노출했다.

## 해결 방식

- `VisitReviewLikeServiceTests`로 동시 PUT, idempotent unlike, self-like, hidden/not-found 조건을 먼저 작성했다.
- `InMemoryVisitReviewStore.update`를 추가해 liked member set 갱신을 원자적으로 수행했다.
- `VisitReviewLikeWebBoundaryTests`로 HTTP 200/403/404/401 응답과 `LikeState` 계약을 검증했다.

## 결과

- targeted community like test와 Spring web boundary test가 통과했다.
- R2 통합 E2E 게이트(#140)가 검증할 후기 좋아요 read/write 계약의 기반이 마련됐다.
