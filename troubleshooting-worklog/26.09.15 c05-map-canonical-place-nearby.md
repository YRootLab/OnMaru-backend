# C05 지도 주변 canonical 장소 조회 API 구현

날짜: 2026-09-15

## 문제 상황

Issue #100은 공개 canonical 장소를 지도 화면에서 안전하게 조회하기 위해 `GET /api/v1/map/places`를 구현하는 작업이었다. R2 OpenAPI fixture는 `regionCode`와 `bbox` 기반 목록 계약을 이미 고정하고 있었고, 이슈 본문은 `nearby`, category filter, coordinate validation, distance projection, lon/lat 축 고정을 요구했다.

## 오류명 또는 실패 증상

- 신규 `MapPlaceQueryServiceTests` 작성 직후 spatial 패키지 타입이 없어 컴파일 실패가 발생했다.
- 첫 web boundary 테스트에서는 `$.items[0].placeId`가 기대와 달랐다. 중심 좌표가 없는 region 조회에도 placeId 정렬을 강제해 fixture가 기대하는 발행 snapshot 순서가 깨진 것이 원인이었다.

## 기존 구조나 방식의 한계

한옥 목록/상세 API는 `InMemory...Store`와 query service로 public projection 계약을 고정해 두었지만, 지도 장소 조회 전용 spatial boundary는 아직 없었다. 실제 PostGIS 어댑터가 붙기 전이라도 FE가 의존할 좌표축, 필터, 오류 envelope, saved state 조합 규칙을 테스트로 먼저 잠가야 했다.

## 관련 코드 맥락

- `modules/catalog/.../query/spatial/MapPlaceQueryService`
  - `MapPlaceQuery`를 입력받아 공개 상태, 좌표 존재 여부, regionCode, category, bbox, 중심점 반경을 순서대로 필터링한다.
  - 중심점 조회일 때만 Haversine 거리 계산으로 오름차순 정렬하고, region/bbox 조회는 publication snapshot 순서를 유지한다.
  - 응답은 R2 fixture와 같은 `MapPlacePage(schemaVersion, coverageStatus, language, items, nextCursor, hasMore)`로 반환한다.
- `apps/spring-api/.../web/map/place/MapPlaceController`
  - `/api/v1/map/places` 요청을 받고 `bbox=west,south,east,north`를 WGS84 double 값으로 파싱한다.
  - 잘못된 bbox/좌표/반경/limit은 `INVALID_REQUEST` envelope로 반환하고, store 장애는 `SERVICE_UNAVAILABLE`로 반환한다.
- `MapSavedStateLookup`
  - journey 모듈의 `InMemorySavedPlaceStore`와 연결해 로그인 세션이 있을 때 `savedByMe`를 계산한다.

## 검토한 선택지

1. 바로 PostGIS repository를 만들기: 실제 DB adapter가 아직 전체 schema/repository 계층으로 연결되지 않아 blast radius가 커진다.
2. 기존 한옥 목록 projection에 지도 필드를 추가하기: R1 한옥 목록과 R2 지도 장소 계약의 category/coverage/odii 필드가 달라 책임이 섞인다.
3. spatial 전용 in-memory projection과 service를 만들기: 현재 repo의 query API 패턴과 맞고, PostGIS adapter로 교체할 때도 계약 테스트를 유지할 수 있다.

## 판단 기준

- R2 fixture와 FE traceability가 기대하는 응답 모양을 먼저 보존해야 한다.
- lon/lat 축과 bbox 파싱은 나중에 DB로 옮겨도 가장 깨지기 쉬운 부분이라 테스트로 고정해야 한다.
- 기존 한옥/상세 API와 같은 계층 구조를 따라야 다음 이슈와 충돌이 적다.

## 최종 결정

spatial 전용 query package를 만들고, 현재는 Haversine 기반 in-memory projection store로 공개 계약과 좌표 검증 규칙을 고정했다.

## 해결 방식

- `MapPlaceQueryServiceTests`로 반경 경계, 거리순, lon/lat 축, 비공개/좌표 없음 제외, category/region/bbox/limit, unavailable propagation을 먼저 작성했다.
- `MapPlaceQueryService`에서 공개 projection만 필터링하고 중심 좌표 조회는 거리순, region/bbox 조회는 snapshot 순서 유지로 정리했다.
- `MapPlaceWebBoundaryTests`로 R2 `map-places-normal`, `map-places-missing`, `invalid-request` fixture 성격을 MockMvc 경계에서 검증했다.
- `MapPlaceController`와 `MapPlaceConfiguration`을 추가해 `/api/v1/map/places`를 노출하고, session cookie 기반 `savedByMe`를 journey saved-place store와 연결했다.

## 결과

- targeted module test와 web boundary test가 통과했다.
- 실제 PostGIS adapter는 후속 persistence 작업에서 붙이면 되고, 이번 변경은 그 어댑터가 반드시 만족해야 할 API/좌표/오류 계약을 고정한다.
