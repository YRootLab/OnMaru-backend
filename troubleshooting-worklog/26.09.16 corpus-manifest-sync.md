# 26.09.16 corpus-manifest-sync

## Context

- Issue: #106 `[AI07] Revision-pinned corpus export·manifest sync 구현`
- Branch: `feature/106-corpus-manifest-sync`
- blocked-by #74, #95, #96은 모두 Closed라 작업 시작 가능 상태였다.
- 목표: Spring canonical export를 hash manifest로 FastAPI에 전달하고, FastAPI가 duplicate pull, partial fetch, hash mismatch, out-of-order manifest를 안전하게 처리한다.

## Changes

- Spring `com.yrootlab.onmaru.internal.corpus` 패키지를 추가했다.
  - immutable revision publish, `CorpusManifest`/document entry/`CorpusChunk`/descriptor DTO와 canonical JSON 기반 SHA-256 hash 계산을 추가했다.
  - `OdiiAudioCorpusSource`가 active audio revision snapshot을 corpus chunk로 변환한다.
  - `/internal/v1/corpus/revisions/{revisionId}/manifest`, `/internal/v1/corpus/revisions/{revisionId}/documents/{documentId}`, `/internal/v1/corpus/revisions/{revisionId}/ack` internal export endpoint scaffold를 추가했다.
  - document fetch는 expected revision이 현재 active revision과 다르면 empty로 응답해 stale fetch가 새 active payload를 읽지 못하게 했다.
  - FastAPI ACK는 published manifest hash와 일치할 때만 기록한다.
- FastAPI `onmaru_ai.corpus.sync` 패키지를 추가했다.
  - `CorpusDocument`, `CorpusManifest`, manifest entry, in-memory store, pull service, ACK payload를 구현했다.
  - 동일 revision 재-pull은 insert 0으로 idempotent 처리한다.
  - partial fetch와 document hash mismatch는 reject하고 active revision을 유지한다.
  - manifest `published_at` 기준 out-of-order rollback을 reject한다.
  - tombstone은 complete revision activation 시에만 active document set에 반영한다.
- `docs/contracts/openapi/internal-ai.yaml`에 corpus manifest/document/ACK private contract를 추가했다.
- 독립 리뷰 후 Spring controller를 OpenAPI wire shape로 맞추고, Spring/FastAPI hash canonicalization을 같은 camelCase JSON payload 기준으로 통일했다.
