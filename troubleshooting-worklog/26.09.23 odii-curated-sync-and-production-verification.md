# Odii 다중 키워드 큐레이션 동기화 및 운영 적재 확인

- 날짜: 2026-09-23
- 관련 이슈: #307, #329
- 구현 커밋: `551b8fa`
- 상태: 코드 구현 완료, 운영 PostgreSQL 적재·게시 미확인

## 문제 상황

기존 Odii 동기화는 `한옥` 단일 검색어만 사용해 공개 가능한 story 수가 부족했다. 동시에 #307에서 운영 PostgreSQL의 Odii revision이 비어 있어 `trending-sounds`와 `odii/stories`가 503을 반환하고 있었다.

## 기존 구조

공개 API 요청 시 공공데이터 API를 직접 호출하지 않고 다음 흐름을 사용한다.

```text
공공데이터 Odii API
→ Odii page source
→ mapping·curation
→ PostgreSQL staging
→ revision publish
→ active revision 조회 API
```

따라서 이번 코드가 배포되더라도 동기화가 성공해 active revision을 게시하지 못하면 FE에는 새 데이터가 전달되지 않는다.

## 구현 내용

### 다중 키워드 수집

`OdiiSyncSettings`와 `application.yaml`을 단일 `keyword`에서 `keywords` 목록으로 변경했다. 기본 수집 키워드는 다음과 같다.

```text
한옥, 고택, 전통마을, 궁궐, 성곽, 문화유산, 역사문화, 전통시장
```

운영 환경에서는 `ONMARU_ODII_KEYWORDS`로 조정할 수 있다.

### 큐레이션 필터

`OdiiCurationPolicy`를 추가해 story가 PostgreSQL revision에 staging되기 전에 제목·오디오 제목·대본을 검사한다.

- 제외: 레저, 스포츠, 골프, 수상레저, 액티비티, 쇼핑, 숙박, 호텔, 리조트
- 조건부 허용: 축제·자연·공원 키워드는 역사·문화·전통·해설 등 문화 맥락이 있을 때만 허용
- 필수 식별자: `stlid`가 없는 story는 제외

### 중복 제거

여러 키워드에서 같은 story가 조회될 수 있으므로 `stlid`를 sync run 내에서 deduplication key로 사용한다. 같은 story는 active revision에 한 번만 staging된다.

### FE 계약 보존

FE controller, DTO, OpenAPI 응답 구조는 변경하지 않았다. FE는 기존 pagination·cursor·상세 조회 로직을 그대로 사용하면 된다. 필터링은 FE가 아니라 백엔드 sync 단계에서 수행한다.

모든 명령이 통과했으며, 실제 PostgreSQL 연동 테스트는 Testcontainers 기반으로 실행됐다.

## 운영 확인 결과

2026-09-23 운영 endpoint를 확인했다.

| 확인 항목 | 결과 |
|---|---|
| `/actuator/health` | `UP` |
| `/api/v1/home/trending-sounds?language=ko-KR&limit=5` | `503 SERVICE_UNAVAILABLE` |
| `/api/v1/odii/stories?language=ko-KR&limit=5` | `503 SERVICE_UNAVAILABLE` |

현재 결과로는 운영 Neon PostgreSQL에 새 Odii active revision이 게시됐다고 판단할 수 없다. 애플리케이션 health는 정상이나 Odii query store가 사용할 active dataset을 찾지 못하는 상태로 보인다.

## 남은 운영 작업

1. 커밋 `551b8fa`가 Render 운영 서비스에 배포됐는지 확인한다.
2. `ONMARU_ODII_KEYWORDS`와 `ONMARU_SECRET_ODII_SERVICE_KEY_CURRENT` 설정을 확인한다.
3. Render 로그에서 `initial odii sync`, `odii sync failed`를 확인한다.
4. 동기화 성공 후 다음 endpoint가 200인지 확인한다.

```text
GET /api/v1/home/trending-sounds?language=ko-KR&limit=5
GET /api/v1/odii/stories?language=ko-KR&limit=5
```

5. Neon PostgreSQL에서 `audio_revision_stages`, `audio_story_versions`, `catalog_active_datasets`의 새 revision과 active pointer를 확인한다.

## 결론

코드 수준에서는 FE 변경 없이 전통문화·역사 관련 Odii 데이터를 넓혀 수집하고, 레저·스포츠 콘텐츠를 백엔드에서 제외하도록 구현했다. 다만 운영 endpoint가 여전히 503이므로 실제 운영 PostgreSQL 적재·게시 완료는 아직 확인되지 않았다. #307 복구와 Render 재배포 후에만 FE에서 증가한 데이터를 확인할 수 있다.
