# D05 community review schema worklog

## 날짜

2026-09-15

## 문제 상황

VisitReview는 기존 온기 모델과 별도의 짧은 방문 후기이며, 좋아요·신고·운영 판정이 모두 원자적으로 저장되어야 한다. Issue #78은 review, like, report, moderation audit을 executable migration으로 만드는 작업이다.

## 오류명 또는 실패 증상

TDD 첫 실행에서 `CommunityMigrationTests`가 실패했다.

- community 테이블들이 없어 table count 검증이 실패했다.
- review/like/report/audit insert가 `PSQLException`으로 실패했다.
- self-report trigger는 동작했지만 예외 메시지에 stable constraint 이름이 포함되지 않아 테스트가 한 번 실패했다.

## 기존 구조나 방식의 한계

`docs/database/modules/community.dbml`과 `docs/operations/moderation.md`에는 정책이 있었지만 실제 DDL이 없었다. 중복 like/report, 본인 신고, moderation audit 변경 금지는 application 코드만으로 처리하면 동시 요청과 운영 실수에 취약하다.

## 관련 코드 맥락

- `apps/spring-api/src/main/resources/db/migration/baseline/V007__d05_community_review_schema.sql`
  - `community_visit_reviews`는 member/place FK와 text 비어 있음 방지, DELETED 상태의 `deleted_at` 필수 제약을 가진다.
  - `community_review_likes`는 `(review_id, member_id)` PK로 중복 좋아요를 막는다.
  - `community_review_reports`는 reason allowlist와 `OPEN` 상태 partial unique로 같은 회원의 열린 신고 중복을 막는다.
  - `community_reject_self_report()` trigger는 review 작성자와 reporter가 같으면 self-report를 거부한다.
  - `community_review_moderation_actions`는 previous/next status가 같을 수 없고, UPDATE/DELETE trigger로 append-only audit을 강제한다.
- `apps/spring-api/src/test/java/com/yrootlab/onmaru/testing/postgres/CommunityMigrationTests.java`
  - 중복 like/report, 빈 review text, self-report, 허용되지 않은 reason, no-op moderation action을 실제 DB에서 검증한다.

## 검토한 선택지

1. self-report와 append-only를 application service에서만 처리한다.
2. DB trigger로 cross-row/cross-table 규칙을 강제한다.
3. report unique를 모든 상태에 적용한다.
4. `OPEN` 상태에만 partial unique를 적용한다.

## 판단 기준

- 본인 신고는 report row만 보는 CHECK로는 검증할 수 없으므로 trigger가 필요하다.
- 운영 audit은 나중에 queue/runbook의 증거가 되므로 UPDATE/DELETE를 DB에서 막는 편이 안전하다.
- resolved/dismissed 뒤 재신고 가능성을 열어두려면 `OPEN` partial unique가 정책과 맞다.

## 최종 결정

V007 Flyway migration으로 community review schema를 추가하고, trigger와 partial unique index를 Testcontainers 테스트로 검증했다.

## 해결 방식

1. RED: `CommunityMigrationTests`를 추가해 community schema 부재를 확인했다.
2. GREEN: `V007__d05_community_review_schema.sql`로 review/like/report/moderation 테이블과 enum을 추가했다.
3. self-report guard: review author와 reporter를 비교하는 trigger를 추가하고, 오류 메시지에 `community_review_reports_not_self_ck`를 포함해 디버깅 가능하게 했다.
4. audit guard: moderation action UPDATE/DELETE를 막는 append-only trigger를 추가했다.
5. registry/docs: V007 SHA-256과 migration ownership 문서를 갱신했다.
