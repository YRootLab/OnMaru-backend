# P06 DataLab 관광 관측 adapter 작업 로그

날짜: 2026-09-15

## 문제 상황

#90은 관광 데이터랩 관측값을 장소 실시간 인원처럼 과장하지 않고, 날짜·공간 단위·단위·상태가 보존된 typed observation으로 다루는 작업이었다. 기존 DB migration에는 insights 테이블이 있었지만 Java 도메인 모듈과 DataLab adapter 계약은 없었다.

## 오류명 또는 실패 증상

첫 TDD 실행은 `modules:insights`와 `DataLabObservationMapper`가 없어 compile RED가 났다. `modules/insights` 디렉터리 자체가 없어서 `settings.gradle.kts`에 새 모듈을 추가하고, adapter가 insights 도메인 타입을 참조하도록 Gradle 의존성을 연결해야 했다.

## 기존 구조나 방식의 한계

기존 `adapters:tourism-api`는 국문 TourAPI 장소 수집 계약만 갖고 있었다. 관광 관측값은 `visitorCount`가 누락될 수 있고, 공간 단위가 SIDO/SIGUNGU/TARGET으로 달라질 수 있으며, provider target을 canonical place로 연결하지 못할 수도 있다. 이 값을 단순 숫자 DTO로만 받으면 결측을 0으로 저장하거나 실시간 혼잡도로 오해하게 만들 위험이 있었다.

## 관련 코드 맥락

- `modules/insights/src/main/java/com/yrootlab/onmaru/insights/observation/*`
  - `VisitorObservation`은 provider, regionCode, basisDate, metric, nullable value, unit, spatialLevel, coverageStatus, sourceObservedAt을 보존한다.
  - `ConcentrationObservation`은 provider target이 매핑되지 않을 때 `targetKey: UNKNOWN`을 허용한다.
  - `ObservationCoverageStatus.NOT_AVAILABLE`은 결측을 0과 구분한다.

- `adapters/tourism-api/src/main/java/com/yrootlab/onmaru/tourism/insights/DataLabObservationMapper.java`
  - DataLab payload를 insights 도메인 observation으로 변환한다.
  - `visitorCount: null`은 `value: null`, `coverageStatus: NOT_AVAILABLE`로 매핑한다.
  - `targetKey`가 없으면 canonical place link를 만들지 않고 `UNKNOWN`으로 둔다.

- `.github/workflows/ci.yml`
  - 새 `modules:insights:test`가 CI에서 빠지지 않도록 verify job에 추가했다.

## 검토한 선택지

1. `adapters:tourism-api` 내부 DTO만 추가한다.
2. 기존 `catalog` 모듈에 insights 타입을 섞는다.
3. 새 `modules:insights`를 만들고 adapter는 해당 도메인 타입으로 변환한다.
4. 누락 방문자 수를 0으로 저장한다.

## 판단 기준

- 관측값은 catalog 장소 데이터와 소유권이 다르므로 별도 모듈이 맞다.
- #138 공개 조회 API가 재사용할 typed observation 모델이 필요하다.
- 결측은 숫자 0과 의미가 다르므로 null/status로 보존해야 한다.
- 새 모듈은 CI에서 자동 검증되어야 한다.

## 최종 결정

`modules:insights`를 추가하고, `adapters:tourism-api`의 DataLab mapper가 이 도메인 타입으로 변환하도록 구현했다.

## 해결 방식

- `ObservationMetric`, `SpatialLevel`, `ObservationCoverageStatus` enum을 추가했다.
- visitor/concentration observation record와 in-memory store를 추가했다.
- DataLab mapper 테스트로 basisDate, spatialLevel, provider, unit, status 보존을 검증했다.
- 결측 visitorCount가 `0`이 아니라 `null + NOT_AVAILABLE`으로 남는지 테스트했다.
- DataLab source qualification manifest와 README를 추가했다.
- CI에 `:modules:insights:test`를 추가했다.

- `./gradlew :modules:insights:test :adapters:tourism-api:test --no-daemon` 통과
