# C02 hanok list query API 구현

날짜: 2026-09-15

## 문제 상황

Issue #98은 published snapshot에서 한옥 후보를 외부 TourAPI 실시간 호출 없이 안정적으로 조회해야 했다. keyword, region, category, hasImage 필터와 deterministic sort, cursor paging, `savedByMe` projection을 함께 제공해야 했다.

## 오류명 또는 실패 증상

- RED 테스트 실패: `HanokListQueryService`, `HanokListProjection`, `InMemoryHanokListStore`, cursor 예외 타입이 없어 catalog 테스트가 컴파일 실패했다.
- 웹 RED 테스트 실패: `InMemoryHanokListStore` bean과 `/api/v1/hanoks` controller가 없어 Spring context 테스트가 실패했다.

## 기존 구조나 방식의 한계

#99에서 detail query는 있었지만 목록 전용 card DTO와 cursor boundary는 없었다. 상세 projection만 재사용하면 list 전용 summary, tags, published ordering, cursor 기준을 표현하기 어려웠고, R1 fixture의 목록/empty/cursor 응답을 runtime에서 검증할 수 없었다.

## 관련 코드 맥락

- `modules/catalog/.../query/hanok/HanokListQueryService`
  - 입력: keyword, regionCode, category, hasImage, limit, cursor, optional member UUID
  - 처리: published snapshot에서 public projection만 필터링하고 NFC/trim/lowercase keyword normalization을 적용한다.
  - 정렬: `publishedAt DESC, placeId ASC`로 deterministic order를 만든다.
  - cursor: `r1.hanoks.cursor.{publishedAt}.{placeId}`를 decode해 keyset paging을 수행한다.
- `InMemoryHanokListStore`
  - 현재는 published snapshot fixture 역할을 한다.
  - `markUnavailable()`로 catalog read failure 503 경계를 테스트한다.
- `apps/spring-api/.../HanokListController`
  - optional session을 member ID로 해석해 journey saved store 기반 `savedByMe`를 반영한다.
  - cursor invalid/expired/source unavailable을 public error envelope으로 변환한다.

## 검토한 선택지

1. detail projection store를 그대로 목록에 재사용한다.
2. OpenAPI fixture JSON을 controller에서 직접 반환한다.
3. list 전용 query projection/service/store를 catalog module에 둔다.
4. shared-web `CursorCodec`을 그대로 사용한다.

## 판단 기준

- 목록은 summary, tags, published ordering처럼 detail과 다른 읽기 모델을 가진다.
- R1 fixture가 고정 cursor 문자열을 요구하므로 signed cursor를 바로 적용하면 fixture와 맞지 않는다.
- 실제 DB adapter가 붙기 전에도 application query 규칙을 테스트 가능해야 한다.

## 최종 결정

3번을 선택했다. list 전용 query boundary를 만들고, cursor는 R1 fixture의 명시 형식을 지원하는 keyset cursor로 구현했다.

## 해결 방식

- `HanokListQueryServiceTests`로 normalization/filter, deterministic order, cursor page, cursor invalid/expired, snapshot unavailable을 먼저 고정했다.
- `HanokListWebBoundaryTests`로 normal fixture, cursor fixture, empty fixture, cursor error envelope, 503 envelope을 검증했다.
- Spring configuration에서 in-memory list snapshot을 seed하고, saved state는 #108의 journey saved store를 재사용했다.

## 결과

- `/api/v1/hanoks`가 published snapshot 기반으로 동작한다.
- 익명/회원 `savedByMe`가 saved store와 연결된다.
- 필터 조합, cursor page, empty response, read failure envelope을 테스트로 검증했다.
