# 26.09.15 I01 Kakao OAuth state·callback·opaque session

## 문제

#86은 Kakao provider token을 브라우저나 장기 저장소에 남기지 않고 OnMaru의 opaque server session으로 전환하는 인증 경계를 요구했다. 동시에 OAuth `state` 재사용·변조·issuer 혼동을 막고, 같은 Kakao 계정으로 callback이 동시에 들어와도 고아 member가 남지 않아야 했다.

## 진행

- `modules:identity`를 추가해 provider 독립 OAuth application boundary를 분리했다.
- `OAuthLoginService`가 state 원문과 browser nonce 원문을 SHA-256 hash로만 저장하고, callback 시 hash·provider·nonce·만료·미소비 조건을 한 번에 소비하도록 구성했다.
- `ExternalIdentity(provider, issuer, subject)`를 명시해 Kakao issuer가 아닌 callback은 session 생성 전에 거부했다.
- `IdentityStore` port와 `InMemoryIdentityStore`를 두어 core policy를 Spring MVC나 Kakao REST client 없이 테스트 가능하게 만들었다.
- Spring app에는 `KakaoOAuthController`와 `RestClientKakaoOAuthClient`를 추가했다. Kakao access token은 user info 조회에만 사용하고 OnMaru에는 `__Host-onmaru-session` opaque cookie만 발급한다.
- DB contract에 member 생성과 external account 연결을 같은 transaction으로 수행해야 고아 member가 남지 않는 동시성 테스트를 추가했다.
- CI에 `:modules:identity:test` 단계를 추가해 OAuth/session core policy가 PR마다 검증되도록 했다.

## 왜 이 기술을 사용했나

- Java record: OAuth command/result/value object를 불변 데이터로 표현해 state, provider, session token의 책임을 좁혔다.
- `SecureRandom` + URL-safe Base64: 브라우저로 나가는 state, nonce, session 원문을 추측하기 어렵고 URL/cookie에 안전한 opaque token으로 발급하기 위해 사용했다.
- SHA-256 hash + secret pepper: DB에는 state/session 원문을 저장하지 않고, 유출 시 즉시 재사용 가능한 credential이 남지 않게 했다.
- Spring `RestClient`: Kakao token 교환과 사용자 조회를 Spring 기본 HTTP client 경계로 캡슐화해 테스트에서는 `KakaoOAuthClient` port를 mock으로 교체할 수 있게 했다.
- PostgreSQL unique constraint + transaction 검증: provider/issuer/subject 유일성을 DB가 최종 보장하고, 충돌 transaction rollback으로 고아 member를 만들지 않는 증거를 남기기 위해 사용했다.

## 해결 결과

- state replay와 tampering은 `OAuthStateRejectedException`으로 거부된다.
- Kakao issuer가 아닌 external identity는 member/session 생성 전에 거부된다.
- 같은 Kakao external identity에 대한 동시 callback은 하나의 member에 연결되고 session만 각각 발급된다.
- callback 실패나 취소는 `/discover?auth=failed`로 돌려보내며 guest cookie를 삭제하지 않는다.
- PR CI에서 identity module test가 별도 단계로 실행되도록 자동화했다.
