# D08 migration concurrency contracts

날짜: 2026-09-15

## 문제 상황

#85는 D02~D07/D09 migration이 각각 통과하는 것을 넘어서, 전체 schema를 함께 올렸을 때 upgrade와 핵심 race가 실제 PostgreSQL에서 깨지지 않는지 증명해야 했다.

## 오류명 또는 실패 증상

초기 RED 실행에서 `DatabaseMigrationContractTests`가 실패했다.

- Flyway history version 기대값을 `8`로 두었지만 실제 값은 `008`이었다.
- `identity_deletion_ledger`를 `id` 컬럼이 있는 테이블처럼 넣었지만 실제 D03 schema는 `member_id`를 primary key로 쓰고 `reason`을 필수로 둔다.

## 기존 구조나 방식의 한계

기존 migration 테스트는 각 schema owner별 단위 검증에 가까웠다. 그래서 전체 baseline을 빈 DB에 적용하는 경로, 직전 baseline에서 최신 baseline으로 올라오는 경로, 그리고 저장/좋아요/런/게시 같은 cross-domain race가 한 번에 깨지는지를 확인하기 어려웠다.

## 관련 코드 맥락

- `apps/spring-api/src/test/java/com/yrootlab/onmaru/testing/postgres/DatabaseMigrationContractTests.java`
  - 실제 `postgis/postgis:17-3.5-alpine` Testcontainers DB를 띄운다.
  - Flyway `classpath:db/migration/baseline`을 빈 DB와 `target("7")` 업그레이드 fixture에 적용한다.
  - `CyclicBarrier`와 별도 JDBC connection 두 개로 동시 insert/update를 발생시켜 PostgreSQL unique constraint와 row update predicate가 경합을 막는지 확인한다.
- `docs/database/migration-and-concurrency.md`
  - D08의 실행 가능한 owner를 `DatabaseMigrationContractTests`로 명시하고, DB-only 계약과 HTTP 응답 매핑의 경계를 분리했다.

## 검토한 선택지

1. 기존 owner별 migration 테스트에 scenario를 분산 추가한다.
2. 애플리케이션 repository/API 계층이 생길 때까지 D08을 미룬다.
3. 별도 통합 계약 테스트 클래스를 추가해 DB-level invariant만 먼저 고정한다.

## 판단 기준

- #85 acceptance criteria가 “empty와 이전 baseline upgrade” 및 “문서의 필수 concurrency matrix”를 요구한다.
- 현재 repository는 schema-first 단계라 HTTP 응답 매핑보다 DB row/constraint/CAS 결과를 먼저 고정하는 것이 맞다.
- Testcontainers는 실제 PostgreSQL/PostGIS lock, partial unique index, enum/check constraint를 사용하므로 H2나 mock보다 race 증거로 적합하다.

## 최종 결정

별도 `DatabaseMigrationContractTests`를 추가해서 D08의 전체 migration·동시성 계약을 한 곳에서 실행한다.

## 해결 방식

- 빈 DB에 V001~V008 전체 migration을 적용하고 최신 Flyway version과 핵심 테이블 존재를 검증했다.
- `target("7")`로 V007 fixture를 만든 뒤 review row를 넣고 V008까지 upgrade해서 기존 row 보존과 D06 audio table 생성을 함께 확인했다.
- 자동 downgrade script를 금지하는 forward-only migration 정책을 migration directory 파일명으로 검증했다.
- run admission, actor admission, cancel/completion, deadline sweeper/completion, duplicate turn command, save/like/report 중복, publish CAS, moderation/public read를 PostgreSQL row 상태와 update count로 확인했다.

## 결과

- `./gradlew :apps:spring-api:test --tests '*DatabaseMigrationContractTests' --no-daemon` 통과.
- D08 matrix는 실제 PostgreSQL/Testcontainers 기반으로 재실행 가능해졌다.
- HTTP/public response code 매핑은 API 구현 시 application-layer contract로 이어서 묶어야 한다.
