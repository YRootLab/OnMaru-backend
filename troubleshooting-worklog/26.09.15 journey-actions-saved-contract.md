# Journey actions·SavedJourney 계약 완성

## 문제

Issue #134 착수 시 `journey.openapi.yaml`에는 exploration 생성·조회, turn, run, SSE, cancel만 있었다. actions와 saved journey public endpoint가 없었고 `ExplorationSnapshot`은 `additionalProperties: true`여서 구현과 FE reducer가 공유할 안정적인 계약으로 사용할 수 없었다.

## 진행

1. Journey 전용 validator를 `scripts/verify-contracts`에 먼저 연결하고 누락된 actions·saved-journeys 경로 때문에 실패하는 RED를 확인했다.
2. action command와 멱등 key, proposal command, SavedJourney 생성·목록·상세·삭제·재개 경로를 OpenAPI 3.1에 추가했다.
3. board, proposal, history, execution, pinned/excluded refs를 포함한 `ExplorationSnapshot`을 닫힌 schema로 정의했다.
4. 정상 PIN, stale version, command idempotency·pinned ref·proposal expiry·active run 충돌, 저장, cursor 목록, unavailable resource 재개 fixture를 추가했다.
5. validator가 request/response schema뿐 아니라 command ID 일치, version 증가, 409 error code와 unavailableRefs 의미 조건도 검사하도록 보강했다.
6. 독립 리뷰에서 발견한 개인정보 snapshot 누출 가능성, CSRF·no-store 누락, nullable 원본 exploration, cursor expiry·SAVE_LIMIT 오류 계약을 보완했다.
7. required path/header/query parameter와 모든 unsafe operation의 idempotency·CSRF·403, 모든 성공 응답의 `Cache-Control: no-store`를 validator가 검사하도록 강화했다.
8. 원본 exploration 만료 후 상세 조회, action·상세·삭제·재개의 타 actor 404, 동일 payload replay, missing CSRF/idempotency, idempotent 삭제 fixture를 더해 총 22개 시나리오로 생성·목록·상세·삭제·재개를 모두 고정했다.
9. SavedJourney는 확정 board와 최소 후보 1개를 요구하고, 자유문 query summary 대신 검수된 region/topic의 canonical `summaryRefs`만 보존한다.
10. 미선언 response status와 body 유무, action discriminator mapping, 공통 validation·payload 오류와 shared no-store error response를 validator가 확인한다.
