## 1. 문제 상황 및 오류 증상

### 1.1 증상
Render 프로덕션 배포 시(`SPRING_PROFILES_ACTIVE=production`), Spring 컨텍스트 초기화 단계에서 아래와 같은 `UnsatisfiedDependencyException`이 발생하며 서버 기동에 실패함:

```text
APPLICATION FAILED TO START
***************************
Field queryStore in com.yrootlab.onmaru.web.audio.OdiiStoryController required a bean of type 'com.yrootlab.onmaru.audio.query.OdiiStoryQueryStore' that could not be found.
...
Parameter 0 of method odiiStoryQueryStore in com.yrootlab.onmaru.web.audio.OdiiStoryConfiguration required a bean of type 'com.yrootlab.onmaru.audio.sync.AudioRevisionStore' that could not be found.
```

### 1.2 원인 분석
- `OdiiStoryConfiguration`에서 인메모리 `odiiAudioRevisionStore` 빈에 `@Profile("!production")` 조건이 설정되어 있었음.
- 프로덕션 프로필에서는 `AudioPersistenceConfiguration`의 `JdbcAudioRevisionStore`가 활성화되어야 하지만, DB `DataSource` 환경변수가 주입되지 않았거나 로드 지연 시 `AudioRevisionStore` 빈 자체가 컨텍스트에 존재하지 않게 됨.
- 이로 인해 `odiiStoryQueryStore`를 조립하지 못하고 애플리케이션이 크래시됨.

## 2. 해결 방식 및 코드 맥락

### 2.1 코드 수정
- **파일**: `apps/spring-api/src/main/java/com/yrootlab/onmaru/web/audio/OdiiStoryConfiguration.java`
- **조치**:
  1. `odiiAudioRevisionStore` 빈에서 배타적인 `@Profile("!production")`을 제거하고, `@ConditionalOnMissingBean(AudioRevisionStore.class)`로 변경.
  2. `odiiStoryQueryStore`에서 `AudioRevisionStore`를 `ObjectProvider<AudioRevisionStore>`로 안전하게 수신하여, DataSource 유무와 관계없이 항상 유효한 QueryStore가 등록되도록 보장.

```java
@Bean
@ConditionalOnMissingBean(AudioRevisionStore.class)
AudioRevisionStore odiiAudioRevisionStore() {
    return new InMemoryAudioRevisionStore();
}

@Bean
@ConditionalOnMissingBean(OdiiStoryQueryStore.class)
OdiiStoryQueryStore odiiStoryQueryStore(
        ObjectProvider<AudioRevisionStore> revisionStoreProvider,
        @Value("${onmaru.audio.dataset:odii-audio}") String dataset,
        OdiiProjectionMetadataResolver metadataResolver
) {
    AudioRevisionStore revisionStore = revisionStoreProvider.getIfAvailable(InMemoryAudioRevisionStore::new);
    return new ActiveRevisionOdiiStoryQueryStore(revisionStore, dataset, metadataResolver);
}
```

## 3. Neon PostgreSQL DB 영속화 및 자동 크론 동기화 연동

### 3.1 필요성 및 이점
1. **데이터 영속성 보장**:
   - 컨테이너 재시작 시 휘발되는 인메모리 방식 대신, PostgreSQL에 한국관광공사 TourAPI 및 Odii 오디오 가이드 실데이터를 안전하게 보관.
2. **백그라운드 크론 자동화 (`OdiiSyncSchedulingAdapter`)**:
   - DB가 연결되면 `SyncRunLease` 분산 락을 획득하여 매일 새벽 한국관광공사 최신 오디오 데이터를 DB로 자동 동기화.
3. **Neon Connection Pooling 최적화**:
   - AWS 아시아-태평양 리전의 Neon PgBouncer Pooler를 사용하여 다중 요청 및 컨테이너 리스타트 시 커넥션 누수 방지.

### 3.2 Render 대시보드 환경변수 설정 가이드

Render 웹 서비스(`onmaru-backend`)의 **Environment** 탭에서 아래 변수를 추가:

| Key | Value | 설명 |
| :--- | :--- | :--- |
| `SPRING_DATASOURCE_URL` | `jdbc:postgresql://ep-shiny-unit-b3izqsyd-pooler.c-4.ap-southeast-1.aws.neon.tech/OnMaru-DB?sslmode=require` | Neon Pooler JDBC 엔드포인트 |
| `SPRING_DATASOURCE_USERNAME` | `OnMaru-DB_owner` | DB 사용자 계정 |
| `SPRING_DATASOURCE_PASSWORD` | `<Render secret에서 주입>` | DB 비밀번호. 실제 값은 문서·로그·Git에 기록하지 않으며, 과거 노출 값은 즉시 폐기·교체한다. |
| `SPRING_DATASOURCE_DRIVER_CLASS_NAME` | `org.postgresql.Driver` | PostgreSQL JDBC 드라이버 |
