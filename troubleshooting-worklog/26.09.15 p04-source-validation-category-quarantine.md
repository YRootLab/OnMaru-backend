# P04 source validation category quarantine

날짜: 2026-09-15

## 문제 상황

Issue #89는 TourAPI source row를 바로 canonical 후보로 공개하지 않고, 허용 category와 좌표 품질을 통과한 행만 candidate로 만들며 실패 행은 quarantine으로 격리하는 경계를 요구했다.

## 오류명 또는 실패 증상

TDD RED에서 `SourceQualificationPolicy`, `SourceRecord`, `TourApiCatalogSourceMapper`가 없어 컴파일 실패했다. 테스트 작성 중 `Map.of`의 10개 entry 제한도 같이 드러나 `Map.ofEntries`로 수정했다.

## 기존 구조나 방식의 한계

`modules/catalog`에는 scheduler·lease·checkpoint만 있었고 source row를 공개 candidate로 판단하는 application 정책이 없었다. `adapters/tourism-api`는 provider envelope를 typed page로 파싱하지만, provider item을 catalog qualification 입력으로 넘기는 mapping 경계가 없었다.

## 관련 코드 맥락

- `modules/catalog/src/main/java/com/yrootlab/onmaru/catalog/application/qualification/SourceQualificationPolicy.java`
  - `SourceRecord`의 `contenttypeid/cat1/cat2/cat3`를 allowlist version `tourapi-category-allowlist-v1`에 대조한다.
  - `mapx/mapy`를 WGS84 한국 범위로 검증하고, 실패 시 `QualificationResult.quarantine()`만 반환한다.
  - canonical 후보의 `normalizedHash`는 `modifiedtime`, `dist` 같은 provider volatile field를 제외해 capture 시각 차이가 공개 변경으로 보이지 않게 한다.
- `adapters/tourism-api/src/main/java/com/yrootlab/onmaru/tourism/catalog/mapping/TourApiCatalogSourceMapper.java`
  - `TourApiSourceRecord`의 Jackson `JsonNode` fields를 문자열 map으로 옮겨 catalog application module이 provider JSON 타입을 몰라도 판단할 수 있게 한다.
- `QuarantineRecord`
  - `recordKey`, `errorCode`, `payloadHash`, `redactedPayload`를 담는다.
  - `serviceKey`, `token`, `requestUrl` 계열 field는 `<REDACTED>`로 치환해 원문 key/token을 저장하지 않는다.

## 검토한 선택지

1. TourAPI adapter 안에서 바로 canonical category를 결정한다.
2. catalog module에 source qualification 정책을 두고 adapter는 provider row 변환만 한다.
3. DB 저장소까지 한 번에 구현해 `operations_sync_quarantine`에 persist한다.

## 판단 기준

공개 가능 여부와 canonical category는 Catalog application 정책이어야 하고, provider JSON parsing은 adapter 책임으로 남겨야 한다. Issue #89의 AC는 mapping fixture와 redaction test이므로, DB persistence는 후속 ingest transaction 작업과 분리하는 편이 안전했다.

## 최종 결정

Catalog application에 qualification 정책을 만들고, TourAPI adapter에는 얇은 source mapper만 둔다.

## 해결 방식

- `SourceQualificationPolicy.withDefaultAllowlist()`로 HANOK, HANOK_STAY, HANOK_CAFE, HANOK_EXPERIENCE, TRADITIONAL_MARKET 매핑을 고정했다.
- 미지원 category, 좌표 결측, 한국 범위 밖 좌표는 `QualificationStatus.QUARANTINED`로 반환하고 candidate를 만들지 않게 했다.
- quarantine payload는 SHA-256 payload hash를 유지하되 민감 field value는 저장하지 않게 redaction했다.
- adapter가 catalog qualification 타입을 반환해야 하므로 `adapters:tourism-api`에 `modules:catalog` 의존성을 추가했다.
- TDD 테스트로 category mapping, invalid coordinate quarantine, normalized hash 안정성, key/token redaction을 고정했다.
