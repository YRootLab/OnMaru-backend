# Spring 공통 오류·cursor·멱등 command web 기반 작업 로그

## 날짜

2026-09-14

## 문제 상황

Issue #70 `[F06] Spring 공통 오류·cursor·멱등 command web 기반 구현` 범위로,
모든 공개 API가 같은 오류 envelope, requestId, cursor, idempotency 규칙을
사용할 수 있는 Spring 공통 web primitive가 필요했다.

기존 저장소는 Spring Boot 실행 골격과 health 테스트만 있었고,
`modules/shared-web` 모듈은 아직 없었다. 도메인 endpoint 구현 전 단계라,
도메인 API를 만들기보다 후속 API들이 재사용할 공통 계약과 테스트를 먼저
고정하는 방향이 필요했다.

## 오류명 또는 실패 증상

- TDD RED: `CursorCodec`, `IdempotencyService`, `IdempotencyCommand`,
  `IdempotentResponse` 등 계약 타입 부재로 `compileTestJava` 실패.
- 모듈 배선 실패: 신규 `modules:shared-web`에서 Spring dependency BOM이 빠져
  `Could not find ... jackson-databind:.` 형태의 dependency resolution 실패.
- dependency lock 실패: `apps:spring-api`가 shared-web을 의존하면서 validation,
  Jackson 전이 의존성이 lockfile에 없어 compile/test classpath resolution 실패.
- MockMvc fixture 실패: 초기 `ApiErrorContractTests`가 좁은 `@ContextConfiguration`
  과 생성자 주입 조합 때문에 `ParameterResolutionException`으로 실패.

## 기존 구조나 방식의 한계

`apps/spring-api` 내부에 모든 공통 web 코드를 바로 넣으면 후속 API 구현은
빠르지만, Issue #70의 Related Module로 명시된 `modules/shared-web` 경계를
놓치게 된다. 반대로 DB-backed idempotency까지 한 번에 구현하면 아직 schema와
transaction boundary가 없는 상태에서 과한 구현이 된다.

따라서 이번 작업은 shared-web 모듈을 만들고, 실제 DB 저장소는 후속 구현에서
교체할 수 있도록 port를 먼저 두는 쪽으로 범위를 제한했다.

## 관련 코드 맥락

- `settings.gradle.kts`
  - `include("modules:shared-web")`를 추가해 CI의 `./gradlew test`가 shared-web
    테스트까지 함께 실행하게 했다.

- `apps/spring-api/build.gradle.kts`
  - Spring 앱이 `implementation(project(":modules:shared-web"))`로 공통 web
    primitive를 사용하게 했다.
  - 이 변경으로 앱 compile/test/runtime classpath에 validation/Jackson 전이
    의존성이 추가되어 `apps/spring-api/gradle.lockfile`을 갱신했다.

- `modules/shared-web/src/main/java/com/yrootlab/onmaru/web/common/cursor/CursorCodec.java`
  - `CursorPayload(scope, claims, expiresAt)`를 JSON으로 직렬화하고 Base64 URL-safe
    payload와 HMAC-SHA256 signature를 `payload.signature` 형식으로 조합한다.
  - decode 시 signature를 constant-time 비교하고, expected scope와 expiresAt을
    검증한다.
  - 변조, malformed, scope mismatch는 `CursorInvalidException`, 만료는
    `CursorExpiredException`으로 나눠 web layer가 각각 400/410으로 매핑할 수 있게
    했다.

- `modules/shared-web/src/main/java/com/yrootlab/onmaru/web/common/idempotency/IdempotencyService.java`
  - `IdempotencyStorePort`에 command 실행을 위임하는 얇은 service다.
  - 입력은 `IdempotencyCommand(key, subjectId, method, path, payloadFingerprint)`,
    출력은 status/header/body를 담은 `IdempotentResponse`다.
  - 실제 저장 구현은 port 뒤로 숨겨 후속 PostgreSQL 구현에서 교체 가능하게 했다.

- `modules/shared-web/src/main/java/com/yrootlab/onmaru/web/common/idempotency/IdempotencyKey.java`
  - HTTP `Idempotency-Key` header 값을 trim한 뒤 UUID로 파싱한다.
  - header가 없거나 blank이면 `IdempotencyKeyMissingException`, UUID 형식이 아니면
    `IdempotencyKeyInvalidException`을 던진다.
  - 후속 command endpoint가 각자 header parsing을 구현하면 누락/형식 오류 응답이
    제각각 될 수 있어 공통 parser로 고정했다.

- `modules/shared-web/src/main/java/com/yrootlab/onmaru/web/common/idempotency/IdempotencyFingerprint.java`
  - method, path, operationScope, payload를 canonical JSON envelope로 만든 뒤
    SHA-256 hex fingerprint를 생성한다.
  - method는 대문자로 정규화하고, path/scope는 trim한다.
  - 같은 command scope와 같은 payload는 같은 fingerprint를 만들고, payload나
    subject/resource scope가 달라지면 다른 fingerprint를 만든다.
  - 이 값이 `IdempotencyCommand.payloadFingerprint`로 들어가야 같은 key 재시도와
    다른 payload 409 판단이 후속 endpoint 사이에서도 일관된다.

- `modules/shared-web/src/main/java/com/yrootlab/onmaru/web/common/idempotency/InMemoryIdempotencyStore.java`
  - contract test용 adapter다.
  - `(subjectId, key, method, path)`가 같고 payload fingerprint도 같으면 최초 응답을
    반환한다.
  - 같은 key/scope에 다른 payload fingerprint가 들어오면
    `IdempotencyConflictException`을 던져 `IDEMPOTENCY_CONFLICT` 409로 이어진다.
  - `synchronized`로 같은 JVM 안의 동시 요청에서 handler가 한 번만 실행되도록
    했다. 운영용 분산 lock/DB unique constraint는 후속 저장소 구현 책임이다.

- `modules/shared-web/src/main/java/com/yrootlab/onmaru/web/common/error/*`
  - `RequestIdFilter`는 `X-Request-Id`가 있으면 process-keyed HMAC opaque ID로
    치환하고, 없으면 UUID를 생성해 response header와 request attribute에 넣는다.
  - `GlobalApiExceptionHandler`는 validation, cursor, idempotency 예외를
    `{schemaVersion:"1.2", code, message, requestId, details}` 형식으로 반환한다.
  - `Idempotency-Key` 누락/형식 오류도 `VALIDATION_ERROR` envelope로 내려
    command endpoint가 실행되기 전에 요청 계약 오류로 차단되게 했다.

## 검토한 선택지

1. `apps/spring-api` 안에만 공통 클래스를 둔다.
   - 빠르지만 shared-web 경계를 나중에 다시 옮겨야 한다.
2. `modules:shared-web`를 만들고 공통 primitive만 둔다.
   - 후속 API가 바로 재사용할 수 있고 Issue #70의 touch point와 맞다.
3. idempotency 저장소를 바로 PostgreSQL로 구현한다.
   - 운영 형태에는 가깝지만 아직 migration/schema 소유가 열려 있어 범위가 커진다.
4. idempotency는 port와 in-memory contract adapter로 시작한다.
   - acceptance의 replay/conflict/concurrency 규칙을 테스트로 고정하면서 저장 구현은
     후속으로 넘길 수 있다.

## 판단 기준

- 도메인 endpoint는 Issue #70 scope 밖이어야 한다.
- 후속 공개 API들이 같은 오류 envelope와 requestId 규칙을 재사용할 수 있어야 한다.
- cursor 변조/만료와 idempotency replay/conflict는 contract test로 보호되어야 한다.
- 기존 CI의 `./gradlew test`가 새 테스트를 자연스럽게 포함해야 한다.

## 최종 결정

`modules:shared-web`를 추가하고, cursor codec·error envelope·requestId filter·
idempotency port/service를 공통 web primitive로 구현했다.

## 해결 방식

- 먼저 테스트를 작성했다.
  - `CursorCodecTests`: 정상 decode, 변조 cursor invalid, 만료 cursor expired.
  - `IdempotencyServiceTests`: 동일 key/동일 payload replay, 다른 payload conflict,
    동시 요청에서 handler 1회 실행.
  - `IdempotencyKeyTests`: header trim 후 UUID parsing, missing/invalid header
    분리.
  - `IdempotencyFingerprintTests`: 같은 operation scope/payload는 같은 hash,
    payload나 scope가 바뀌면 다른 hash.
  - `ApiErrorContractTests`: MockMvc로 validation/cursor/idempotency 예외가
    schemaVersion `1.2` envelope와 HTTP status로 매핑되는지 검증.

- RED 확인을 했다.
  - 신규 계약 타입이 없어 `compileTestJava`가 실패했다.
  - shared-web BOM/lockfile/MockMvc fixture 실패도 순차적으로 드러났다.

- GREEN 구현을 했다.
  - shared-web 모듈에 Spring dependency platform을 명시했다.
  - cursor HMAC 서명/검증, scope 검증, 만료 분기 예외를 구현했다.
  - `Idempotency-Key` header parser와 payload fingerprint 생성기를 추가해
    후속 command endpoint가 같은 입력 검증과 hash 규칙을 쓰게 했다.
  - idempotency command와 response model, store port, in-memory adapter를 구현했다.
  - requestId filter와 global exception handler로 오류 envelope를 통일했다.
  - 앱 dependency lockfile을 compile/test/runtime classpath 기준으로 갱신했다.

- CI는 별도 workflow를 새로 추가하지 않았다.
  - 기존 `.github/workflows/ci.yml`의 `Spring API tests`가 `./gradlew test --no-daemon`
    를 실행한다.
  - `settings.gradle.kts`에 `modules:shared-web`가 include되어 있으므로 기존 CI에서
    shared-web 테스트가 함께 실행된다.

## 결과

- 검증 통과:
  - `./gradlew :modules:shared-web:test :apps:spring-api:test --tests '*CursorCodecTests' --tests '*IdempotencyServiceTests' --tests '*ApiErrorContractTests'`
  - `./gradlew test`

  - `git diff --check`

- 남은 과제:
  - 운영 idempotency 저장소는 PostgreSQL unique key/transaction 기반 adapter로
    후속 구현해야 한다.
  - 실제 도메인 command endpoint가 생기면 인증·소유권 재검증 후 저장 응답을 반환하는
    흐름을 controller/service 단에서 연결해야 한다.
