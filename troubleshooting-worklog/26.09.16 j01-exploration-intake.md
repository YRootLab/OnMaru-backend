# J01 Exploration intake와 소유권 구현

## 작업 배경

- 관련 Issue: #101 `[J01] Exploration 생성·조회·turn intake와 소유권 구현`
- 시작 전 #70, #77, #87, #92, #134, #136이 모두 Closed인지 확인했다.
- 담당자와 열린 중복 PR이 없음을 확인한 뒤 `feature/101-exploration-intake`에서 작업했다.
- durable run state machine, worker, SSE는 후속 #109 범위이므로 이번 작업은 intake와 dispatch port까지만 구현한다.

## 구현 경계

- `modules/journey`에 guest/member actor, exploration aggregate, 원문 turn store, version/clientTurnId 검증과 run dispatch port를 추가했다.
- `POST /api/v1/explorations`, `GET /api/v1/explorations/{id}`, `POST /api/v1/explorations/{id}/turns`를 Journey OpenAPI 1.2 계약에 맞췄다.
- POST 응답은 `RunAccepted`, GET 응답은 authoritative `ExplorationSnapshot`이다.
- session member를 우선하고 guest는 opaque cookie의 SHA-256 subject만 store에 남긴다. 다른 actor의 조회와 turn 추가는 동일한 404로 은닉한다.
- query, locale, regionCode, clientTurnId, baseVersion 검증은 저장 전에 수행한다. 422 거절은 exploration이나 원문 turn을 만들지 않는다.
- canonical region이 없으면 run을 `COMPLETED/CLARIFICATION_REQUIRED`로 끝내며 dispatcher를 호출하지 않는다. region이 있으면 `QUEUED` run 하나만 dispatch한다.
- 같은 `clientTurnId`와 같은 payload는 원래 run을 재응답하고, 다른 payload 재사용은 `IDEMPOTENCY_CONFLICT`로 거절한다.
- shared `IdempotencyService`로 create/turn의 actor·path·payload fingerprint를 저장하며, 같은 key replay와 다른 payload conflict를 구분한다.
- `GET /auth/csrf`가 24시간 server-side guest credential을 함께 발급한다. endpoint는 미등록/만료/누락 cookie를 신뢰하지 않고 401로 거절한다.
- Java intake policy가 FastAPI 정책과 같은 전화번호·이메일, HTML·prompt injection, 명백한 비여정 범위를 저장·dispatch 전에 거절한다.
- 로그인 회원은 직접 member 소유권 외에도 #92의 유효 guest exploration grant로 기존 탐색에 접근할 수 있다.
