# D04 journey/discovery schema worklog

## 날짜

2026-09-15

## 문제 상황

여정 탐색은 SSE 이벤트가 아니라 PostgreSQL snapshot과 run 상태가 정답이다. Issue #77은 exploration, turn, run, proposal, saved journey, saved resource의 durable truth를 만드는 migration 작업이다.

## 오류명 또는 실패 증상

TDD 첫 실행에서 `JourneyMigrationTests`가 실패했다.

- discovery/journey 테이블이 없어 table count가 0이었다.
- exploration/run/saved insert가 `PSQLException`으로 실패했다.
- owner XOR 검증은 테이블 부재 예외 때문에 기대한 constraint 이름을 보지 못했다.

## 기존 구조나 방식의 한계

`docs/database/modules/discovery.dbml`과 `docs/database/modules/journey.dbml`에는 logical schema가 나뉘어 있었지만, 실제 Flyway migration은 없었다. D03에서 `identity_oauth_states.exploration_id`, `identity_exploration_grants.exploration_id`도 FK 없이 남아 있었는데, 참조 대상인 `discovery_explorations`가 아직 없었기 때문이다.

## 관련 코드 맥락

- `apps/spring-api/src/main/resources/db/migration/baseline/V006__d04_journey_discovery_schema.sql`
  - `discovery_explorations`는 member/guest owner XOR와 `state_version >= 0`을 강제한다.
  - `discovery_runs`는 `QUEUED/RUNNING` active run에 대해 exploration별·actor별 partial unique index를 둔다.
  - terminal run은 outcome이 있어야 하고 active run은 outcome이 없어야 한다.
  - `journey_saved_journeys`는 같은 member/source exploration/version 중복 저장을 막는다.
  - `journey_saved_resources`는 같은 member/resource type/resource id 중복 저장을 막는다.
  - V003에서 미뤄둔 identity-to-exploration FK를 V006에서 추가한다.
- `apps/spring-api/src/test/java/com/yrootlab/onmaru/testing/postgres/JourneyMigrationTests.java`
  - owner 없음·owner 둘 다 있음 INSERT 실패를 확인한다.
  - active run 중복을 partial unique index로 막는지 확인한다.
  - terminal 전환 뒤 active slot이 풀리고, state version CAS update predicate가 stale update 0건을 반환하는지 확인한다.
  - saved journey/resource duplicate 저장을 DB unique constraint로 차단하는지 확인한다.

## 검토한 선택지

1. discovery와 journey를 별도 migration으로 쪼갠다.
2. D04 하나에서 discovery와 journey 저장소를 같이 만든다.
3. run active uniqueness를 application lock으로만 처리한다.
4. identity exploration FK를 계속 nullable reference로 남긴다.

## 판단 기준

- Issue #77 scope가 exploration/run/proposal/turn/saved를 함께 포함한다.
- REST/SSE 복구의 정답이 DB이므로 active run uniqueness와 owner XOR는 application race 전에 DB가 막아야 한다.
- identity grant/state는 exploration 생성 이후 참조 무결성이 필요하므로 D04에서 FK를 마저 연결하는 편이 맞다.

## 최종 결정

V006 Flyway migration에 discovery와 journey 테이블을 함께 추가하고, active run partial unique와 saved unique constraint를 Testcontainers로 검증했다.

## 해결 방식

1. RED: `JourneyMigrationTests`를 먼저 추가해 schema 부재 실패를 확인했다.
2. GREEN: `V006__d04_journey_discovery_schema.sql`을 추가해 discovery/journey enums와 6개 테이블을 만들었다.
3. 무결성: owner XOR, JSON shape, version/generation, terminal outcome, active run partial unique, saved duplicate unique를 DDL로 강제했다.
4. 연결: `identity_oauth_states`와 `identity_exploration_grants`에 exploration FK를 추가했다.
5. registry/docs: V006 checksum/sha256과 migration 소유권 문서를 갱신했다.
