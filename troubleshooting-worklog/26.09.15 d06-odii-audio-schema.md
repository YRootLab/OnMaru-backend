# D06 Odii audio schema worklog

## 날짜

2026-09-15

## 문제 상황

Odii 원천은 spot/story와 언어별 원본 ID가 분리되어 있고, 대본·음원·삭제 상태는 dataset revision에 묶여야 한다. Issue #79는 언어별 identity collision을 막고, tombstone과 transcript provenance를 저장하는 executable schema를 만드는 작업이다.

## 오류명 또는 실패 증상

TDD 첫 실행에서 `AudioMigrationTests`가 실패했다.

- audio 테이블들이 없어 table count 검증이 실패했다.
- Odii spot/story/version/subtitle/link insert가 `PSQLException`으로 실패했다.

## 기존 구조나 방식의 한계

`docs/database/modules/audio.dbml`과 `docs/spring/catalog-ingestion.md`에는 logical schema가 있었지만 실제 Flyway migration에는 없었다. 이 상태에서는 #96 Odii sync가 언어별 `tlid/stlid`를 덮어쓰거나, story version이 해당 revision의 spot version 없이 저장되는 문제를 DB가 막을 수 없었다.

## 관련 코드 맥락

- `apps/spring-api/src/main/resources/db/migration/baseline/V008__d06_odii_audio_schema.sql`
  - `audio_odii_spots`는 `(provider, tid, tlid)` unique로 언어별 spot identity를 분리한다.
  - `audio_odii_stories`는 `(provider, stid, stlid)` unique와 `spot_id` FK로 story identity를 spot에 묶는다.
  - `audio_spot_versions`와 `audio_story_versions`는 `catalog_dataset_revisions`를 참조해 revision 기반 게시를 지원한다.
  - `audio_story_versions`는 `(revision_id, spot_id)` 복합 FK로 story가 같은 revision의 spot version에 매달리게 한다.
  - `audio_subtitle_lines`는 `(revision_id, story_id, position)` PK와 story version 복합 FK, non-negative timing을 강제한다.
  - `audio_place_odii_links`는 catalog place FK, confidence 0..1, 검수된 link 정책을 담는다.
- `apps/spring-api/src/test/java/com/yrootlab/onmaru/testing/postgres/AudioMigrationTests.java`
  - 언어별 ID 분리, 중복 provider ID 거부, revision FK, tombstone status, subtitle timing, place link confidence를 실제 PostgreSQL/PostGIS로 검증한다.

## 검토한 선택지

1. language를 무시하고 `tid/stid`만 unique로 둔다.
2. logical DBML과 동일하게 version table을 만들되 revision FK만 둔다.
3. story version이 같은 revision의 spot version을 반드시 참조하도록 복합 FK를 둔다.
4. subtitle line timing 검증을 importer에만 맡긴다.

## 판단 기준

- Issue #79 acceptance가 언어별 ID collision 없음과 revision FK/tombstone 검증을 요구한다.
- Odii는 place 연결 실패와 무관하게 audio 자체가 게시될 수 있으므로 audio identity는 독립적으로 안정적이어야 한다.
- 부분 게시 방지를 위해 story version은 같은 revision의 spot version 없이 저장되면 안 된다.

## 최종 결정

V008 Flyway migration으로 audio identity/version/transcript/link schema를 추가하고, 복합 FK와 check constraint를 Testcontainers로 검증했다.

## 해결 방식

1. RED: `AudioMigrationTests`를 먼저 추가해 audio schema 부재를 확인했다.
2. GREEN: `V008__d06_odii_audio_schema.sql`로 spot/story identity, spot/story versions, subtitle lines, place links를 만들었다.
3. 무결성: provider ID unique, revision/story/spot FK, story->spot version 복합 FK, subtitle timing, confidence range를 DDL로 강제했다.
4. registry/docs: V008 SHA-256을 등록하고 migration/concurrency 문서에 D06 ownership을 추가했다.
