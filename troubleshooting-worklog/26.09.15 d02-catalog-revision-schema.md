# D02 Catalog revision schema 작업 기록

## 날짜

2026-09-15

## 문제 상황

Issue #75는 한옥·지도·Odii가 공유할 안정적인 canonical `placeId`와 공급자 원본 ID, dataset revision별 공개 projection을 PostgreSQL/PostGIS 실행 schema로 만드는 작업이다. 원본 `contentId`를 public identity로 쓰지 않고, 동일 source 중복은 차단하되 provider가 다른 같은 external ID는 분리해야 했다.

## 오류명 또는 실패 증상

- RED 테스트에서 `catalog_place_sources`, `catalog_place_versions` 등 catalog table이 없어 PostgreSQL `relation does not exist` 오류가 발생했다.
- GiST spatial index가 없어서 `catalog_place_versions_location_gix` 존재 검증이 실패했다.

## 기존 구조나 방식의 한계

`docs/database/modules/catalog.dbml`에는 catalog 논리 설계가 있었지만 Flyway 실행 migration은 D01 baseline만 있었다. 따라서 후속 C02/C03/C05/P03/P04가 참조할 `catalog_dataset_revisions`, `catalog_place_identity`, `catalog_place_sources`, `catalog_place_versions`의 FK/unique/spatial index를 실제 DB가 보장하지 못했다.

## 관련 코드 맥락

- `apps/spring-api/src/main/resources/db/migration/baseline/V002__d02_catalog_revision_schema.sql`
  - catalog enum 3종(`catalog_region_level`, `catalog_dataset_status`, `catalog_place_status`)과 catalog table들을 만든다.
  - `catalog_place_sources_provider_dataset_external_id_language_uq`가 `(provider,dataset,external_id,language)` 중복 source를 차단한다.
  - `catalog_place_versions`는 `revision_id`, `place_id`, `source_ref_id`, `region_id`를 FK로 묶고 `location geography(Point,4326)`에 GiST index를 둔다.
  - TourAPI 원본 content/intro/info, image, hanok detail version table은 revision/source FK로 raw provenance를 보존한다.

- `apps/spring-api/src/test/java/com/yrootlab/onmaru/testing/postgres/CatalogMigrationTests.java`
  - 실제 PostGIS Testcontainers DB에 Flyway migration을 적용한다.
  - 중복 KTO source 삽입은 unique constraint로 실패하고, provider가 다른 ODII source는 같은 external ID여도 성공하는지 검증한다.
  - revision FK가 없는 place version 삽입이 실패하고, `ST_DWithin`으로 geography point가 조회되는지 검증한다.

- `db/migration/registry/migrations.json`
  - V002 path와 SHA-256을 등록해 migration SQL drift를 CI에서 차단한다.

## 검토한 선택지

1. DBML 전체 catalog를 한 번에 V002로 실행 migration화한다.
2. D02 acceptance에 필요한 place/source/revision 핵심 table만 만들고 나머지는 후속으로 미룬다.
3. source 중복을 application repository에서만 검사한다.
4. provider/dataset/external_id/language unique constraint를 DB에서 강제한다.

## 판단 기준

- D02 scope는 수집 worker가 아니라 저장 schema다.
- C/P/M 후속 이슈가 안전하게 참조할 FK와 spatial index는 지금 필요하다.
- 원본 provider ID 충돌과 중복 source는 동시성 상황에서도 DB가 최종 방어선이어야 한다.
- PostGIS 기능은 H2나 mock이 아니라 실제 container에서 검증해야 한다.

## 최종 결정

DBML catalog 핵심 table 전체를 V002로 만들고, provider source unique/FK/geography GiST index를 DB constraint로 강제한다.

## 해결 방식

- `CatalogMigrationTests`를 먼저 추가해 table 부재, unique 부재, FK/index 부재를 RED로 확인했다.
- V002 Flyway SQL에 catalog enum, identity/source/revision/projection/raw provenance table을 추가했다.
- `catalog_place_versions_location_gix` GiST index와 region/status/category 보조 index를 추가했다.
- registry에 V002 version, issue number, stable checksum, SHA-256을 등록했다.
- `docs/database/migration-and-concurrency.md`에 D02 migration 소유 범위를 기록했다.

## 결과

- 동일 provider/dataset/external_id/language source 중복은 DB unique constraint로 차단된다.
- provider가 다른 같은 external ID는 별도 source로 저장된다.
- place version은 revision/place/source/region FK를 강제하고 PostGIS geography point를 저장·조회한다.
- 검증:
  - `./gradlew :apps:spring-api:test --tests '*CatalogMigrationTests' --no-daemon`
  - `node --test scripts/test/migration-policy.test.mjs`
