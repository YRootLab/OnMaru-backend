# O02 Grafana Cloud dashboard·alert 구성 작업 로그

날짜: 2026-09-15

## 문제 상황

Issue #81은 API, sync, AI, SSE, moderation, backup 상태를 Grafana Cloud에서 한 화면으로 보고 warning/critical/resolve 통지를 검증할 수 있게 만드는 작업이다. 기존 저장소에는 Grafana Cloud에 가져갈 dashboard, alert rule, notification policy export가 없어 운영 인수 기준을 반복 검증하기 어려웠다.

## 오류명 또는 실패 증상

`node --test scripts/test/grafana-observability.test.mjs`를 먼저 추가해 실행했을 때 `ENOENT`로 `observability/grafana/dashboards/onmaru-mvp-operations.json`을 찾지 못했다. 이는 운영 관측성 export가 아직 저장소에 없다는 RED 신호였다.

## 기존 구조나 방식의 한계

운영 문서인 `docs/operations/runtime-and-reliability.md`에는 Grafana Cloud가 alert state의 기준이며 Discord와 email은 통지 경로라는 정책이 정리되어 있었다. 하지만 실제 dashboard panel 목록, warning/critical rule, resolve message 정책이 파일로 분리되어 있지 않아 PR·CI에서 drift를 잡기 어려웠다.

## 관련 코드 맥락

- `scripts/test/grafana-observability.test.mjs`: Grafana export 파일을 JSON으로 읽어 필수 panel, alert severity, dashboard/runbook annotation, 민감 label 금지 플래그, warning/critical notification route를 검증한다.
- `observability/grafana/dashboards/onmaru-mvp-operations.json`: API request/error/latency, JVM/readiness, DB pool wait, AI run/provider, SSE reset/reconnect, sync lag/failure, published revision, corpus ACK, moderation report, backup age panel을 선언한다.
- `observability/grafana/alerts/onmaru-alert-rules.json`: staging warning/critical synthetic alert 기준을 저장한다. rule annotation은 environment, service, errorCode, dashboardUrl, runbookUrl 중심으로 제한한다.
- `observability/grafana/notification-policy.json`: warning은 Discord, critical은 Discord와 email로 라우팅하고 resolve message를 활성화한다.
- `docs/operations/release-evidence/grafana-o02-checklist.md`: 실제 Grafana Cloud staging import와 synthetic alert evidence를 남기는 체크리스트다.

## 검토한 선택지

1. 문서에만 panel/rule 목록을 추가한다.
2. Grafana UI에서 수동 설정하고 링크만 남긴다.
3. 저장소에 JSON export를 두고 CI에서 구조를 검증한다.
4. self-hosted Grafana stack까지 docker-compose로 구성한다.

## 판단 기준

Issue 범위가 self-hosted Grafana stack을 제외하고, IaC/export 가능한 dashboard와 alert definition 저장을 요구했다. 또한 민감 정보가 metric label과 annotation으로 새는 것을 자동으로 막아야 했으므로 JSON export와 Node 테스트 조합이 가장 작은 구현 단위였다.

## 최종 결정

Grafana Cloud에 import 가능한 운영 export 파일을 `observability/grafana` 아래에 두고, repository-local Node 테스트로 panel/rule/route 계약을 검증하는 방향을 선택했다.

## 해결 방식

- TDD로 `scripts/test/grafana-observability.test.mjs`를 먼저 추가하고 missing export 파일로 RED를 확인했다.
- `observability/grafana/dashboards/onmaru-mvp-operations.json`에 #81이 요구한 sync lag, AI failure, SSE, moderation, backup panel을 포함했다.
- `observability/grafana/alerts/onmaru-alert-rules.json`에 warning과 critical rule을 분리하고, 모든 rule에 dashboard/runbook annotation과 `noSensitiveLabels`를 넣었다.
- `observability/grafana/notification-policy.json`에서 resolve message 활성화와 warning/critical contact point 라우팅을 명시했다.
- staging에서 실제 import와 synthetic alert 결과를 남길 수 있도록 `docs/operations/release-evidence/grafana-o02-checklist.md`를 추가했다.
