# AI proposal allowlist validator

- 날짜: 2026-09-16
- 관련 Issue: #105

## 문제 상황

Gemini adapter는 JSON parsing과 provider failure를 처리했지만, provider가 canonical candidate 밖 ref나 다른 candidate의 evidence를 반환해도 business 경계에서 막는 구현이 없었다. malformed output을 그대로 다음 단계에 넘기면 모델이 place ID와 근거 범위를 사실상 확장할 수 있었다.

## 실패 증상

첫 RED는 `ModuleNotFoundError: No module named 'onmaru_ai.proposal'`이었다. 구현 뒤 review에서 미완성 HTML 태그, 강조 Markdown, bare domain, control character와 provider 생성 region ref가 통과하는 adversarial 실패 6개를 재현했다. 독립 PR review 1차에서는 임의 TLD domain, `ftp`·`mailto`·`data` scheme, 순서 목록, italic과 reference-style Markdown 우회 7개를 재현했다. 2차에서는 `tel`·`geo`·`sms` scheme, protocol-relative IP, IDN URL, Setext heading·horizontal rule 우회 7개를 reason·question·choice label 경계에서 재현했다.

## 관련 코드 맥락

- `ai/src/onmaru_ai/providers/gemini/adapter.py`는 provider JSON을 `GeminiResult.proposal` mapping으로 반환한다. 이 계층은 HTTP·timeout·usage를 소유하지만 canonical business scope를 알지 못한다.
- `ai/src/onmaru_ai/proposal/models.py`는 provider outcome schema와 Spring이 전달한 `ProposalScope`를 정의한다. scope는 candidate revision, pin, exclude, candidate별 evidence ownership을 고정한다.
- `ai/src/onmaru_ai/proposal/validator.py`는 provider mapping을 Pydantic으로 파싱한 뒤 scope와 대조하고, 원문이 없는 typed rejection을 반환한다.

## 검토한 선택지

1. JSON Schema 통과만 신뢰: candidate/evidence ownership과 pin 보존을 검사할 수 없어 제외했다.
2. reason summary를 evidence text의 exact substring으로 제한: 정상적인 한국어 요약까지 과도하게 거부하므로 제외했다.
3. Pydantic shape validation과 명시적 allowlist validation을 분리: provider schema와 business scope 책임이 분명해 선택했다.
4. invalid output 자동 repair call: 비용과 비결정성을 늘리고 설계 계약에 어긋나 제외했다.

## 최종 결정과 해결

- outcome별 discriminated schema에서 extra field, 길이, cardinality와 cross-outcome shape를 fail-closed 처리했다.
- Gemini에 전달할 schema는 `$defs`, `$ref`, discriminator를 재귀적으로 inline하고 모든 object를 closed로 유지했다.
- board ref의 uniqueness, candidate/exclude membership, pin 보존, reason 1:1 순서와 evidence ownership을 검사했다.
- 일반 URI scheme, protocol-relative·IP·IDN URL, HTML, Markdown 구조 문자·목록·Setext 구문, control character와 clarification의 임의 region ref를 거부했다.
- camelCase wire alias만 허용하고 `ordered_refs` 같은 내부 Python field name 입력은 거부했다.
- `ProposalValidationError`는 raw ref·summary를 출력하지 않고 내부 rejection code와 `AI_INVALID_RESPONSE`만 보존한다.
